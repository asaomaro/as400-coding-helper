# 要件: 継続行にまたがる参照を追えるようにする

## 背景 / 課題

改名の参照追随は**物理行ごと**にキーワード欄を見ている。そのため
`CSRLOC(ROW +` / `COL)` のように継続で書かれていると、**後ろの行の `COL` が
参照だと分からない**（その行には `CSRLOC(` が無い）。

取りこぼすだけで壊しはしないので、`20260828-dds-rename-references` では
受け入れて起票に回してあった。

## 目的 / ゴール

継続でつながった run に書かれた参照も、改名で一緒に変わる状態。
**かつ、継続でない行の見た目は変わらない**（前 work で踏んだ回帰を再発させない）。

## ユーザーストーリー

- US1: DSPF を書く人として、継続で折った行の参照も追随してほしい。
  なぜなら 45-80 桁は 36 桁しかなく、**キーワードが 2 つ並べば折れるのは普通**で、
  折り方によって追随したりしなかったりするのは説明できないから。（受け入れ: AC1, AC2）

## スコープ

### 対象
- 継続（`-` / `+` / 引用符の開き）でつながった run の中の参照。
- 項目の参照・様式の参照の**両方**。

### 対象外
- 参照の見つけ方そのもの（表は変えない）。

## 完了条件 (受け入れ基準)

- [ ] AC1: 継続の**後ろ側**にある名前も変わる（`CSRLOC(ROW +` / `COL)` の `COL`）。
- [ ] AC2: `&名前` が継続の先にあっても変わる。
- [ ] AC3: 様式の参照も同じく追える。
- [ ] AC4: **単独のキーワード行は様式の行に吸い込まれない**（前 work の回帰）。
- [ ] AC5: 折り直した結果が**実機でコンパイルを通る**。

## 相互作用の受け入れ基準

- [ ] AC-I1 見た目が変わるのは継続の run だけ: 継続でない行は今までどおり
      その場で差し替える（行数も変わらない）。
