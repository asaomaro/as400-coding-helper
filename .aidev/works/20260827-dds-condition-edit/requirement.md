# 要件: 条件標識を編集する（付け外し）

## 背景 / 課題

条件標識は**読めるところまで**来ている——一覧に出て、3 値で倒すと描画が変わり、
条件つきキーワードも解けるようになった（`20260827-dds-conditional-attributes`）。

しかし**書けない**。プロパティの `条件` 欄は読み取り専用で、
「ここに `50` を付ける」「`N50` を外す」はテキストエディタに戻るしかない。

デザイナで条件を倒して見え方を確かめたあと、**その条件を書くのは手作業**になっている。

## 目的 / ゴール

**見て確かめた条件を、その場で付け外しできる状態。**

紐づく charter ゴール: DDS の視覚的な確認と編集（第 4 の柱）。

## ユーザーストーリー

- US1: DSPF を書く開発者として、**選んだ項目に条件標識を付けたい**。
  なぜなら 7-16 桁は 3 桁ずつの区切りで、手で書くと**ずれる**から。（受け入れ: AC1, AC2）
- US2: DSPF を書く開発者として、**OR 条件も書きたい**。
  なぜなら「エラー時 **または** 初回表示時」は実務で普通に出てくるから。（受け入れ: AC3）

## スコープ

### 対象
- 項目の条件標識を付け外しする（AND / OR / `N`）
- 7-16 桁への書き戻し（**OR は行が増える**）
- 条件を消す

### 対象外
- **キーワードだけの行**の条件の編集（`30 DSPATR(RI)` の `30`）——
  宛先が項目ではなくキーワード群で、UI の置き場所が別になる
- 画面サイズ条件名（`*DS3` 等）の編集——標識とは別の欄の使い方

## 完了条件 (受け入れ基準)

- [ ] AC1: 項目に条件標識を付けられる（`50` / `N50`）
- [ ] AC2: 桁がずれない（7 桁目 = A/O、8-10 / 11-13 / 14-16 = `[N]nn`）
- [ ] AC3: **OR 条件は行が増える**。増えた行が正しく読み戻せる
- [ ] AC4: 条件を消すと行が減り、**項目の行だけが残る**
- [ ] AC5: 書けないもの（標識が範囲外・1 つの AND に 10 個以上）は**理由つきで拒否**
- [ ] AC6: 往復する（書いた条件が読み直しで同じ条件になる）
