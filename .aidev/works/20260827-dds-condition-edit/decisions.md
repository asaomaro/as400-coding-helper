# 決定記録

## D1: 入力欄は「短い形」で受け、桁は core が書く

- 背景: 7-16 桁は「7 桁目に A/O、8-10 / 11-13 / 14-16 に `[N]nn`」。
  そのまま打たせると必ずずれる。
- 決定: `N50 01, 60`（AND は空白 / OR はカンマ）の 1 行で受け、
  `writeBackCondition` が桁に落とす。
- 理由: **これは DDS の書き方ではなくこのデザイナの入力欄の書き方**だと割り切った。
  読み書きに同じ形を使う（`formatConditionText` / `parseConditionText`）ので往復する
  ——往復しない形にすると、開いて閉じただけで条件が変わる。

## D2: 行がずれた分だけ選択を送り直す（数え方は 1 か所）

- 背景: 条件の編集は**行数を変える**（OR や 4 つ以上の AND で条件だけの行が増える）。
  選択は行番号で持っているので、**OR にした瞬間に選択が迷子になり
  プロパティごと消えた**（e2e で踏んだ）。
- 決定: `conditionLineCount(groups)` を core に置き、UI はその差分だけ `sourceLine` を
  送り直す（`pendingSelection`）。
- 理由 / 代替案: 「add/remove と同じく選択を捨てる」案は退けた——条件はプロパティの
  1 欄で、打った直後に選択が外れるのは操作として成立しない。
  数え方を UI に写す案も退けた（片方だけ直すと黙ってずれる）。
  **`writeBackCondition` の本数と一致することをテストで固定**している。

## D3: 注記行が挟まっていたら断る

- 背景: 条件行と代表行の間に注記行を書ける。区間で置き換えると**注記が消える**。
- 決定: `condition-lines-not-contiguous` で断る（`setKeywords` の同種の扱いと同じ）。
- 理由: 書けるが壊す編集は、黙って通すより断る方がよい。

## D4: 画面サイズ条件名は編集させない

- 背景: 7-16 桁には標識のほかに画面サイズ条件名（`*DS3` 等）も入る。
- 決定: その場合は入力欄を読み取り専用にする。
- 理由: 標識とは**別の欄の使い方**で、短い形に混ぜると意味が曖昧になる
  （`*DS3` は AND でも OR でもない）。要件のスコープ外と明記してある。

## D5: キーワードだけの行の条件は対象外

- 背景: `30 DSPATR(RI)` の `30` も条件だが、宛先は項目ではなく**キーワード群**。
- 決定: この work では扱わない。読む側は `20260827-dds-conditional-attributes` で
  できているので、書く側は別途。
- 影響: プロパティの `条件つき` の行は読み取り専用のまま。backlog に残す。
