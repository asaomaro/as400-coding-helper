# 要件: オラクル表示（VERIFICATION / CHARACTERIZATION）を機械で検査する

## 背景

skill `rpgunit-test` §0.2 は「**この印は機械で検査できる**。`VERIFICATION` も
`CHARACTERIZATION` も無いテストは出所が不明なので差し戻す」と書いているが、
**検査は存在しない**。名乗らなくても素通りし、レポートは SUCCESS を出す。

これは §0 が最も強く警告している形そのもの——**出所不明のテストが緑を出し、
読む人が「仕様どおり」と誤読する**。印が規律の要なのに強制力が無い。

## 要件

1. テストソースの各テスト手続きについて、**どちらの印が効いているか**を機械で判定する。
2. 印が無いテストを**出所不明**として報告する。
3. 印だけあって**根拠の行が無い**もの（`オラクル:` / `期待値の出所:`）も欠陥とする。
   印は根拠と対で意味を持つ。単語だけの `VERIFICATION` は名乗りの偽装になる。
4. 結果は**レポート（Markdown / JSON）に載せる**。読む人が見るのは実行画面ではなく成果物。
5. §0.4「特性化テストは網羅に数えない」を支えるため、**検証／特性化の内訳**を出す。
6. CI で止められる手段を持つ。

## 非要件

- 印の内容（オラクルの引用が正しいか）は検査しない。**人が読む**。
- 実装との対応づけ・カバレッジ測定はしない。
