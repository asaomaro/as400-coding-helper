# 検証

## 単体（`--self-test`、実機に触らない）

62 件すべて通過。追加分の要点:

| 見るもの | なぜ要るか |
|---|---|
| 検証／特性化の印が効く | 基本 |
| **見出しに VERIFICATION が同居しても特性化と読む** | 英語で `CHARACTERIZATION — not a VERIFICATION test` と書かれる |
| **単語だけの印は通さない** | 名乗りの偽装を防ぐ |
| **飾り線（`* ====`）は根拠にならない** | 原典の見出しは飾り線で囲む。数えるとオラクル行の省略が素通りする |
| 頭の印は以降すべてに効く／途中で変えられる | 1 ファイル混在 |
| 内訳を数える | §0.4「特性化は網羅に数えない」 |
| `setUp` / `tearDown` はテストではない | export されるがテストではない（§1） |
| `EXPORT` が無い／6 桁目が P でない | 誤検出しない |
| 自由形式も読む | `dcl-proc … export;` |
| **継続名前行（`...`）を読む** | 15 桁に収まらない名前。読まないとテストが丸ごと見えない |
| キーワード欄の外の `EXPORT` は拾わない | 81-100 桁は注記域 |

## 変異検査（**足したテストが本当に守っているかを確かめる**）

| # | 変異 | 落ちた試験 |
|---|---|---|
| 1 | 判定順を入れ替え（VERIFICATION を先に見る） | 3 |
| 2 | 根拠の行の検査を外す | 1 |
| 3 | `test` 始まりの絞りを外す | 2 |
| 4 | 根拠の判定を「注記行なら何でも」に緩める | 1 |
| 5 | 特性化を検証として記録する | 4 |
| 6 | レポートの出所を常に「検証」にする | 1 |
| 7 | 継続名前行の処理を外す | 1 |
| 8 | `EXPORT` を行全体から探す | 1 |

**1 回目は #1 と #4 が 0 件だった。** どちらも試験データが手薄で、
- #1 … 見出しが日本語（`検証テストではない`）で **Latin の VERIFICATION が入っていなかった**
- #4 … 印の直後に飾り線が無く、**「注記行なら何でも根拠」でも差が出なかった**

データを実物の形に直して両方とも落ちるようにした。
**通っているだけの試験は何も守らない**（AGENTS.md）。
