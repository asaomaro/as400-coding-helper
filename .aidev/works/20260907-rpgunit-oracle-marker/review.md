# レビュー

## 自分の差分で見つけた欠陥（いずれも直した）

### R1. 長い名前のテストが**丸ごと見えていなかった**（重大）

P 仕様の名前欄は 7-21 桁（**15 桁**）。収まらない名前は `...` で次行に続く
（**継続名前行**）。この形を読んでおらず、

```
     PtestLongProcedureName...
     P                 B                   EXPORT
```

が **0 件**と判定された。`--require-oracle` を付けても**素通り**する。
`testCalculateTaxRounding` のような名前は AI に書かせれば普通に出るので、
**この検査が最も効くはずの相手を取りこぼしていた**。

実機で確かめた事実:
- この形は**コンパイルでき、実行できる**
- RPGUnit は **`TESTLONGPROCEDURENAME` と全長で報告する**（切り詰めない）

→ 継続名前行を積むようにし、実機の報告名と一致することを確認した。

### R2. 取りこぼしそのものを検出できていなかった

R1 は「解析が黙って 0 件を返す」形の欠陥で、**同種は今後も起きる**。
AGENTS.md の CDML の教訓（**件数は必ず実データの総数と突き合わせる**）が
そのまま当てはまる。実行後に**実機が報告したテスト名**と突き合わせ、
ソースから読めなかったものを出所不明として扱うようにした。

解析を壊した版（変異 m7）を実機で走らせ、backstop が働くことを確認:
```
⚠ ソースから読めなかったテストがあります: TESTLONGPROCEDURENAME
  実機は報告しているので、印の検査を素通りしています。
```

### R3. `EXPORT` を行全体から探していた

キーワード欄は原典で **44-80 桁**、**81-100 桁は注記域**。行全体を見ると
注記に書いた `EXPORT` を拾う。44-80 桁に絞った。

### R4. 突き合わせの実装が `!seen.add(n)` で常に偽

`Set.add` は Set を返すので `!` は必ず false。**1 件も検出しない**書き方だった。
素直なループに直した。書いた直後に読み返して気付いたもの。

## 試験そのものの欠陥（変異検査で発覚）

変異 6 種のうち **2 種が 1 件も落とさなかった**。原因はどちらも試験データ:

- 判定順の入れ替え … 見出しが日本語（`検証テストではない`）で
  **Latin の VERIFICATION が入っていなかった**
- 根拠の判定を緩める … 印の直後に**飾り線が無く**、差が出なかった

データを実物の形に直し、**8 種すべてが落ちる**ことを確認した。
**通っているだけの試験は何も守らない**（AGENTS.md）。

## 残る限界（承知の上）

- **印の中身は検査しない**。「オラクル: 設計書 3.2」と書いてあれば通る。
  条項が実在するか・引用が正しいかは**人が読む**。ここは機械化しない。
- 突き合わせは**実行後**なので、`--require-oracle`（実行前）は解析結果だけで判断する。
  解析が取りこぼすと `--require-oracle` は素通りし、レポートで気付く形になる。
