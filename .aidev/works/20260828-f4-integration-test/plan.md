# 計画: F4 の統合テストが止まる問題

## 作業順序と依存関係

1. 器を動く状態にする（依存・runner・suite・tsconfig・スクリプト）
2. F4 のテストを書き直す（依存: 1）
3. 手元で走らせる（依存: 2）
4. 止まる形に戻して落ちることを確かめる（依存: 3）
5. CI に載せる（依存: 3）

## リスク / 留意点

- **CI の環境は手元と違う**。`xvfb` が要る。載せてみて CI に判定させる。
- 時間切れが無いと、次に `await` を書いた人がまた全体を止める。

## テスト方針

- 手元で `npm run test:integration` が緑になること。
- **止まる形（`await`）に戻すと落ちること**を実際に確かめる。
- 単体・GUI e2e・verify が変わらないこと。
