# 要件: F4 の統合テストが止まる問題を直す

## 背景 / 課題

`test/integration/f4Prompter.test.ts` が
`await vscode.commands.executeCommand("rpgClSupport.showPrompter")` しているが、
`showPrompter.ts` は `await openPrompter(...)`——**利用者が送信／取消するまで
解決しない Promise** を待つ。テストからは永久に返らず、**拡張ホストごと落ちて
統合スイート全体が止まる**。

**調べたら、止まる以前に動かない状態だった**（2026-08-28）:

| 何が | どうなっていたか |
|---|---|
| `vscode-test` | **依存に入っていない**（`import` が解決しない） |
| `test/suite/index.ts` の `ui` | `bdd`。テストは `suite` / `test`（＝`tdd`）で書かれている |
| 対象のディレクトリ | 1 つ上（`..`）＝ **単体テストまで拡張ホストの中で走る** |
| npm スクリプト | **無い**（走らせる手段が無い） |
| `mocha` / `glob` の使い方 | 古い（型が合わずコンパイルできない） |

## 目的 / ゴール

VSCode の器（コマンドの登録・`WorkspaceEdit`・カスタムエディタ）を
**機械的に確かめられる**状態。CI でも回る。

## ユーザーストーリー

- US1: この拡張を直す人として、VSCode を要る部分を自動で確かめたい。
  なぜなら WebView の中は GUI e2e が見るが、**器は拡張ホストの中でしか
  確かめられず**、いまは 1 本も回せないから。（受け入れ: AC1, AC2, AC3）

## スコープ

### 対象
- 統合テストの器（runner / suite / スクリプト / 依存）。
- F4 のテストを「止まらない形」に書き直す。
- CI に載せる。

### 対象外
- **プロンプター本体の作り替え**（standalone 化）。別項目。
- 送信／取消の振る舞いの検証。WebView の e2e が実物で確かめている。

- [ ] AC1: `npm run test:integration` で統合テストが**走って緑になる**。
- [ ] AC2: F4 のテストが**止まらない**（起動できることだけを見る）。
- [ ] AC3: 対象は `test/integration` **だけ**（単体を拡張ホストで走らせない）。
- [ ] AC4: 止まる形に戻すと**落ちる**（時間切れ）。スイートごと死なない。
