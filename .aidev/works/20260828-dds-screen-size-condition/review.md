# レビュー: 画面サイズ条件名を編集する

## ラウンド 1（2026-08-28）

### 要件適合
- AC1 ✓ 7 桁目ブランク・名前は 8 桁目から。読む側（`readConditioning`）と対。
- AC2 ✓ 往復のテスト。
- AC3 ✓ 標識と混ぜたら `screen-size-name-invalid`。
- AC4 ✓ 形は `isScreenSizeConditionName` に委ねる（**読む側と同じ関数**）。
- AC5 ✓ 標識・空への切り替えで元のソースと一致する。
- AC6 ✓ キーワード行にも同じ引数で書ける。

### 価値適合
条件付け欄に入るものが**これで全部**編集できるようになった
（標識 → 項目 / キーワード行 → 画面サイズ条件名）。
2 つの画面サイズを持つ DSPF は実務で普通にあり、そこだけテキストエディタに戻る状態が消えた。

### 正確性
- 形の判定を**読む側と共有**した。2 か所に書くと必ずずれる。
- 排他を検証で弾き、**入力の形でも自然に守られる**ようにした（D2）
  ——短い形は「先頭が `*` なら画面サイズ」なので、混ぜて書けない。
- `*DS4` で項目が消えるのは正しい振る舞い（D3）。一覧には残るので手は届く。

### 規約適合
任意の欄＋検証は `setAttributes` と同じ形（D1）。3 つ目の編集の種類を作らなかった。

### 保守性
`writeBackScreenSizeCondition` は 1 行だけを返す（AND も OR もしない）ので、
行数の数え方（`conditionLineCount`）に影響しない。

### 指摘
must 0 / should 0 / nit 0。

**残っているもの**: ユーザー定義名が `DSPSIZ` に宣言されているかは見ていない
（打ち間違えても気付かない）。`DSPSIZ` はファイル・レベルのキーワードで、
デザイナからまだ読めない——次の項目と一緒に扱うのが自然。
