# テスト結果: 項目の置き先を「選んでいる様式」にする

- `npm test`: 1415 passing / 0 failing（webview の変更なので単体テストの件数は変わらない）。
- GUI e2e（`dev/e2e.mjs`）: 手元で 228 PASS / 0 FAIL。
  - 手元では本件と無関係の段（2 次画面サイズでドラッグした項目を `data-row` 7 で掴む）が、ドラッグの行が 6 になって止まる。
    `origin/main` の worktree でも同じ所で止まり、CI（main の `prompter definitions`）は通っているので、手元の描画の差と判断した。
    この段だけ掴む行を ±1 許す写し（`e2e-dbg.mjs`、コミットしない）で最後まで流した。本件の判定は CI の e2e でも走る。
- 入れ替えた判定「項目を持つ様式を選んでいても、選んだ様式に入る」は、直す前の e2e が同じ操作で **反対の結果（押した行の REC1 に入る）** を
  検査して通っていた。つまり直す前の実装では落ちる。

## 受け入れ基準ごとの判定
- AC1: pass — FOOTER（項目あり）を選んで REC1 の行（3 行目）に置くと FOOTER に入る。
- AC2: pass — 状況表示に「様式 FOOTER に置きました」／見当で決まったときも「様式 REC1 に置きました」。
- AC3: pass — 見出しを選んでいない（REC1 の項目を選んでいる）と押した行の REC1 に入る。「足した様式にそのまま項目を置ける」も通る。
