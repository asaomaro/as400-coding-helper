# 決定記録

## D1: **前 work で通った土台を使う**

- 背景: 前 work では対照づくりに 3 回つまずいた。今回も F / O 仕様の
  最小プログラムを新しく組もうとして、対照が落ちた。
- 決定: **通ることを確かめた形**（I 仕様の probe の base）に F 仕様だけを差し替えた。
- 理由: 対照が通らなければ何も判定できない。**土台は使い回す**のが最短だった
  ——新しく組むと、桁ではない失敗を毎回切り分けることになる。
- 影響: 1 回で決着した（前 work は 3 回）。

## D2: サンプルの桁ずれは**この work では直さない**

- 背景: 実機の判定で `RPG3SAMP.rpg` の F / I / O 仕様が桁ずれと分かった。
- 決定: 起票する。直さない。
- 理由: 5 行を書き直す作業で、外部記述のファイルと印刷ファイルを使うため
  実機での確認の組み立てが別になる。**数値欄を足す話と混ぜない。**
- 影響: `research.md` に行ごとのずれを測って残した（次の人が測り直さない）。

## D3: **数値の検査だけでは行全体のずれを捕まえられない**（記録）

- 背景: `RECLEN` を数値欄にすればサンプルのずれも出るかと思った。
- 決定: 出ない。24-27 桁には `132` の一部（`  13`）が入り、**右寄せの数字に見える**。
- 理由: 桁のずれは「その欄に何が入っているか」ではなく「行全体がどれだけ動いたか」の話。
- 影響: 起票にこの点を書いた——**数値欄を増やしても解決しない**。
