# 調査: RPG III の F 仕様

## 判明した事実

実機は IBM i 7.3 / `CRTRPGPGM`。`verify/probe-rpg3-fspec.mjs`。
土台には**前 work で通ることを確かめた形**（I 仕様の probe の base）を使った。

| 形 | 実機 |
|---|---|
| 定義どおりの桁（種別 15 / レコード長 24-27 右寄せ）＝ 対照 | 通る |
| **`RPG3SAMP.rpg` の見た目**（1 桁ずつ右） | **通らない** |
| **レコード長を左詰め**（24 桁に `80`） | **通らない** |
| **レコード長に英字** | **通らない** |

### F1: **定義の桁が正しい**（サンプルではない）

対照が通り、サンプルの見た目が通らない。**定義を疑う必要は無かった。**

### F2: **`RPG3SAMP.rpg` の F / I / O 仕様は桁がずれている**

定義と突き合わせて測った結果:

| 行 | ずれ |
|---|---|
| 2（F・入力） | 種別・指定・形式・装置がすべて**1 桁右** |
| 3（F・印刷） | 同上。レコード長も 1 桁右（`132` が 26-28 桁。正しくは 24-27 に右寄せ） |
| 4（I・レコード） | `NS` が 16-17（正しくは 15-16）、`01` が 20-21（正しくは 19-20） |
| 12（O・レコード） | 種別が 16（正しくは 15） |
| 13（O・フィールド） | 名前が 36（正しくは 32-37）、終了位置が 46（正しくは 40-43）**4-5 桁右** |

**C 仕様は正しい**（前 work で確かめた 1 行を直したあとは全部合っている）。

### F3: **数値の検査だけでは行全体のずれを捕まえられない**

`RECLEN` を数値欄にしても、サンプルの 24-27 桁には `  13`（`132` の一部）が入り、
**右寄せの数字に見える**ので指摘が出ない。桁のずれは別の見方が要る。
