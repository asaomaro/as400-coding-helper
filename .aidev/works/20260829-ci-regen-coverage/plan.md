# 計画: 生成物の再生成チェックを取りこぼしなくする

## 作業順序と依存関係

1. **T1** CI の再生成ステップに `generate-dds-columns.mjs --lang=en` と
   `generate-rpg-io-definitions.mjs` を足す（依存: なし）
2. **T2** 差分検査を `vscode-extension/resources` 全体にする（依存: なし）
3. **T3** 手元で同じコマンド列を回し、**差分ゼロ**と**手編集で落ちること**を確かめる（依存: T1・T2）
4. **T4** backlog を割る（本 PJ 側は済・別リポジトリ側は残件）（依存: T3）

## リスク / 留意点

| リスク | 対応 |
|---|---|
| **`resources/` に生成物以外があって誤検出** | 再生成しても差分が出ない限り落ちない。手元で全件確認する |
| 生成器の**順序**を崩す | 既存のコメントどおりの順序を保つ。崩すと `prompter/cl/en` に 200 件超の差分が出る（手元で実測） |
| CI でしか分からない失敗 | 手元で同じコマンド列を実行して先に確かめる |

## テスト方針

- **手元で CI と同じコマンド列を実行**し、`git status vscode-extension/resources` が空であること。
- **`prompter/dds` の JSON を手で 1 文字直すと落ちること**（検査が効いている証拠）。
- CI 上でも通ることを PR で確認する。
