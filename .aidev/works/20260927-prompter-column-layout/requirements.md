# 要件: 欄を桁の決まりどおりに寄せる（左詰めしない）

## 背景 / 課題
2026-09-27 の実操作調査（`docs/research/20260927-f4-prompter-exploration/findings.md` の P4）で、F4 プロンプターが値を trim して**左詰め**で
書くため、次の欄が正しい桁に入らないことが分かった。先頭の空白は trim で消えるので回避策も無い。

| 欄 | 入力 | 書かれた桁 | 正しい桁 |
|---|---|---|---|
| C 仕様 条件標識 9-11 | `OF` | 9-10（9 桁目は N 欄） | 10-11 |
| C 仕様 結果標識 71-76 | `    50`（等しい） | 71-72（高） | 75-76 |
| D 仕様 開始位置 26-32 | `12` | 26 から左詰め | 右寄せ（実機 RNF0263） |
| DSPF/PRTF 条件付け 8-16 | `40` | 8-9 | 9-10 |
| DSPF/PRTF 小数部 36-37 | `0` | 36 | 37（実機 CPD7422） |
| DSPF/PRTF 位置 39-44 | `7 74` | `7 74` を 39 から | 行 `  7`・桁 ` 74`（実機 CPD7422） |

## 目的 / ゴール
プロンプターで確定した値が、原典・実機の決まりどおりの桁に入り、実機でコンパイルできる。

紐づく charter ゴール: 固定長フォーマットの入力補助（プロンプター）

## スコープ
### 対象
- 定義に値の置き方（`attributes.columnLayout`: `right` / `indicatorSlots` / `rowColumn`）を持たせ、書き戻しで使う。形に合わない値は欄のエラー。
- C 仕様（ILE）の結果標識を高・低・等しいの 3 欄に分ける（RPG III の定義・SEU と同じ）。
- 対象の欄: C 条件標識・D 開始位置・F キー長（右寄せ）、DDS の条件付け・小数・位置（DDS は生成スクリプトで付ける）。
### 対象外
- C-NEW の条件標識の欄（P10）。C の新旧判定（P5）と一緒に扱う。

## 完了条件 (受け入れ基準)
- [ ] AC1: 表の各欄が正しい桁に書かれる（単体テスト）。
- [ ] AC2: 位置・条件付けの形に合わない値（`1 2 3`・`AB`）は欄のエラーになる（単体テスト）。
- [ ] AC3: プロンプターで書いた DSPF と RPG の行が実機（IBM i 7.3）でコンパイルできる。左詰めの対照は CPD7422 / RNF0263 になる。
- [ ] AC4: 桁の原典照合（`verify-rpg-definitions.mjs`）・定義の検査（`verify:defs`）・全定義の往復・既存テストが通る。
