## AC3: 検査が発火することの確認

**発火しない検査は何も守らない**ので、わざと順序依存のテストを用意した。
モジュール・レベルのグローバルを 1 つ置き、片方が書いて片方が読む。

```
     DSHARED           S             10I 0
     PTESTSETS         B                   EXPORT     ← SHARED = 1 を書く
     PTESTUSES         B                   EXPORT     ← SHARED を読む
```

`*API` 順ではアルファベット順に `TESTSETS` → `TESTUSES` と走るので**正順は緑**。

```
▸ 独立性   正順 0 失敗 / 逆順 1 失敗  … **食い違いあり**

  正順と逆順で合否が違うテスト（順序に依存している）:
    ✗ TESTUSES  正順=合格 / 逆順=失敗

終了コード 1
```

**捕まえた。** 正順だけ走らせていれば気付かないものを、機械的に弾けている。

## `compareRuns` の設計（self-test で固定）

**比べるのは合否だけ。** 実行時間・並び順・文言は毎回変わるので差として扱わない
（扱うと毎回「食い違い」になって検査が意味を失う）。self-test で 3 件を固定した。

| 入力 | 期待 |
|---|---|
| 並び順だけ違う | 食い違い**なし** |
| 合否が違う | 食い違い**あり** |
| 片方にしか無いテスト | 食い違い**あり**（順序で件数が変わるのは異常） |

## 判定

**全 6 件の受け入れ基準を満たしている。差し戻しは無し。**
