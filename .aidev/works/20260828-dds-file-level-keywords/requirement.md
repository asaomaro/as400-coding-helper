# 要件: ファイル・レベルのキーワードをデザイナから読めるようにする

## 背景 / 課題

`DSPSIZ` / `REF` / `INDARA` / `PRINT` は**最初のレコード様式より前**に書かれる。
`toLogicalUnits` はレコードにも項目にも属さない先頭のキーワード行を捨てるので
（配置に関係しないため）、**一覧にもプロパティにも出ない**。

`CUSTMNT.dspf` ではキーワード行 8 本のうち **4 本がこれにあたる**。
デザイナからは画面サイズも参照ファイルも標識域の指定も一切読めない。

## 目的 / ゴール

**ファイルに書かれたキーワードが、様式・項目と同じようにデザイナから読める状態。**

紐づく charter ゴール: DDS の視覚的な確認と編集（第 4 の柱）。

## ユーザーストーリー

- US1: DSPF を読む開発者として、**画面サイズや参照ファイルをデザイナで確かめたい**。
  なぜならそれらは様式の外にあり、いま見る手段がテキストエディタしか無いから。（受け入れ: AC1, AC2）
- US2: AI エージェントとして、**CLI の `parse` でファイル・レベルも受け取りたい**。
  なぜなら `records` にしか入っていないと、DDS の全体像が欠けるから。（受け入れ: AC4）

## スコープ

### 対象
- ファイル・レベルのキーワード行を読む（条件つきも）
- 一覧に出す・選ぶとプロパティに出す（原典の解説つき）
- CLI の `parse` に出す

### 対象外
- **編集**（`decisions.md` D3）。宛先が論理単位なので別の仕掛けが要る

## 完了条件 (受け入れ基準)

- [ ] AC1: `CUSTMNT.dspf` の 4 本が一覧に出る
- [ ] AC2: 選ぶとプロパティにチップで出て、**原典の解説が引ける**
- [ ] AC3: 編集できない以上、**効かない操作を出さない**（`✕` / `＋` / 生テキストの編集）
- [ ] AC4: CLI の `parse` に出る
- [ ] AC5: 最初の様式（または項目）で止まる。様式のキーワードを巻き込まない
- [ ] AC6: **項目を選ぶ側の邪魔をしない**（一覧の走査・キー移動が拾わない）
