# 計画: ファイル・レベルのキーワードをデザイナから読めるようにする

## 作業順序と依存関係
1. 分類を切り出す（`classifyDdsLine`）（依存: なし）
2. `fileLevelKeywordLines`（依存: 1）
3. モデルに載せる（画面・帳票）（依存: 2）
4. 一覧とプロパティ（依存: 3）
5. CLI の `parse`（依存: 3）
6. テストと e2e（依存: 4, 5）

## リスク / 留意点
- **`toLogicalUnits` の返す形を変えない**（読み手が「置けるもの」を前提にしている）。
- 一覧のクラス名を既存と共有すると、**項目を選ぶ側が拾う**。
- 編集できないものに編集の操作を出さない。

## テスト方針
- 実物（`CUSTMNT.dspf` / `CUSTRPT.prtf`）で読めることを見る。
- 様式・項目で止まること、注記行を飛ばすことを見る。
- **論理単位には入らない**ことを見る（既存の読み手を壊していない担保）。
- e2e で一覧に出て、選ぶとプロパティに出て、**編集の操作が出ない**ことを見る。
