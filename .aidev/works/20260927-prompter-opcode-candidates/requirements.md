# 要件: C 仕様書の命令コードに候補を出す

## 背景 / 課題
2026-09-27 の実操作調査（`docs/research/20260927-f4-prompter-exploration/findings.md` の P18）で、ILE RPG の C 仕様書のプロンプターの
命令コードの欄に候補が無く、何を書けるか分からなかった。

## 目的 / ゴール
C-SPEC / C-NEW の命令コードの欄に、その形式で書ける命令の候補が出る。

紐づく charter ゴール: 固定長フォーマットの入力補助（プロンプター）

## スコープ
### 対象外
- 同じ P18 の「F1 ヘルプが命令と無関係」、P16・P17・P20・P21（backlog に残す）。

## 完了条件 (受け入れ基準)
- [ ] AC1: C-NEW には拡張演算項目 2 を取る命令（`EVAL` / `IF` / `ELSE` / `ENDIF` …）、C-SPEC には取らない命令（`CHAIN` / `MOVEL` …）が候補に出る。
  分け方は行の分類（`DEFAULT_C_NEW_OPCODES`）と同じ集合で、定義の JSON に命令を並べ直さない（単体テスト）。
- [ ] AC2: 候補は制限ではなく、`EVAL(H)` も書ける（単体テスト）。
- [ ] AC3: 本物の VS Code で、C-NEW / C-SPEC の行の F4 に候補が出る。
