# 要件: ソース表示を下部ドックへ移す

## 症状

DDS ビジュアルエディタで、**エディタとソース表示が左右に並んでいる**ため
横幅が足りず、**エディタ側に横スクロールバーが出る**。

原因は `vscode-extension/dev/standalone.css` の
`#panes { grid-template-columns: minmax(0, 1fr) minmax(340px, 36%); }`。
ソース面が**最低 340px・最大 36%** を横取りし、エディタ内部でも
左 200px ＋ 右 320px が固定なので、**キャンバスに 80 桁を描く幅が残らない**。

**桁は横に伸びる。** 横を削る置き方と相性が悪く、縦なら行数を削るだけで済む。

## 要件

1. ソース表示を**エディタの下部・全幅**に移す。
2. **自由に展開できる**——ドラッグで高さを変え、畳み、半分／最大にできる。
3. **検証（診断）を同じドックにタブでまとめる**。下端の取り合いを避ける。
4. 畳んでも**タブ行は残り、検証の件数が見える**（いまは常設リストなので、
   タブに入れると気付けなくなる。その手当て）。
5. **3 ペイン（左・キャンバス・右）は変えない**。C1 で「移植可能性の核心」と決めた構成。
6. **左右ペインを畳めるようにする**（132 桁のため）。

## 決定（設計 README に全文）

`docs/design/dds-designer/README.md` の「案 D」節。4 点とも
**「開くときだけ判断し、以降は勝手に動かない」**で揃えた。

| # | 決定 |
|---|---|
| 2 | ドックは **WebView 内に自前で持つ**（ソースは表示専用） |
| 1 | 既定は**ソース 8 行（約 190px）**。選択に追従。以降おぼえる |
| 3 | 検証タブは**開くときだけ判断**（エラーがあれば検証タブ） |
| 4 | 左右ペインは畳める。**開くときに幅が足りなければ畳んでおく** |

## 非要件

- **198 桁は収まらない**（畳んでも 1649px 必要）。ズームで扱う。
- ドック内でのソース編集はしない（表示専用）。
