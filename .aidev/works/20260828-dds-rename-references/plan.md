# 計画: 名前変更の参照追随

## 作業順序と依存関係

1. `ddsReferences.ts`（引数の切り出し・表・`findFieldReferences` / `renameFieldReferences`）
2. `setAttributes` の `name` に追随を足す（依存: 1）
3. UI（断り書きの訂正・件数）（依存: 2）
4. 単体テスト（依存: 2）
5. `verify-dds-references.mjs` と `npm run verify` への登録（依存: 1）
6. 実機で書き出しを確かめる（依存: 2）
7. e2e（依存: 3）

## リスク / 留意点

- **一部一致で壊す**。引数を切ってから丸ごと一致。単体で固定する。
- **外部を指す引数を触る**。これが起きると原因の分からない壊れ方をするので、
  「触らない」ことを単体で固定する（`REF` / `REFFLD` / `FONTNAME`）。
- **表の書き漏らし**。検査で見張る（`verify-dds-references.mjs`）。

## テスト方針

- 単体: 追随する / しない の両方。特に**外部を指す引数が変わらないこと**。
- 検査: 原典の syntax に名前らしい引数があるのに判断が書かれていないキーワードで落ちる。
- 実機: 追随した結果が `CRTDSPF` を通る。**追随しないと通らない**ことも見る
  （追随の値打ちがそこにあるため）。
- e2e: 名前を変えると参照の行も変わる。
