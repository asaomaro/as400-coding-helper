# 要件: 名前変更の参照追随

## 背景 / 課題

項目の名前を変えても、その名前を**引数に持つキーワード**は追随しない。
プロパティにも「名前を変えても、参照しているキーワード（SFLCTL 等）は追随しません」と
断りが出ている。名前を変えたソースは**実機がコンパイルを通さない**か、
通っても別のフィールドを指す。

**この断り書き自体が誤っている。** `SFLCTL` が指すのは**レコード様式**であり、
項目の名前を変えても影響しない。デザイナに様式を改名する手段は無い（名前の入力欄が
あるのは項目のプロパティだけ）ので、いま追随すべきなのは**項目の名前**の参照。

## 目的 / ゴール

項目の名前を変えると、**同じソースの中でその項目を指しているキーワードの引数**も
一緒に変わる状態。指していないもの（外部のファイル・フォント・メッセージ）は
**変えない**。

## ユーザーストーリー

- US1: DSPF を書く人として、項目の名前を変えたらそれを参照しているキーワードも
  直ってほしい。なぜなら手で直すには、どのキーワードが名前を採るかを覚えている
  必要があり、それはデザイナを使う理由と正反対だから。（受け入れ: AC1, AC2, AC4）
- US2: 同じ人として、**外部のオブジェクトを指す引数は絶対に触らないでほしい**。
  なぜなら `REF(CUSTMST)` が黙って書き換わると、原因の分からない壊れ方をするから。
  （受け入れ: AC3, AC5）

## スコープ

### 対象
- **項目（フィールド）の名前**を変えたときの追随。
- 追随する引数は 2 種類:
  - `&名前`（プログラム - システム間フィールド）——原典より**このソースの中の項目**。
  - 原典が「このファイル内の項目」と明記している定位置の引数
    （`CSRLOC` / `HLPARA(*FLD …)`）。

### 対象外
- **様式（レコード）の改名**。デザイナに手段が無い（改名できないものの参照を
  追随させるコードは到達しない）。`SFLCTL` / `ERASE` / `PASSRCD` /
  `MNUBARDSP` / `MNUBARCHC` / `HLPRCD` の参照はここに入る。別項目として起票する。
- 外部オブジェクトを指す引数（`REF` / `REFFLD` / フォント / オーバーレイ /
  メッセージ・ファイル など）。**触らない**。

## 完了条件 (受け入れ基準)

- [ ] AC1: 項目の名前を変えると、`&旧名` を持つキーワードの引数が新しい名前になる。
- [ ] AC2: `CSRLOC(旧名 X)` / `HLPARA(*FLD 旧名)` も追随する。
- [ ] AC3: `REF(...)` / `REFFLD(...)` など**外部を指す引数は変わらない**。
- [ ] AC4: 追随は**同じソースの中だけ**で、様式・ファイル・レベルの行も対象
      （`CSRLOC` は様式のキーワード）。
- [ ] AC5: 名前の一部が一致するだけのもの（`&CUSTNO2` の中の `CUSTNO`）は変えない。
- [ ] AC6: 追随した結果が**実機でコンパイルを通る**。

## 相互作用の受け入れ基準

- [ ] AC-I1 何が起きたか分かる: 追随した件数をステータスに出す。
      黙って複数行が変わると、何をしたのか分からない。
- [ ] AC-I2 断りの文言を直す: 追随するものと**しないもの**（様式の改名）を書く。
