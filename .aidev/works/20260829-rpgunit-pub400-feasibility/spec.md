# 仕様: RPGUnit の pub400 導入可否を確かめる

## 設計方針

### D1: 副作用の無い方法で確かめる（共用機なので）

pub400 は**共用の公開機**。「導入を試みる」を素直に実行すると、失敗しても
save file やライブラリの残骸が出る。**先に権限を見れば、試さずに決着する**。

使うのは 2 つだけ:
- `QSYS2.USER_INFO` / `QSYS2.OBJECT_STATISTICS`（読み取り）
- `CHKOBJ OBJ(QSYS/<cmd>) OBJTYPE(*CMD) AUT(*USE)`（**権限を見るだけ**でオブジェクトを作らない）

AGENTS.md の「判定は副作用の無い形で行う」と同じ考え方。

**注意**: `CHKOBJ` は可否を予測しきれないことがある（AGENTS.md——`QSYS` 側がプロキシで
実体が別ライブラリーにあるものがある）。ここでは `SPECIAL_AUTHORITIES` が**空**である
という直接の事実と合わせて判断するので、`CHKOBJ` 単独に依存していない。

### D2: 「入れられない」で終わらせず、どこでなら入るかまで測る

依存項目（P 仕様書での RPGUnit）が止まっているので、**次の一手が決まる形**にする。
同じ probe を SR-OSAKA にも当てて対比する。

### D3: 実際には入れない

pub400 が不可と決まった時点で、SR-OSAKA に入れるのは**別の判断**——
起票の対象機械が違ううえ、**第三者のバイナリ（save file）を利用者の機械に入れる**話。
可否を測るところまでが本項目。
