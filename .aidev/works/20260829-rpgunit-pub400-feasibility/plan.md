# 計画: RPGUnit の pub400 導入可否を確かめる

## 作業順序と依存関係

1. **T1** pub400 の権限と復元系コマンドを測る（依存: なし）
2. **T2** 代替経路（`CRTLIB` / ビルド系）を測る（依存: T1）
3. **T3** SR-OSAKA で対比する（依存: T2）
4. **T4** 結果を記録し、backlog の依存項目の前提を書き換える（依存: T3）

## リスク / 留意点

| リスク | 対応 |
|---|---|
| **共用機に残骸を作る** | `CHKOBJ` と SQL の読み取りだけ。作成・削除をしない |
| `CHKOBJ` が可否を予測しきれない | `SPECIAL_AUTHORITIES` が空という直接の事実と合わせて判断する |
| 「入れられない」で止まる | どこでなら入るかまで測り、次の判断材料にする |

## テスト方針

- コード変更が無いので自動テストは増やさない。
- **probe を成果物として残す**（`verify/probe-*.mjs`）。同じ確認を再実行できる。
- 判断の根拠は**メッセージ ID と権限一覧の生の値**を結果に載せることで検証可能にする。
