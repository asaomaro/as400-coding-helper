# 決定記録

## D1: 実機の検証スクリプトから `DLTSPLF` を外す（スプールは残す）

- 背景: research のプローブが片付けのつもりで「利用者の直近 3 件のスプール」を
  **順位で掴んで削除**していた。`CRTPF` が `CPD0043`（`REPLACE` は無効）で即座に落ち、
  リストが 1 件も生成されなかった回に、掴んだ 3 件がすべて**無関係な既存スプール**で、
  6 ケース分で**約 15 件を削除**した（`075010/ASAO/QPRTJOB` の `#942` 以降）。
  `QSYS2.HISTORY_LOG_INFO` に記録は残らず**復元できない**。
- 決定: この work のプローブは `DLTSPLF` を持たない。作成したスプールは名前と番号を
  `results.md` に記録して残し、片付けは利用者が決める。オブジェクト・メンバー・
  ソース物理ファイル・IFS は名前が一意なので消す。
- 理由 / 代替案: 名前と作成時刻で自分のものだけを消す形にも直せる（一度そう直した）が、
  **「消す」判断がスクリプトに残る**。利用者が削除そのものを外すことを選んだ。
- 影響: requirement の AC9「実機の残骸が 0」のうち**スプールだけ意図的に 0 でない**。
  `spec.md` D9 と `results.md` に明記した。以後の実機プローブもこの方針に従う。

## D2: 物理/論理 38 桁は 3 文脈（物理・単純論理・結合論理）を測る

- 背景: `CRTPF` だけで測ると受理は ブランク `B` の 2 件で、定義（ブランク `B` `I` `N`）と
  食い違った。原典を読み直すと **38 桁目は文脈ごとに値集合が違う**と明記されていた
  （`FIELD-PF-lfusg.html`「物理ファイルの場合に指定できる項目」「論理ファイルに有効な項目」、
  および「N は結合論理ファイルの場合にだけ有効」）。
- 決定: `CRTPF` / `CRTLF(PFILE)` / `CRTLF(JFILE)` の 3 本を流し、**受理集合の和**を
  定義と突き合わせる。17 桁も同じ理由で 3 文脈すべてを測った。
- 理由 / 代替案: **1 つの定義（`DDS-PF.json`）が `.pf` と `.lf` の両方を担う**ので、
  対応するのは和。1 文脈だけで判定すると「定義が誤っている」と誤診し、
  `I` `N` を消して**論理ファイルの正しいソースを弾く**ところだった。
  種別ごとに定義を分ける案は、スキーマと消費経路（`positionResolver`）に及ぶので採らない。
- 影響: `spec.md` の「実機に流す一覧」に無かった 2 本（`probe-logical.mjs` /
  `probe-join.mjs`）を足した。結果は 3 文脈とも原典と一致した。

## D3: 印刷装置 17 桁は `restricted: false` のままにする

- 背景: 実機は `H` を受ける（`CPD7410@17` が出ず、35 桁と 42 桁の指摘だけ）。
  **原典は日英とも `R` とブランクだけ**を挙げる（`FIELD-PRTF-prttype.html` / `dds-en`）。
- 決定: `PROVEN_COMPLETE` に入れない。値集合も原典のまま（`H` を足さない）。
- 理由 / 代替案: `H` を足せば一致して `true` にできるが、**`H`（ヘルプ仕様）が
  印刷装置で何を意味するのかが分からない**。原典に無い値を定義へ足す判断は根拠が要る。
  `false` なら候補つき自由入力のままで、`H` を書きたい利用者を妨げない
  （厳しくして正しいソースを弾くより安全側）。
- 影響: 7 欄中 6 欄が `true`。理由を生成器の表とテストのコメントに残した。

## D4: 印刷装置 38 桁の選択肢が空だが、この work では直さない

- 背景: 検証中に見つけた**別の欠陥**。`FIELD-PRTF-prtuse.html` は
  `O またはブランク: 出力専用` / `P : プログラム - システム間` と値を挙げているが、
  `<dt>/<dd>` でも表でもないため生成器が拾えず、定義は `inputType: "text"` で
  **選択肢が 1 つも無い**。
- 決定: この work では直さず、backlog に戻す。
- 理由 / 代替案: requirement の対象は「いま選択肢を持つ 8 欄」で、この欄は入っていない。
  直すと**入力欄が text から dropdown に変わる**（利用者に見える変更）うえ、
  原典の新しい書き方（`O またはブランク: …`）を読む器が要る。
  `restricted` を広げる話とは別の問題なので、混ぜるとレビューの単位が崩れる。
- 影響: backlog に 1 項目を足す。実機の値集合は未取得。

## D5: 原典 errata は使わない（backlog の前提が誤っていた）

- 背景: backlog は「印刷装置 35 桁は原典に `G` `O` が無い。**原典側を errata で補う
  判断が要る**」としていた。実際には原典の**値の表の直後の注**にあり、
  ブランクも本文に明記されていた。
- 決定: `ORIGIN_ERRATA` は触らず、`addNoteDataTypes` の正規表現を緩め、
  ブランクは根拠つきの表（`BLANK_FROM_PROSE`）で足す。
- 理由 / 代替案: **原典が正しいのに誤りとして記録すると、後から見た人が原典を疑う。**
  緩めても巻き込まないことは原典の全件走査で裏を取った（`dds` と `dds-en` の全 HTML で
  「DBCS を含む注」を持つのは 3 ページだけ、いずれもデータ・タイプのページ）。
- 影響: `spec.md` D7 のとおり。errata の項目は増えていない。

## D6: 単独起動ハーネスに DDS の定義を足した

- 背景: プロンプターの e2e（`dev/prompter-e2e.mjs`）は CL / .cmd の定義しか開いておらず、
  **DDS の欄が `<select>` になり、ブランクへ戻せること**を押して確かめる経路が無かった。
  `restricted: true` は入力欄の種類を変える（`buildOpenChoice` → `buildSelect`）ので、
  相互作用の受け入れ基準（AC-I1 / AC-I2 / AC-I5）がモデルまでしか届かない。
- 決定: `dev/prompter-standalone.ts` の `SAMPLES` に `DDS-PF.json` を足し、
  `dev/prompter-e2e.mjs` に 7 件の確認を足した（17/35/38 桁が `<select>` であること、
  ブランクが選択肢の先頭にあること、値を入れたあとブランクへ戻せること）。
- 理由 / 代替案: 単体テストは「値集合にブランクがある」までしか見られない。
  **`select.value = field.value` が一覧に無い値を黙って落とす**という、この変更の
  中心にあるリスクは、実際に選ばせないと確かめられない
  （AGENTS.md「プロンプターはモデルまででは届いていない」）。
- 影響: `dev/` は検証用で VSIX には入らない。e2e は 62 → **69/69 PASS**。
