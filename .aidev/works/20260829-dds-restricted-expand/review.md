## 指摘

### must-1: lint 規則の説明が、この変更で誤りになった

`vscode-extension/src/lint/rules/index.ts:199`

```
「その印が付くのは、実機で全空間（1 文字なら 37 通り）を試して原典と一致した欄だけ
 （**いまは表示装置の 38 桁目**）。」
```

印が付く欄は **7 欄**になったので誤り。しかもこの文字列は
**SARIF の `rules[].shortDescription.text` に出る**（`lint` CLI の出力で確認済み）ので、
利用者が読む。定義側の表（`generate-dds-prompter.mjs` の `PROVEN_COMPLETE`）は
更新したのに、**消費側の説明が取り残された**。

### should-1: `restrictedValue.ts` の説明が 3 点で事実と違う

`vscode-extension/src/lint/rules/restrictedValue.ts:3-20`

| 記述 | 事実 |
|---|---|
| 「**既定では無効**（`rules/index.ts` の enabledByDefault）」 | `enabledByDefault: **true**`（PR#142 で既定 ON） |
| 「DDS / RPG の定義は restricted を設定していないので、有効化しても**現状は 1 件も検出しない**」 | 表示装置 38 桁で既に検出していた。今回さらに 6 欄 |
| 「**修復が要る理由**（research.md F1）…原典の注を読んでいない／ブランクも 0 も落ちている」 | いずれも修復済み（前作業と今回） |

**この work より前からの古さ**だが、同じ機能の同じ面にあり、今回さらに乖離した。
「既定では無効」は特に危険で、**規則が効いていないと読ませる**。

### nit-1: 注の走査窓を広げた理由が差分から読めない

`docs/origin/generate-dds-prompter.mjs` の `addNoteDataTypes` で、窓を
`{0,160}` → `{0,200}` に広げている。**原典の全件で抽出結果は 160 と 200 で同一**
（日英 3 ページとも同じ値）なので、この変更は結果を変えていない。

広げた理由自体はある——**前置きの語（`データ・タイプ` / `The data types`）を
正規表現が消費しなくなった**ので、同じ実効範囲を保つには窓を広げる必要がある。
だがコメントに書かれていないため、**後から見ると根拠の無い変更に見える**。

### should-2: 英語版 DDS 定義に日本語が混ざる（範囲外・既存）

`resources/prompter/dds/en/DDS-*.json` に日本語が **146 箇所**ある
（欄の説明・ヘルプ・`（ブランク）` の接頭辞）。今回足したブランクも同じ形
（`"（ブランク）Character (default)"`）で、**隣接する `addBlank` と同じ書き方**に
そろえてある。

RPG 側は「英語版に日本語が混ざらないこと」を `verify-rpg-spec-definitions.mjs` が
検査しているが、**DDS には同じ検査が無い**。

**この work では直さない**。原因は `（ブランク）` の接頭辞だけでなく、欄の説明が
桁定義（日本語）から来ていることにあり、`restricted` を広げる話とは別。
直すなら訳文の置き場（RPG の `rpg-spec-en-strings.json` に相当）から要る。
→ **backlog に起票する**。
