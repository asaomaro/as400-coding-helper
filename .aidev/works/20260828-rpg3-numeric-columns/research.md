# 調査: RPG III の数値欄

## 判明した事実

実機は IBM i 7.3 / `CRTRPGPGM`。原典が入手できないので**コンパイラが唯一の判定者**。

### F1: C 仕様の長さ・小数は**数値かつ右寄せ**（`verify/probe-rpg3-numeric.mjs`）

| 形 | 実機 |
|---|---|
| 長さ 51 桁に右寄せ ＋ 小数（対照） | 通る |
| **長さを 49 桁に左詰め** | **通らない** |
| 長さ 2 桁を 49-50（左詰め） | **通らない** |
| 長さ 2 桁を 50-51（右寄せ） | 通る |
| **長さ欄に英字** | **通らない** |
| **小数欄に英字** | **通らない** |
| 長さ欄に空白を挟んだ数字 | **通らない** |

### F2: I 仕様の開始・終了・小数も同じ（`verify/probe-rpg3-io.mjs`）

| 形 | 実機 |
|---|---|
| 開始 44-47 / 終了 48-51 を右寄せ（対照） | 通る |
| **開始を左詰め** / **終了を左詰め** | **通らない** |
| **開始欄に英字** / **小数欄に英字** | **通らない** |

### F3: **数値の結果フィールドには小数位置が要る**

最初は小数を省いた形を対照にして**全部落ちた**。`Z-ADD` の相手が数値だからで、
桁の話ではなかった。対照を置いていなければ「長さ欄は右寄せでも通らない」と
誤読していた。

### F4: **対照づくりで 3 回つまずいた**

`SETON` を書き忘れて結果標識だけ置いた / 小数を省いた /
I 仕様のレコード識別標識を 17-18 桁に置いた（正しくは 19-20）。
**いずれも対照が落ちて気付いた。**

### F5: **`RPG3SAMP.rpg` も壊れていた**

`     C                     Z-ADD0         TOTAL 6` — 長さが **49 桁（左詰め）**で
**小数が無い**。実機は通さない（`verify/verify-rpg3-fix.mjs` の対照で確認）。

### F6: `numeric-alignment` が**行末で欄が切れると判定を諦めていた**

> // 行末で欄が切れている場合は右寄せかどうか判定できない。

固定長のレコードは空白で埋められるので、「行が短い」は「残りが空白」と同じ
——欄の最後の桁に値が来ていない、つまり**左詰め**。実機はその形を通さない（F1）。
