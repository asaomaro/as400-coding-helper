# レビュー: 候補にすぎない選択欄を、一覧つき自由入力にする

## ラウンド 1（自己レビュー・2026-08-29）

対象: `formModel.ts` / `webview/ui.ts` / `dev/prompter-standalone.ts` /
`dev/prompter-e2e.mjs` / `test/unit/prompterWebview.test.ts`。

### 要件適合

AC1〜AC5 / AC-I1〜I5 すべてに対応する検証がある（`verify/results.md`）。
`対象外` に手を出していない——`restricted` の値そのもの・`validate()`・定義 JSON は無変更。

### 価値適合

目的は「**実機が受ける値を、プロンプターからも打てる状態**」。

- 打てる: `ADDPFM` の `SRCTYPE` に `RPGLE` を打って確定し、書き戻し行に乗ることを画面で確認。
- 候補は見えたまま: `<datalist>` に `*NONE` が並ぶ。
- **範囲が正しい**: 制限のある欄は `<select>` のまま。**変えすぎても落ちる**検査を置いた。

### 正確性

| # | 重大度 | 内容 | 対応 |
|---|---|---|---|
| 1 | should | 既存の e2e「種類ごとに候補一覧が出る」が **`datalist` を全件数えて**いたため、欄ごとの候補が増えて落ちた。検査したいのは「オブジェクト候補が種類ごとに出るか」だけ。 | `datalist[id^='objects-']` に絞り、詳細も出すようにした。**過剰に固定した検査は、正しい変更を落とす。** |
| 2 | nit | `buildOpenChoice` が `<span>` で入力欄と `<datalist>` を包む。`<datalist>` は描画されないので包む必要は無いが、**欄と候補が離れると対応が読めない**ので同居させた。 | そのまま（意図を注記済み）。 |

**新たな欠陥は見つからなかった。** 変更が小さく、既存の手段（`<datalist>`）を
そのまま使ったため。

### 規約適合（AGENTS.md）

- **「列挙した値＝制限とは限らない」** — この原則は定義（`restricted`）と検証
  （`validate`）には通っていたが、**画面だけが遅れていた**。今回そこを揃えた。
- **「同じ概念集合を複数箇所で列挙しない」** — 「制限か候補か」の判断は
  `attributes.restricted` の 1 箇所だけ。画面は独自に判断しない。
- **「落ちないテストは何も守っていない」** — 3 件で確認。うち 1 件は
  **変えすぎ方向**（制限のある欄まで自由入力にする）。
- **「追加したリソースは到達可能になって初めて完了」** — 描画モデルに `restricted` を
  足しただけでは死蔵。**画面で押して確かめる**ところまで e2e で辿った。
- **PR#98 の後退を戻さない** — `buildTextInput` を使い回したので `maxlength` の
  CL 変数の余地はそのまま（既存の e2e が見張っている）。

### 保守性

- `buildControl` の分岐は 1 行（`restricted === false ? 開く : 閉じる`）。
  読む単位を増やしていない。
- 件数（108 / 57）を単体テストで固定した。**動いたらこの変更の前提が変わっている。**

### 既知の制限

- `<datalist>` の見え方はブラウザ / WebView 実装に依る。**候補が並ぶこと**は
  DOM で確かめられるが、**どう表示されるか**は確かめていない。
  オブジェクト名の候補が同じ仕組みで出荷済みなので、新しい risk は増えていない。

## 判定

**must 0 件 / should 1 件 / nit 1 件——解消済み。** 差し戻しなし。
