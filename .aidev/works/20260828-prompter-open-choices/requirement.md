# 要件: 「候補にすぎない」選択欄で、一覧に無い値も打てるようにする

## 背景 / 課題

**列挙した値＝制限とは限らない。** 実機が `Rstd=NO` と言う欄では、列挙値は候補にすぎず
任意の値を書ける（AGENTS.md「入力の検査を厳しくするときは、実機の値を流して確かめる」）。
定義側はこれを `attributes.restricted: false` で表している。

ところが **`restricted:false` は検証を緩めるだけ**で、画面は `<select>` のまま。
`<select>` である以上、**一覧に無い値は打てない**。

実測（2026-08-29・現 main）:

- 該当は **108 欄**（`cl` / `cmd` の ja・en 合計）。
- うち **57 欄は選択肢が 1 つしかない**。選択肢 1 つの `<select>` は選択ではなく**錠前**で、
  その欄には**実質何も入力できない**。
- 典型が `ADDPFM` の `SRCTYPE`。原典の定義済み値は `*NONE` だけだが、実際に書くのは
  `RPGLE` / `CLP` など。**プロンプターからは打てない。**

`20260828-prompter-standalone` で「ソースに書かれていた値は選択肢に足す」ようにしたので
**既にある値が消えることは無くなった**が、**新しく打つことはできないまま**。
`20260828-rpg3-fspec-continuation-options` では同じ問題を
`inputType:"text"` にして**回避**した——回避であって解決ではない。

## 目的 / ゴール

**実機が受ける値を、プロンプターからも打てる状態。**
候補は候補として見えたまま、一覧に無い値も入力できる。

紐づく charter ゴール: `.aidev/charter.md` が無いため該当なし。

## ユーザーストーリー

- US1: **拡張の利用者**として、`ADDPFM` の `SRCTYPE` に `RPGLE` と打ちたい。
  なぜなら**それが実機の受ける値**であり、いまはプロンプターを使うと書けないから。（AC1, AC2）
- US2: **拡張の利用者**として、候補は候補として見えていてほしい。
  なぜなら**打てるようになった代わりに候補が消える**のでは、使い勝手が下がるから。（AC3）
- US3: **この拡張を触る開発者**として、この判断を定義側の 1 つの旗
  （`restricted`）だけで表したい。なぜなら**同じ意味の指定が 2 つある**と食い違うから。（AC4）

## スコープ

### 対象

- `restricted:false` かつ選択肢を持つ欄の**入力部品を変える**（`<select>` → 一覧つき自由入力）。
- 描画モデルに `restricted` を載せる（いま載っていないので画面から見えない）。

### 対象外

- **`restricted` の値そのものの見直し**。どの欄が `Rstd=NO` かは CDML 由来で確定済み。
- **検証の強さ**。`validate()` は既に `restricted !== false` を見て正しく振る舞う。
- RPG / DDS の定義（`restricted:false` の dropdown は無い。CL / cmd だけの話）。

## 機能要件

- `restricted:false` かつ `options` があるとき、**一覧を見ながら任意の値を打てる**。
- `restricted` が未指定（＝制限あり）の欄は**いままでどおり `<select>`**。
- 既にある値は失われない（`20260828-prompter-standalone` の `withCurrentValue` と両立する）。

## 非機能要件 / 制約

- **CSP を緩めない。** インライン `style` を使わない（既存の作法どおり）。
- 既存の 182 + 57 件の e2e と 1118 件の単体テストを壊さない。

## 完了条件 (受け入れ基準)

- [ ] AC1: `restricted:false` の欄に、**一覧に無い値を打って確定できる**。
- [ ] AC2: 打った値が**確定の値としてホストへ渡る**（書き戻しに乗る）。
- [ ] AC3: 候補が**一覧として見える**（打ちながら選べる）。
- [ ] AC4: `restricted` が未指定の欄は `<select>` のまま（**振る舞いを変えない**）。
- [ ] AC5: `npm test` / `npm run verify` / e2e 2 本が緑。

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: 一覧は入力欄の操作で開き、選ぶか他へ移ると閉じる。
- [ ] AC-I2 確定 / 取り消し: 一覧から選んでも、直接打っても、同じように確定できる。
- [ ] AC-I3 キーボードだけで完結する: `Tab` で入り、打つか選ぶかして `Tab` で抜けられる。
- [ ] AC-I4 フォーカスの行き先: 描き直しを挟んでも入力中の欄から外れない。
- [ ] AC-I5 既存の操作を妨げない: `restricted` 指定の無い欄の操作は変わらない。
