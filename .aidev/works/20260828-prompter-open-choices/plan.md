# 計画: 候補にすぎない選択欄を、一覧つき自由入力にする

## 実装方針

**下から積む。** 描画モデル → 画面 → ハーネス → e2e。
変える範囲が狭い（`restricted === false` の欄だけ）ので、
**変えていない範囲が変わっていないこと**の確認に重みを置く。

## 作業順序と依存関係

1. `SerializableField.restricted` を足し、`toSerializableState` で詰める（依存: なし）
2. `buildControl` の分岐と `<datalist>` 生成（依存: 1）
3. ハーネスに `ADDPFM` を足す（依存: 2）
4. e2e で「一覧に無い値を打って確定できる」を確かめる（依存: 3）
5. 単体テストで載せる範囲を固定（依存: 1）
6. 全部回す（依存: 4, 5）

## リスク / 留意点

- **R1: 変える範囲を間違えると 108 欄が壊れる。** `restricted` 指定の無い欄が
  `<select>` のままであることを**e2e と単体の両方で**固定する。
- **R2: `maxlength` の CL 変数の余地を落としやすい。** `buildTextInput` を
  そのまま使えば落ちないが、別経路を作ると再発する（PR#98）。**別経路を作らない。**
- **R3: `<datalist>` は表示の部品なので、壊れても例外が出ない。**
  「候補が並ぶ」ことを e2e で見る（DOM の `<option>` を数える）。

## テスト方針

| 見るもの | どこで |
|---|---|
| `restricted` が描画モデルに載る / 載せる範囲 | `test/unit/prompterWebview.test.ts` |
| 一覧に無い値を打って確定できる | `dev/prompter-e2e.mjs`（`ADDPFM` の `SRCTYPE` に `RPGLE`） |
| 候補が一覧として見える | 同上（`<datalist>` の中身） |
| **制限ありの欄は `<select>` のまま** | 同上（回帰） |
| 既存が壊れていない | `npm test` / `npm run verify` / DDS の e2e 182 件 |

**後退を戻すと落ちることを確かめてから載せる。**
