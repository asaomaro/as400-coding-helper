# レビュー: 行長の数え方を実機の桁に揃える

## ラウンド 1（自己レビュー）

### 要件適合

- AC1 実機の桁で数える → 単体 4 件。**JS の文字数に戻すと落ちる**ことを確認済み。
- AC2 文言に両方 → 単体 1 件（`170 桁` と `文字数は 88` の両方を見る）。
- AC3 折り返しの各塊が 36 桁以内 → 単体 3 件（全角 1-40 の総当たりを含む）。
- AC4 実機で通り、読み直しで戻る → `verify/verify-folded-dbcs.mjs`（全角 10/16/17/20/34）
  ＋ 単体 2 件（全角 1-40 と混在の読み直し）。
- AC5 半角の回帰 → 単体 1 件（折り方が変わらない）。
- AC-I1 下線は溢れ始める文字から → 単体 1 件。

### 価値適合

「切れたことに気付くのは転送してコンパイルした後」——**気付けるようにする**のが
lint 側、**そもそも書き出さない**のが折り返し側。後者が起票時に見えていなかった
一番重い欠陥だった（`decisions.md` D5）。

### 正確性

- **実機と値が完全に一致**することを 5 通りで確かめた（境目の前後・混在）。
- 全角を半分に割らないよう、`-` で切る位置も桁で決めている。
- 切る位置が 0 のときに止める（無限に積まない）。全角 1 文字で 35 桁を超えることは
  無いが、`KEYWORD_AREA_WIDTH` が変われば起こりうる。

### 規約適合

- **同じ判定を 2 か所に持たない**（D2）。`printWidth` を作り直していない。
- **既存テストの前提を実機の証拠で直した**（D4）。消していない。
- 上限の値は動かしていない（D1）——数え方の話と混ぜない。

### 保守性

`indexExceedingWidth` は `printWidth` の隣に置き、返すのが**JS の添字**である
ことを名前と注記に書いた。

### 指摘

- must: 0 / should: 0 / nit: 0
