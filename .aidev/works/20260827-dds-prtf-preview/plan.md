# 計画: 帳票のプレビューモード（CPI / LPI）

## 作業順序と依存関係

1. 原典から値の集合を生成 — 依存なし
2. 検査（形式・本文・`CRTPRTF` の既定）— 依存: 1
3. core（値の集合・ソースからの読み取り・紙の大きさ）— 依存: 1
4. 描画モデルに載せる — 依存: 3
5. UI（切替・選択・用紙・物理セル）— 依存: 4
6. 単体テスト — 依存: 3, 4
7. GUI e2e — 依存: 5
8. **実機で値の集合を確かめる** — 依存: 3
9. 記録 — 依存: 全部

## リスク / 留意点

- **倍率の二重適用**。プレビューでは実測を使わない（物理 × 倍率だけ）。
- **フォントが升目に合わない**。幅で合わせる（等幅なので桁は合う）。
- **1 ページの中で LPI が変わる帳票**は描けない。**知らせる。**
- 画面ファイルに出さない（CPI / LPI は帳票のもの）。

## テスト方針

- **単体**（`test/unit/prtfDensity.test.ts` 新規）: 値の集合・既定・ソースからの読み取り
  （最初のものを採る / 複数の検出 / 原典に無い値を採らない / 他のキーワードに反応しない）・
  **紙の大きさを原典の例で検算**・モデルに載ること。
- **原典検査**: `npm run verify` に足す。
- **GUI e2e**: 既定は切 / 紙の比率になる / 用紙がインチで出る / CPI・LPI を変えると変わる /
  **倍率と掛け合わさる** / **プレビュー中でも掴んだ項目が指した桁に入る** /
  切ると戻る / 画面では出ない。
- **実機**: `CPI` / `LPI` に**通る値と通らない値の両方**を流し、集合が一致することを見る。
