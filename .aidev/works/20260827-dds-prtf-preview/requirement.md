# 要件: 帳票のプレビューモード（CPI / LPI を見た目に反映する）

## 背景 / 課題

帳票をビジュアルエディタで開けるようになった（`20260827-dds-prtf-editor`）が、
キャンバスは**等幅フォントの升目**で描いている。紙の上の見え方とは比率が違う。

紙面の比率は **CPI（1 インチ当たりの文字数）と LPI（1 インチ当たりの行数）**で決まる。
原典（`LPI` キーワード）:

> 例えば、ページの長さが 66 行で、ファイルの LPI の値が 6 であるとすれば、
> **用紙の長さは 11.0 インチ**です。

つまり同じ 66 行 × 132 桁でも、**10 CPI / 6 LPI なら 13.2 × 11.0 インチ**、
**15 CPI / 8 LPI なら 8.8 × 8.25 インチ**——紙に対する詰まり方がまるで違う。

いまのキャンバスからは、

- **用紙に収まるのか**が分からない（A4 横は 11.7 インチ）。
- **文字の縦横の比**が実際と違うので、詰まった帳票の印象が掴めない。
- `CPI` / `LPI` を書き換えても**見た目が変わらない**。

紐づく charter ゴール: **DDS（DSPF/PRTF）の視覚的な確認と編集**を第 4 の柱として加える。

## 目的 / ゴール

**紙の比率で帳票が見えている状態**。CPI と LPI を指定すると、その場で見え方が変わる。
**用紙の大きさ（インチ）が読める状態**。

## ユーザーストーリー

- US1: 帳票を作る開発者として、**紙の比率で見たい**。
  なぜなら、升目のキャンバスでは**詰まり方が分からず**、印刷して初めて
  「思ったより詰まっている」と分かるから。（受け入れ: AC1, AC2）
- US2: 帳票を作る開発者として、**CPI / LPI を変えて見比べたい**。
  なぜなら、15 CPI に落とせば収まるのかを**印刷せずに**知りたいから。（受け入れ: AC3）
- US3: 帳票を作る開発者として、**用紙が何インチになるか知りたい**。
  なぜなら、用紙に収まるかは行数・桁数ではなく**インチ**で決まるから。（受け入れ: AC4）

## スコープ

### 対象
- プレビューモード（紙の比率で描く）と、その切替。
- CPI / LPI の指定（値の集合は原典に従う）。
- 用紙の大きさ（インチ）の表示。
- ソースに `CPI` / `LPI` が書かれていたら**それを既定にする**。

### 対象外
- **1 ページの中で LPI が変わる帳票**（原典は認めているが、行ごとに高さが変わる）。
  **指定が混ざっていることを知らせる**に留める。
- `CHRSIZ`（文字サイズ）・`FONT`・`PAGRTT`（ページの回転）。
- 実際のフォント（プリンタのフォントは再現しない）。
- DSPF（画面に CPI / LPI は無い）。

## 機能要件

- プレビューモードでは、**1 桁の幅 = 1/CPI インチ**、**1 行の高さ = 1/LPI インチ**で描く。
- CPI は原典の値（`10` / `15`）、LPI は原典の値（`4` / `6` / `8` / `9` / `12`）から選ぶ。
- 既定は**ソースに書かれた値**、無ければ `CRTPRTF` の既定（CPI 10 / LPI 6）。
- 用紙の大きさを**インチで**出す（桁数 ÷ CPI × 行数 ÷ LPI）。
- **ソースに複数の CPI / LPI がある**場合はそう知らせる（1 つで描いていることを隠さない）。
- プレビューモードでも**掴んで動かせる**（桁と行の対応は変わらない）。
- **値の集合は原典から生成する**（手で書かない）。

## 非機能要件 / 制約

- **既定は切**（プレビューモードは選んで入る）。等幅の升目は桁を数えるのに要る。
- **ソースは変わらない**（表示だけ）。
- core は `vscode` を import しない。
- **DSPF では出さない**（CPI / LPI は帳票のもの）。
