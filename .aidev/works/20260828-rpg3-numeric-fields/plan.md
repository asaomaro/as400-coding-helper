# 計画: RPG III の残りの数値欄

## 実装方針

**土台 → 変種 → 反映**の順。土台が通らないうちは変種を流さない（前 work の教訓）。

## 作業順序と依存関係

1. 土台づくり（F / F(索引) / O / E / L の通る最小形）（依存: なし）
2. 欄ごとに 対照 / 英字 / 左詰め の 3 件を流す（依存: 1）
3. 食い違ったものはコンパイル・リストで理由を読む（依存: 2）
4. 定義に反映（依存: 3）
5. E / L の分類を足す（依存: 4 — 反映しても届いていないことが 4 で分かるため）
6. テストを足し、**直す前に戻して落ちること**を確かめる（依存: 5）
7. サンプルの桁を直す（依存: 6）

## リスク / 留意点

- **仕掛け側の誤りを実機の規則と読み違える。** 対照を必ず添える。
- 共用機ではないが、作ったオブジェクトは必ず消す。

## テスト方針

- ユニット: `test/unit/rpg3NumericColumns.test.ts` に O/E/L の suite を足す。
  **スキップ欄に `numericOnly` を付けたら落ちる**テストと、
  **`numericOnly` を持つ欄の一覧**を機械で見張るテストを置く。
- 到達性: `classifyRpgSpecKeyword` を直接呼ぶ（lint の結果だけを見ない）。
- 全体: `npm test` / `npm run verify` / `npm run dev:e2e` / CI と同じ桁位置 lint。
