# レビュー

## ラウンド 1（自己レビュー）

### 要件適合

- AC1〜AC6 すべて対応あり。AC5（到達可能）は**実装中に破れていることが判明**し、
  `classifySpec` に `E` / `L` を足して塞いだ。定義を置いただけでは届かない、という
  PJ の教訓がそのまま起きていた。

### 価値適合

- 「実機の通す形を弾かず、通さない形を見逃さない」に対して:
  - 弾かない側 — スキップ欄に `numericOnly` を付けなかった（`A0` が通ることを実測）。
    付けたら落ちるテストも置いた。
  - 見逃さない側 — O/E/L の 9 欄が新たに検査対象になり、**サンプルの桁ずれを実際に検出**した。

### 正確性

- 対照が落ちた 5 件はいずれも仕掛け側の誤りで、直してから読み直した。
  実機の規則として誤って記録したものは無い。
- `QRG2016` の桁の並びは両側から確認（47-52 は落ち、71-72 は通る）。
- `QRG2067`（53 桁＝継続）は否定だけでなく**継続行が通ること**でも確かめた。
- `QRG3049`（L は 2 組）は 3 組目を直接置いて落ちることでも確かめた。

### 規約適合

- 原典の無い RPG III なので JSON を直接編集した（生成スクリプトは存在しない）。
- 実機で確かめた事実は `help` にメッセージ ID つきで書いた。
- 作ったオブジェクトは全部消した（`OBJECT_STATISTICS` で 0 件を確認）。

### 保守性

- `numericOnly` を持つ欄の一覧をテストで固定した（手で数えた一覧は漏れる、の予防）。
