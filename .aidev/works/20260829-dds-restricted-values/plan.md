# 計画: DDS の値集合を原典どおりに直す

## 作業順序と依存関係

1. 子ページを manifest に足して取得（日英）
2. `fetch-origin.mjs` の併合の鍵を直す（1 で発覚）
3. 生成器に 3 つの読み取りを足す（依存: 1）
4. 実機で 38 桁を判定（依存: 3。日英の食い違いが見えてから）
5. 誤植の置き換えを生成器に足す（依存: 4）
6. 回帰テストを足し、後退を戻すと落ちることを確かめる（依存: 5）

## リスク / 留意点

- **R1: 注を広く拾うと関係の無い文字を値にする。** 対象を「データ・タイプ」＋DBCS に絞る。
- **R2: 誤植を消すと正しい値まで失う。** 置き換えにする。
- **R3: 実機が不安定。** SQL のポートが断続的に落ちる。**対照で結果の妥当性を担保**し、
  取れないときは残りを別 work に回す。

## テスト方針

| 見るもの | どこで |
|---|---|
| 値集合（4 欄ぶん） | `test/unit/ddsPositionalValues.test.ts` |
| 桁がルーラーと一致 | `npm run verify` の `verify-dds-prompter` |
| 再生成で差分が出ない | 生成器を 2 度流して `git diff` |
| 実機の判定 | `verify/probe-pos38.mjs`（対照つき） |

**後退を戻すと落ちることを 4 件（生成器の 4 つの直し）で確かめる。**
