# 調査: DDS の定位置欄の値集合

## 調査の問い

- Q1: 表示装置 35 桁の値はどこにあるか。取れるか。
- Q2: 「注」が足す値をどう取るか。
- Q3: 38 桁の「ブランクまたは 0」は何なのか。**日英で食い違わないか。**
- Q4: 値集合は「完全だ」と言えるか（＝`restricted` を立てられるか）。

## 判明した事実

### F1: 35 桁の値は子ページにある。取得できた

親ページ `FIELD-DSPF-rzakcmstdfdt.html`（5,057 バイト）は本文と**リンクだけ**で、
値の一覧は `rzakcvalentries.htm`（「表示装置ファイルの有効な項目」）にある。
manifest に無かったので追加し、日英とも取得した（15,132 / 12,729 バイト、表 1 個）。

中身は**キーボード・シフト 10 種**（ブランク X A N S Y W I D M）＋
**データ・タイプ 4 種**（F L T Z）。

### F2: 「注」が DBCS のデータ・タイプを足している（日英とも）

```
注: データ・タイプ J (専用)、E (択一)、O (混用)、および G (グラフィック) は、
    DBCS を使用する DDS 表示装置ファイルをサポートします。
Note: The data types J (only), E (either), O (open), and G (graphic) support
    DDS display files that use DBCS.
```

**表にも定義リストにも無い。** 物理/論理の 35 桁（`FIELD-PF-ldata.html`）も同じ形。
これで DSPF 35 は 18 値、PF 35 は 14 値になる。

**注は他にもある**（「37 桁目に 0 を指定…」など）ので、広く拾うと関係の無い文字を
値にしてしまう。**「データ・タイプ」で始まり DBCS を含む注だけ**を対象にした。

### F3: 38 桁は**日英で原典が食い違っていた**

| 版 | 原典の記述 |
|---|---|
| ja `FIELD-DSPF-pos38.html` | **「ブランクまたは 0」**（数字のゼロ） |
| en `FIELD-DSPF-pos38.html` | **「Blank or O」**（英字のオー） |

さらに実サンプル `docs/src/CUSTMNT.dspf` は 38 桁目に `O` を使っている。

### F4: 実機の判定 —— **`0` は誤植。`O` が正しい**

`verify/probe-pos38.mjs`（`CRTDSPF`。**対照を先頭と末尾に置き 4/4 一致**）:

| 38 桁 | 作成 | メッセージ |
|---|---|---|
| `B`（対照・通るはず） | ○ | — |
| `Q`（対照・でたらめ） | × | **CPD7410** |
| ブランク | ○ | — |
| **`0`（ja の原典）** | **×** | **CPD7410** ← でたらめな `Q` と同じ |
| **`O`（en の原典）** | **○** | — |
| `I` | ○ | — |
| `H` / `M` / `P` | × | CPD7443 / CPD7436 / CPD5238 ほか |

**メッセージ本文が決め手**（`QCPFMSG`）:

- `CPD7410`「示されたフィールドに文字を使用することはできない」
  = **その値が許されない**。→ `0` は無効。**日本語版の誤植。**
- `CPD7443`「使用目的が **H または P** の場合には、フィールドをブランクにしなければならない」
  = **H と P は認識されている使用目的**。こちらの雛形が長さ・位置を書いていただけ。
- `CPD7436`「**メッセージ・フィールド**の場合には…」= **M も認識されている。**

**「弾かれた ＝ 無効な値」と読んではいけない。** RPG III の継続行で踏んだのと同じ形で、
今回も本文まで読んで初めて H / M / P を集合に残すと判断できた。

→ 38 桁の正しい集合は **ブランク O I B H M P**（＝英語版の記述）。

### F5: `fetch-origin.mjs` の manifest 併合が言語を見ていなかった

`--only=dds` を流したら manifest が 618 行 → 465 行になった。調べると:

- **153 行は同じ `file` の重複**（同じページを 2 回取った記録）。Map に読み戻すと
  1 つに畳まれる。**これは正しい重複除去**で、失われた記録ではない。
- ただし読み戻しの鍵が `category/name` で、**書き込み側は `${cat}${suffix}/${name}`**
  （英語版は `dds-en/…`）。**鍵が食い違い、5 件が余計に畳まれていた。**

鍵を保存先パスから作るようにして直した。**取り直し後も落ちた記録はゼロ**
（466 件 → 468 件。増えたのは新しく取った 2 ページだけ）。

### F6: `restricted` を立てられるのは 38 桁だけ

| 欄 | 値集合の根拠 | `restricted` |
|---|---|---|
| 表示装置 38 桁 | 原典(en) ＋ **実機で全値を判定**（拒否の理由も本文で確認） | **立てられる** |
| 表示装置 35 桁 | 原典（子ページ ＋ 注）。**実機未確認** | 立てられない |
| 物理/論理 35 桁 | 原典（一覧 ＋ 注）。**実機未確認** | 立てられない |
| 物理/論理 38 桁 | 原典。**実機未確認** | 立てられない |
| 印刷装置 35 桁 | 原典。**実機未確認** | 立てられない |

## 影響範囲

- `docs/origin/sources.mjs` / `manifest.yml` / 取得した 2 ページ。
- `docs/origin/fetch-origin.mjs`（鍵の修正）。
- `docs/origin/generate-dds-prompter.mjs`（注 / ブランクまたは X / 子ページ / 誤植）。
- 生成物 `resources/prompter/dds/{ja,en}/DDS-{PF,DSPF}.json`。

## 実現性 / リスク

- **R1: 原典の誤植を直すのは例外扱い。** 根拠（実機の判定）を必ず添える
  （`verify-cl-roundtrip.mjs` の `BROKEN_EXAMPLES` と同じ作法）。
  **消すのではなく置き換える**——消すだけだと日本語版から正しい値 `O` が失われる。
- **R2: 実機が不安定。** SQL のポートが断続的に応答しない。
  残る 4 欄の実機確認は**別 work**にする方が確実。

## spec への申し送り

- **値集合の修復まで**を今回の範囲にする。`restricted` の付与と
  `restricted-value` の既定 ON は、残り 4 欄の実機確認が済んでから（backlog を割る）。
