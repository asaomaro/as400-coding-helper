# 要件: DDS の値集合を修復し、`restricted-value` を有効にできるか判断する

## 背景 / 課題

lint の規則 `restricted-value`（定義済み値以外を弾く）は **既定 OFF** のまま。
理由は**値集合が欠けていて、正しいソースを弾くから**——実測で偽陽性 30 件が出ている。

欠けている原因は生成器の読み落とし（2026-08-28 の下調べ）:

- **物理/論理の 35 桁**: 原典の一覧は `P S B F A H L T Z 5` だが、
  **その直後の「注」**が `J`(専用) `E`(択一) `O`(混用) `G`(図形) を足している。
  生成器が注を読んでいない。
- **表示装置の 38 桁**: 先頭が「**ブランクまたは 0**」で、1 文字の正規表現に合わず
  **ブランクと 0 の両方が落ちている**（定義には `I B H M P` しかない）。
- **表示装置の 35 桁**: 値の一覧が**子ページ**（`rzakcvalentries.htm`）にあり、
  親ページにはリンクしか無い。**manifest に無く、ローカルにも無い。**
- **実機が受けるのに原典に無い値**がある（`CUSTMNT.dspf` の 38 桁 `O`）。

## 目的 / ゴール

**値集合が「完全だと言える」欄を、根拠つきで確定した状態。**
その結果として `restricted-value` を安全に有効にできるなら有効にし、
**できないならその理由を記録して有効にしない。**

**「有効にすること」自体は目的ではない。** 値集合が欠けたまま立てると正しいソースを弾く
——それがこの規則がいま OFF である理由そのもの。

紐づく charter ゴール: `.aidev/charter.md` が無いため該当なし。

## ユーザーストーリー

- US1: **DDS を書く利用者**として、定義済み値の誤りを lint で教えてほしい。
  なぜなら**桁は合っているのに値が違う**誤りは、コンパイルするまで分からないから。（AC4, AC5）
- US2: 同じ利用者として、**正しいソースを弾かれたくない**。
  なぜなら偽陽性が出る検査は切られ、切られた検査は無いのと同じだから。（AC5）
- US3: **この拡張を触る開発者**として、値集合の出所を機械で検査したい。
  なぜなら原典の「注」は生成器が読み落としやすく、**黙って欠ける**から。（AC1, AC2）

## スコープ

### 対象

- 子ページ（`rzakcvalentries.htm` 日英）を manifest に足して取得する。
- 生成器（`generate-dds-prompter.mjs`）に「注」と「ブランクまたは 0」の解析を足す。
- **実機で値集合を裏取りする**（`CUSTMNT.dspf` の 38 桁 `O` を含む）。
- 値集合が完全だと言える欄にだけ `restricted: true` を付ける。
- 検証済みサンプルで偽陽性を数え、0 件なら既定 ON にする。

### 対象外

- **`restricted-value` 以外の lint 規則。**
- CL / RPG の値集合（別系統。CDML 由来で確定済み）。
- **原典に無い値を「知識で」足すこと。** 実機の判定か原典の生テキストだけを根拠にする。

## 機能要件

- 値集合は**原典の生テキスト**から機械的に取る。手で JSON を直さない（AGENTS.md）。
- 原典と実機が食い違ったら**実機を正とする**（AGENTS.md）。
- 完全だと言えない欄には `restricted` を立てない（**部分的に有効にしない**）。

## 非機能要件 / 制約

- 原典の取得は `fetch-origin.mjs` の既存経路を使う。**手で HTML を保存しない。**
- 生成物は `verify-*.mjs` が原典と突き合わせる（差分ゼロが受け入れ条件）。

## 完了条件 (受け入れ基準)

- [ ] AC1: 子ページが manifest にあり、日英とも取得できている。
- [ ] AC2: 生成器が「注」と「ブランクまたは 0」を読み、**再生成しても差分が出ない**。
- [ ] AC3: 実機で値集合を裏取りし、**原典に無いが実機が受ける値**が特定されている
      （`CUSTMNT.dspf` の 38 桁 `O` の扱いを含む）。**対照つき。**
- [ ] AC4: `restricted: true` を立てた欄は、**なぜ完全だと言えるか**が記録されている。
      立てなかった欄も、**なぜ言えないか**が記録されている。
- [ ] AC5: 検証済みサンプル 9 件で**偽陽性 0 件**なら既定 ON。1 件でも出るなら
      **既定 OFF のままにして理由を残す**。
- [ ] AC6: `npm test` / `npm run verify` が緑。
