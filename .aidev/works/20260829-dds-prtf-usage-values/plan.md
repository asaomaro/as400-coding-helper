# 計画: 印刷装置 38 桁（使用目的）の値集合を入れる

## 作業順序と依存関係

1. **T1** 生成器に `<li><samp>` の読み方と「またはブランク」を足す（依存: なし）
2. **T2** 実機で 38 桁の全 37 通りを判定（依存: なし。T1 と並行可）
3. **T3** `PROVEN_COMPLETE` を決めて再生成（依存: T1・T2）
4. **T4** テストと検査（依存: T3）
5. **T5** サンプルで偽陽性 0・往復・e2e（依存: T4）

## リスク / 留意点

| リスク | 対応 |
|---|---|
| `<li><samp>` が他の欄を汚す | 原典全件走査で日英 2 ページのみと確認済み。再生成の差分でも確かめる |
| `P` は位置欄を持てない（原典）| 雛形が位置を書くと `P` の行が別の理由で落ちる。**判定は 38 桁の印だけ**を見るので影響しない |

| スプール | 消さない（spec D4） |

## テスト方針

- 値集合（ブランク / `O` / `P`）と `inputType: dropdown` を固定。ja / en 一致。
- `restricted: true` にしたら、実機が弾いた値での発火をテストに固定。
- **抽出を戻すと落ちること**を確かめる。
- `docs/src` 全サンプルで指摘 0。往復検証。e2e で `<select>` になること。
