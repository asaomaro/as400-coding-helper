# 要件: 印刷装置 38 桁（使用目的）の値集合を入れる

## 背景 / 課題

印刷装置ファイルの 38 桁目（使用目的）は、原典が有効な値を挙げているのに
**定義の選択肢が空**で `inputType: "text"` になっている。

原典（`FIELD-PRTF-prtuse.html`）の書き方が `<li><samp>O</samp> またはブランク: 出力専用</li>`
という形で、生成器が読む 2 通り（定義リスト `<dt>/<dd>` と表）のどちらでもないため落ちている。

結果として、この欄だけ**候補が一つも出ない自由入力**になっており、
利用者は `O` / `P` を知っていないと書けない。

出所: `.aidev/backlog/workflow.md`（`20260829-dds-restricted-expand` の `decisions.md` D4）。

## 目的 / ゴール

**印刷装置 38 桁で、原典が挙げる値が候補として見えている状態。**
実機の受理集合と一致していれば無効な値が止まり、一致しなければ候補のまま据え置かれている状態。

紐づく charter ゴール: 「プロンプター定義の拡充」。

## ユーザーストーリー

- US1: **帳票 DDS を書く開発者**として、38 桁目で F4 を押したら選べる値が見えてほしい。
  なぜなら、いまは**候補がゼロ**で、原典を読むか実機に叱られるまで `O` / `P` を知る手段が無いから。
  （受け入れ: AC1, AC3, AC4）

## スコープ

### 対象
- `<li><samp>X</samp> 意味` の形から値を採る（原典の 3 つ目の書き方）。
- 「またはブランク」/「or blank」が**ブランクも有効**と言っていることを読む。
- 実機で全 37 通りを試し、一致すれば `restricted: true`。

### 対象外
- 他の欄の見直し。今回は印刷装置 38 桁だけ。
- `restricted` の仕組み自体（前作業で入っている）。
