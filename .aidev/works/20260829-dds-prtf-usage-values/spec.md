# 仕様: 印刷装置 38 桁（使用目的）の値集合を入れる

## 設計方針

### D1: `<li><samp>X</samp> 意味` を 3 つ目の読み方として足す

原典の値の並べ方は既に 2 通りある（定義リスト `<dt>/<dd>` ＝ 物理論理・表示装置、
表 ＝ 印刷装置のデータ・タイプ）。ここは 3 つ目——**箇条書きの項目**。

```html
<li><samp class="ph tt">O</samp> またはブランク: 出力専用</li>
<li><samp class="ph tt">P</samp>: プログラム - システム間 (特殊な出力フィールド)</li>
```

**`<li>` が `<samp>` で始まり、その中身が英数字 1 文字**のときだけ採る。
同じページの他の `<li>`（「位置は無効です。」等の散文）は `<samp>` で始まらないので当たらない。

**巻き込まないことは原典の全件走査で裏を取った**——`dds` と `dds-en` の全 HTML で
この形を持つのは**このページの日英 2 件だけ**。

### D2: 「またはブランク」はブランクの意味として読む

`O またはブランク: 出力専用` / `O or blank: Output only` は、
**`O` とブランクが同じ意味**だと言っている。既存の `addOption` は
「ブランクまたは 0」という**逆順**の形を既に扱っている（表示装置 38 桁）。
ここはその鏡像なので、同じ関数の中で扱う。

代替案（`BLANK_FROM_PROSE` に足す）を退けた理由: あちらは**本文にしか無い**ブランクのための
逃げ道で、根拠を手で書き写す。ここは**値の一覧そのものに書いてある**ので、読めばよい。

### D3: `restricted` は実機の網羅で決める

前作業と同じ基準——全 37 通りを流し、受理集合が定義と完全一致したときだけ `true`。
判定は「メッセージ番号 ＋ 印が指す桁」（`CPD7419` / `CPD7410` が無効、
`CPD7408` / `CPD7635` / `CPD7914` は受理）。

**解析器は前作業のものを再利用する**（`20260829-dds-restricted-expand/verify/parse-listing.mjs`）。
写しを作ると、ページ境界と 2 部構成の罠を二度踏む。

### D4: 実機スクリプトは `DLTSPLF` を持たない

前作業の決定（`decisions.md` D1）を引き継ぐ。作ったスプールは名前を記録して残す。
