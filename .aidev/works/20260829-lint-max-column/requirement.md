# 要件: lint の桁上限を利用者のソース PF に合わせられるようにする

## 背景 / 課題

固定長ソースの行長検査（`line-length`）は上限を **100 桁に固定**している
（`vscode-extension/src/lint/rules/lineLength.ts` の `MAX_COLUMN = 100`）。
原典が「仕様書の注記以外は 7-80 桁目、注記部分は 81-100 桁目」と規定しているためで、
**100 桁自体は原典どおり**である。

問題は**実機のソース物理ファイルのレコード長が 1 つではない**こと。pub400 で調べた 5 件は
**レコード長 92（データ 80 桁）が 3 件・112（データ 100 桁）が 2 件**で混在していた
（`20260828-dds-line-width-columns` の `decisions.md` D1）。
レコード長 92 のファイルでは **81 桁目以降が実機に入れた時点で切り捨てられる**が、
いまの lint は 100 桁まで許すので**指摘が出ない**。

切り捨ては実測で確認済み（IBM i 7.3）。全角 30 文字の定数を持つ行は JS では 76 文字だが、
メンバーに入れて読み戻すと **71 文字に欠けていた**。桁は実機の桁（SO/SI ＋ 全角 2 桁）で
数える必要があり、**JS の文字数では気付けない**。

そして **ローカルのソースからはレコード長が分からない**。ファイルはただのテキストで、
どのソース PF に入るかはコンパイル時に決まる。つまり lint 自身には判定材料が無い。

## 目的 / ゴール

利用者が**自分の使うソース PF のレコード長に合わせて桁上限を選べ**、
レコード長 92 のファイルでも**実機に入れる前に切り捨てを検知できる**状態。
既定を変えないので、いまの利用者の見え方は変わらない。

紐づく charter ゴール: 第 4 の柱「**DDS（DSPF/PRTF）の視覚的な確認と編集**」の
「レイアウト診断（lint）」。行長検査は RPG 固定長にも効くため「固定長編集支援」にもかかる。

## ユーザーストーリー

- **US1**: レコード長 92 のソース PF を使う開発者として、桁上限を 80 桁に設定したい。
  なぜなら、いま書いている行が実機に入れた時点で欠けることを、
  **コンパイルまで待たずに編集中に**知りたいから。（受け入れ: AC1, AC2, AC3）
- **US2**: CI で `lint` を回す開発者として、**エディタと同じ上限を CLI にも渡したい**。
  なぜなら、上限が片方だけ変わると「エディタでは出ないが CI で落ちる」
  （逆もある）という食い違いが生まれ、どちらが正しいか分からなくなるから。（受け入れ: AC4）
- **US3**: 既存の利用者として、**設定しなければ今までどおり**であってほしい。
  なぜなら、上限が黙って狭まると正しいソースが一斉に赤くなるから。（受け入れ: AC5）

## スコープ

### 対象

- 桁上限を利用者が選べるようにする（VSCode 設定 ＋ lint CLI の両方）。
- lint core（`src/lint/`）に上限を渡す配線。**vscode 非依存は保つ**。
- 指摘メッセージが、固定の 100 ではなく**実際に適用された上限**を言うこと。

### 対象外

- **実機に接続してレコード長を取得し自動判定すること**。判断済みで不採用
  （lint が実機接続に依存すると、`src/lint/` を vscode 非依存・オフラインで作った設計が崩れる）。
- `line-length` 以外の規則の桁依存の見直し。
- ソース PF のレコード長そのものを扱う機能（作成・変更・照会）。

## 機能要件

- 桁上限を設定できる。**既定は 100**（現状の振る舞い）。
- VSCode 設定と lint CLI の**両方**から指定でき、同じ値なら同じ結果になる。
- 上限を超えた行の指摘メッセージに、**適用中の上限**が出る。
- 桁の数え方は変えない（`printWidth`。実機の桁で数え、下線の位置は JS の添字）。

## 非機能要件 / 制約

- **既存挙動を壊さない**。設定しなければ現在と 1 件も違わない指摘になる。
- `src/lint/` は **vscode にも実機にも依存しない**ままにする（型は `LintOptions` 経由で渡す）。
- エディタと CLI で**同じロジックが動く**という現在の性質を保つ。
- `tsc` 通過・単体テスト通過。

## 完了条件 (受け入れ基準)

- [ ] **AC1**: 上限を 80 に設定すると、81-100 桁の行が `line-length` で指摘される。
- [ ] **AC2**: 上限を 80 に設定しても、80 桁以内の行は指摘されない。
- [ ] **AC3**: 指摘メッセージに**適用された上限**が出る（80 のとき「100 桁まで」と言わない）。
- [ ] **AC4**: lint CLI から同じ上限を指定でき、同じソースに対して VSCode 設定と**同じ指摘**になる。
- [ ] **AC5**: 設定しない場合、上限は 100 のままで**既存のテストが 1 件も変わらず通る**。
- [ ] **AC6**: 桁は実機の桁で数える（全角・SO/SI を含む行で、JS の文字数ではなく `printWidth` で判定される）。
- [ ] **AC7**: `src/lint/` が vscode を import していない（既存の性質を壊していない）。

## 未確定事項 / 確認したいこと

- **上限の値域を「80 / 100 の 2 択」にするか、任意の数値を許すか**。
  決定（2026-08-29）は「80 / 100 から選べる」だが、実機のソース PF のレコード長は
  他の値も取り得る。**spec で原典・実機の材料を確認して決める**
  （2 択にすると他のレコード長で使えず、任意にすると原典に無い値を許すことになる）。
