# 要件: DDS デザイナの表示切替（SO/SI・属性バイト・グリッド・他様式・ズーム）

## 背景 / 課題

- 確定デザイン C1（`docs/design/dds-designer/`）のツールバーには
  **選択 / フィールド / 定数 ｜ SO/SI 表示・属性バイト・グリッド・スナップ・他様式・5250 配色 ｜ ズーム**
  が並ぶ。実装済みなのは「フィールドを置く / 定数を置く」だけで、**表示の切替が 1 つも無い**。
- **SO/SI が見えない。** DDS の DBCS は SO/SI が桁を消費するが、いまのキャンバスは
  桁を正しく空けるだけで**そこに何があるか分からない**。C1 は `{ 社 員 番 号 }` と可視化していた。
  「なぜこの定数は 10 桁なのか」が画面で説明できない。
- **属性バイトが常に出ている。** 淡いマーカーを常時描いており、**項目が密な画面では邪魔**になる。
  必要なときだけ出したい。
- **どの様式を見ているのか分からない。** 複数様式の DDS ではキャンバスに**全様式が重なって**出る。
  `CUSTMNT.dspf` は HEADER と DETAIL の 2 様式で、いま画面上では区別が付かない。
- **拡大できない。** セル幅は実測値のままで、細かい桁を確認したいときに拡大する手段が無い。
  ただし **VSCode のエディタズームと二重に効く**という未解決がある（C1 の未解決 #5）。

## 目的 / ゴール

達成したい状態:

- **桁の内訳が画面で説明できる状態**——SO/SI が見え、選択中の項目について
  「SO 1 + 全角 n × 2 + SI 1 = N 桁」が読める。
- **見たいものだけが見える状態**——属性バイト・グリッド・他様式を必要に応じて出し入れできる。
- **アクティブな様式が一目で分かる状態**——他様式は淡く出し、編集対象と区別できる。
- **細部を拡大して確かめられる状態**。かつ **ホストのズームと衝突しない**。

紐づく charter ゴール: 「DDS（DSPF/PRTF）の視覚的な確認と編集」。
確定デザイン: `docs/design/dds-designer/README.md`（C1）。

## ユーザーストーリー

- **US1**: AS400 開発者として、**SO/SI を見えるようにしたい**。
  なぜなら **DBCS の桁数が合わない理由**（SO/SI が 1 桁ずつ食う）が、見えないと理解できず、
  実機で桁がずれて初めて気付くから。（受け入れ: AC1, AC2）
- **US2**: 開発者として、**属性バイトやグリッドを消したい**。
  なぜなら項目が密な画面では**装飾が本体を隠す**から。（受け入れ: AC3）
- **US3**: 複数様式を保守する開発者として、**編集中の様式だけをはっきり見たい**。
  なぜなら**全様式が重なった絵**からは、どれを触っているのか判断できないから。（受け入れ: AC4）
- **US4**: 開発者として、**拡大して桁を確かめたい**。
  なぜなら 6.5px のセルでは**属性バイトの 1 桁**が見分けられないから。
  ただし **VSCode のズームと二重に効いて実寸が信用できなくなるのは困る**。（受け入れ: AC5, AC6）

## スコープ

### 対象

- **SO/SI 表示**の切替（`{` `}` を桁を消費する位置に出す）。
- **桁勘定の表示**——選択中の定数について内訳（SO・全角・半角・SI）と合計桁数。
- **属性バイト表示**の切替（いまは常時表示）。
- **グリッド表示**の切替。
- **他様式の淡色表示**の切替（アクティブ様式＝選択中の項目が属する様式）。
- **ズーム**（段階指定。**キーバインドは張らない**）。
- 切替の状態は**セッション内で保つ**（項目を選び直しても戻らない）。

### 対象外（後続 work）

- **5250 配色**（C1 のツールバーにある実機風の配色）。
- **スナップの切替**——いまのドラッグは**常にセルに吸着**しており、自由配置の概念が無い。
  切替を作っても**片方が存在しない**ので、必要になってから。
- **条件標識**（core に条件の解決が無い）。
- **表示状態の永続化**（再起動をまたいで覚える）。
- **キーワード編集**（L3）。

## 機能要件

1. SO/SI を `{` `}` として、**桁を消費する位置**に表示できる。切替で消せる。
2. 選択中の定数について、**桁の内訳と合計**が読める（SO/全角/半角/SI の別）。
3. 属性バイト・グリッド・他様式の淡色表示を、**それぞれ独立に**切り替えられる。
4. ズームを段階で選べ、**キャンバスの桁位置がズーム後も正しい**（ルーラー・行番号・項目が一致する）。
5. **キーボードショートカットを張らない**（ホストのズームと取り合わない）。
6. 切替の状態はセッション内で保たれ、**再描画で戻らない**。
7. VSCode と単独起動で**同じ切替**が使える。

## 非機能要件 / 制約

- **判定を増やさない**。SO/SI の位置は core が既に持っている情報（区切り）から出す。
  **UI が文字を見て「これは全角か」を判断しない。**
- **既存挙動を壊さない**——編集・選択・診断・プロパティ・ツリーは従来どおり。
  `npm test` と `npm run verify` を通す。
- **ズームで桁がずれない**。セル寸法は実測値 × 倍率で、**ルーラーと項目が同じ値を使う**。
- UI は `vscode` に触らない（既存の分離を維持）。

## 完了条件 (受け入れ基準)

- [ ] **AC1**: SO/SI 表示を入れると、DBCS 定数の**前後に `{` `}` が桁を消費する位置**に出る。
      切ると消える。**桁位置は変わらない**（表示の有無で項目の位置がずれない）。
- [ ] **AC2**: 定数を選ぶと**桁の内訳**が出る（例: `SO 1 + 全角 4×2 + SI 1 = 10 桁`）。
      合計は core の計算（`printWidth`）と一致する。
- [ ] **AC3**: 属性バイト・グリッドをそれぞれ切り替えられ、切った状態が保たれる。
- [ ] **AC4**: 他様式の淡色表示を入れると、**選択中の項目が属する様式以外**が淡く出る。
      切ると全様式が同じ濃さで出る（現状の挙動）。
- [ ] **AC5**: ズームを変えると**セル・ルーラー・行番号・項目がすべて同じ倍率**で拡大縮小し、
      桁位置が一致する。
- [ ] **AC6**: ズームに**キーボードショートカットを割り当てない**（ホストのズームと取り合わない）。
- [ ] **AC7**: 切替とズームの状態は、選択の変更・編集の適用（再描画）で**戻らない**。
- [ ] **AC8**: 既存挙動の非後退——編集・選択・プロパティ・ツリー・診断が従来どおり。
      `npm test` / `npm run verify` / 桁位置 lint が通る。
- [ ] **AC9**: VSCode と単独起動の**両方**で同じ切替が使える（単独起動で実操作を e2e で確認）。

## 相互作用の受け入れ基準

- [ ] **AC-I1 状態が見える**: 入っている切替はボタンの見た目で分かる（押下状態）。
- [ ] **AC-I2 即時反映**: 切り替えるとその場でキャンバスが変わる（保存や再読込が要らない）。
- [ ] **AC-I3 キーボードだけで完結**: ツールバーのボタンは `Tab` で辿れ、`Enter`/`Space` で押せる。
- [ ] **AC-I4 既存の操作を妨げない**: 切替の操作でキャンバスの選択が外れない。
- [ ] **AC-I5 ズームの安全性**: ズームしても**掴んだ項目が指した桁に入る**（座標変換が倍率に追随する）。

## 未確定事項 / 確認したいこと

- ズームの段階（C1 は 90 / 100 / 125%）。それ以上の拡大が要るか。
- 他様式の「淡さ」の度合い（読めなくなると意味が無い）。
- SO/SI の記号（`{` `}` は既存の SOSI 表示機能と同じ流儀。それに揃える）。
