# レビュー: キーワード行の条件を編集する

## ラウンド 1（2026-08-27）

### 要件適合
- AC1 ✓ 付け外し・AND / OR / `N` とも。書き戻しは項目の条件と同じ経路。
- AC2 ✓ 項目の行は動かない（OR で行が増えるときも。テストで固定）。
- AC3 ✓ 条件の有無によらず代表行以外の群を全部出す（D3）。
- AC4 ✓ 代表行を指したら `keyword-line-not-found`。
- AC5 ✓ `validateConditionShape` を項目と共有。
- AC6 ✓ 書き換えた条件が見え方に効くことをテストで見ている
  （`77` に付け替えると `30` では倒れなくなる）。

### 価値適合
狙いは「見て確かめた条件をその場で書ける」の**最後の穴**を埋めること。
読む側（前々 work）→ 項目の条件を書く（前 work）→ キーワードの条件を書く（本 work）で、
条件まわりは読み書きとも揃った。

**条件が無い行にも入力欄を出した**（D3）のが実質的な差——条件つきだけを出していたら、
新しく条件を足す手段が無いままだった。

### 正確性
- 置き換え範囲を群の `sourceLines` に限り、**継続行を巻き込まない**。
- 注記行が挟まる形は断る（項目の条件と同じ扱い）。
- 選択の付け替えを**あえて足していない**（D4）。効かないコードを残さない。

### 規約適合
- 新しい桁の規則を書いていない（`writeBackCondition` を使い回す）。
- 短い形の記法は項目の条件と同じ。2 つ目の記法を作らない。
- `parseEdit` に足した。**足し忘れると画面が「適用中…」で止まる**ので、
  配線を単体テストで固定した（外すと落ちることを確認済み）。

### 保守性
検証は「形」（上限・標識）と「宛先」（引き当て・連続）に分かれており、
形の方は項目とキーワードで共有している。

### 指摘
must 0 / should 0 / nit 0。

**残っている穴**: `EDTCDE` のように**条件付けできないキーワード**に条件を付けても
デザイナは止めない（実機で `CPF7311`）。網羅には原典からの生成が要るので backlog に起票済み。
