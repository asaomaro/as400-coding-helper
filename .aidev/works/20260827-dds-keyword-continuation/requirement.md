# 要件: キーワード欄の継続行を実機どおりに読む

## 背景 / 課題

DDS のキーワード欄（45-80 桁）は 36 桁しかないので、収まらない値は**次の行へ継続**する。
本 PJ の `toLogicalUnits` は継続行を**空白 1 つで連結**しているだけで、継続の規則を知らない。

実機（IBM i 7.3 / SR-OSAKA）で確かめたところ、**2 つの壊れ方**がある。

1. **項目がキャンバスから丸ごと消える。** 継続元の行は引用符が閉じていないため
   `readConstant` が `undefined` を返し、名前も空なので**項目と認識されない**。
   結果、直前の様式のキーワードとして吸収され、**画面にもツリーにも出ない**。
   実機で通る DSPF（5 個の定数）を読ませたところ、**描かれたのは 1 個だけ**だった。
2. **値が壊れる。** `-` / `+` は継続記号で、結合後は消える。いまは
   `COLOR(-` ＋ `RED)` が `COLOR(- RED)` になる（記号も余分な空白も残る）。

継続はまれな書き方ではない。長い定数・`ERRMSG` / `EDTWRD` / `DFT` の長いリテラルで普通に使う。

紐づく charter ゴール: **DDS（DSPF/PRTF）の視覚的な確認と編集**を第 4 の柱として加える。

## 目的 / ゴール

**継続行を含む DSPF でも、実機と同じ値・同じ桁で読めている状態**。
実機のコンパイラが解決した結果と、本 PJ が読む値が一致している。

## ユーザーストーリー

- US1: DSPF を直す開発者として、**継続行を含む項目もデザイナに出てほしい**。
  なぜなら、いまは**画面にもツリーにも現れず**、その項目だけテキストエディタに戻るしかないから。
  （受け入れ: AC1, AC4）
- US2: DSPF を読む開発者として、**継続記号が値に混ざらないでほしい**。
  なぜなら `COLOR(- RED)` のような値は実機のどこにも存在せず、
  **プロパティの表示も桁勘定も誤る**から。（受け入れ: AC2, AC3）
- US3: DSPF を直す開発者として、**書き換えられない形は書き換えないでほしい**。
  なぜなら、継続行にまたがるリテラルを片方の行だけ書き換えると**黙って壊れる**から。
  （受け入れ: AC6）

## スコープ

### 対象
- 継続の判定と結合（`toLogicalUnits` の前段）。
- 継続元の行を**項目として認識する**（消さない）。
- 継続行にまたがる項目の**キーワード欄の書き換えを拒否**する。

### 対象外
- **継続行の生成**（長いキーワードを書き出すときに `-` で折る）。
  読めるようにするのが先。書く側は backlog に残す。
- PRTF / PF・LF の継続（同じ規則のはずだが、確かめたのは DSPF だけ）。
- lint に「継続が壊れている」規則を足すこと。

## 機能要件

- 機能欄の**最後の非空白が `-`** なら、`-` を捨てて次行の**45 桁目ちょうど**から続ける（空白を保つ）。
- 最後の非空白が **`+`** なら、`+` を捨てて次行の**最初の非空白**から続ける。
- どちらでもなく**引用符が閉じていない**なら、**空白 1 つ**を挟んで次行の最初の非空白から続ける。
- 3 行以上の連鎖に対応する。
- 継続でない「キーワードだけの行」は**従来どおり空白 1 つで連結**する（`OVERLAY` 等）。
- 継続に使われた行は**その項目の一部**として扱う（削除時にまとめて消える）。

## 非機能要件 / 制約

- 判定の根拠は**実機**（原典のスナップショットに継続規則のページが無い）。
  AGENTS.md「原典と実機が食い違ったら、実機のパーサーに判定させる」に従い、
  **実験と結果を再現できる形で記録する**。
- **既存挙動を壊さない**: 継続を含まないソースの読み取り結果は 1 ビットも変えない。
- core は `vscode` を import しない。

## 完了条件 (受け入れ基準)

- [ ] AC1: 継続元の行が**項目として認識される**（キャンバスとツリーに出る）。
- [ ] AC2: `-` 継続は**空白を挟まず**結合する（`COLOR(-` ＋ `RED)` → `COLOR(RED)`）。
- [ ] AC3: `+` 継続は継続行の**先頭の空白を捨てて**結合する（`'ABC+` ＋ `   DEF'` → `ABCDEF`）。
- [ ] AC4: 継続記号なし（引用符が閉じない）は**空白 1 つ**を挟む
      （`'ABC` ＋ `   DEF'` → `ABC DEF`）。
- [ ] AC5: 3 行以上の連鎖が結合できる（`'AAA-` / `BBB-` / `CCC'` → `AAABBBCCC`）。
- [ ] AC6: 継続行にまたがる項目のキーワード欄（定数の文字列）の書き換えは**拒否**され、
      理由が出る。位置・長さの変更は**従来どおりできる**。
- [ ] AC7: 継続を含まない既存のサンプルの読み取り結果が、この変更の前と一致する。
- [ ] AC8: 実機で作った DSPF の**コンパイラが解決した値**と、本 PJ が読む値が一致する。
