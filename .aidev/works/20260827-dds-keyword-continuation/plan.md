# 計画: キーワード欄の継続行を実機どおりに読む

## 実装方針

**規則 → 結線 → 拒否 → 検証**の順。規則（`joinContinuations`）は純関数なので、
`toLogicalUnits` に繋ぐ前に実機の実測値で固められる。

## 作業順序と依存関係

1. `joinContinuations`（判定と結合）— 依存なし
2. `toLogicalUnits` を結合結果の上で動かす — 依存: 1
3. 継続にまたがるキーワード欄の書き換えを拒否 — 依存: 2
4. 単体テスト（実機の実測値を期待値にする）— 依存: 1-3
5. 実機との突き合わせスクリプトを work に残す — 依存: 4
6. 記録（backlog・PJ skill の未確認事項の解消）— 依存: 全部

## リスク / 留意点

- **既存の読み取りを変えない**のが最大の制約。継続でない「キーワードだけの行」の
  空白 1 つ連結は**そのまま**。既存の 593 件が回帰の網。
- **`sourceLines` に継続行を入れ忘れると削除が壊れる**（継続行だけ残る）。
- **PRTF / PF・LF も同じ経路を通る**。実機で確かめたのは DSPF だけなので、
  その旨を記録に残す（勝手に「確認済み」と書かない）。

## テスト方針

- **単体**（`test/unit/ddsContinuation.test.ts` 新規）:
  - spec の表（`-` / `+` / 記号なし / 連鎖 / リテラルの外）。**期待値は実機の実測値**。
  - 継続でない行が従来どおりであること。
  - 注記行が挟まったら継続が切れること。
  - 継続記号があるのに次行が無いとき、記号を捨てないこと。
  - 継続元の行が**項目として認識される**こと（`buildDspfRenderModel` で件数を見る）。
  - `sourceLines` に継続行が入ること（削除がまとめて消えること）。
  - 継続にまたがる項目のキーワード欄の書き換えが拒否され、**位置の変更は通る**こと。
- **回帰**: `npm test` / `npm run verify` / lint / GUI e2e。
- **実機**: `verify/` のスクリプトで、実機の Expanded Source と本 PJ の読み取りを突き合わせる。
