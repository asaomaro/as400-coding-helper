# 決定記録

## D1: 継続の規則は**実機のコンパイラに判定させた**

- 背景: ローカルの原典スナップショット（`docs/origin/dds/`）に継続規則のページが無い。
  記憶で書くと、`+` と `-` の違い・挿入される空白の数を取り違える。
- 決定: IBM i 7.3（`SR-OSAKA` / `ASAOLIB`）で**実際にコンパイルし、
  リストの `Expanded Source` に出る「解決後の定数」を期待値にした**。
- 理由 / 代替案: AGENTS.md「原典と実機が食い違ったら、実機のパーサーに判定させる」
  「判定は副作用の無い形で行う」に従う。原典を追加取得する案もあったが、
  **実機の答えのほうが強い**（原典は版によって書き方が変わるが、コンパイラが正）。
  取得は `QTEMP` へのコンパイルで、オブジェクトを残していない。
- 影響: 単体テストの期待値がすべて実測値。実機との突き合わせは
  `verify/verify-continuation.mjs` で**いつでも再現できる**。

## D2: 結合は**分類より先**に行う

- 背景: 継続元の行は引用符が閉じていないので `readConstant` が読めず、名前欄も空。
  分類を先にすると「キーワードだけの行」と誤判定され、**項目が丸ごと消える**。
- 決定: `joinContinuations` を `toLogicalUnits` の前段に置き、
  **分類の規則そのものは変えない**。
- 理由 / 代替案: 分類の条件に「位置欄が埋まっていれば項目」を足す案もあったが、
  それは**別の規則を 1 つ増やす**ことになり、継続の本質（値がまだ完成していない）を表さない。
  結合してしまえば、継続元の行は**普通の定数行**になる。
- 影響: `dspfLayout` / `dspfOutline` / `dspfRenderModel` / `prtfLayout` / lint が**無変更で直った**。

## D3: 継続の判定は 45-80 桁の中だけで行う

- 背景: `keywordAreaOf` は 45 桁目から**行末まで**を返す（80 桁で切っていない）。
- 決定: 継続の判定と結合は `functionsArea`（45-80）で行う。`keywordAreaOf` は**変えない**。
- 理由: 実機は 81 桁目以降を読まない（80 桁を超えた行は `CPD7508`
  「閉じ引用符が無い」で落ちた）。行全体で判定すると、はみ出した文字を継続記号と誤読する。
  `keywordAreaOf` を変えなかったのは、**書き戻し側が同じ関数を使っている**ため——
  この work の範囲を超える。現在のサンプル・テストに 80 桁を超える行は 1 本も無く、
  挙動は変わらない。
- 影響: `keywordAreaOf` の 80 桁での打ち切りは backlog へ（今は差が出ない）。

## D4: 継続にまたがるキーワード欄は**書き換えを拒否**する

- 背景: 継続でつながった値を代表行だけ書き換えると、**継続行が取り残されて壊れる**
  （閉じない引用符・宙に浮いた括弧が残る）。
- 決定: `setAttributes` の `text`（定数の文字列）だけを拒否する。
  拒否コード `keyword-continuation`。**位置・長さ・型・用途は拒否しない。**
- 理由 / 代替案: 折り直して書き出す案は、この work の目的（読めるようにする）を超える。
  「書けないものだけ拒否」の方針どおり、**理由を出して止める**。
  なお直す前は `replaceLeadingConstant` が黙って何もしていなかった
  （拒否も表示も無し）ので、**黙って効かない**より良くなっている。
- 影響: 判定は `startsContinuation(unit.line)`——**代表行自身が次行へ続くか**で見る。
  `unit.sourceLines` の長さで見ると、`OVERLAY` を別行に書いただけの普通の項目まで拒否する
  （そちらは代表行の欄を書き換えても壊れない）。

## D5: 継続記号があるのに次の行が無ければ、記号を捨てない

- 背景: ファイルの末尾や注記行の直前で `-` で終わる行がありうる。
- 決定: 継続しない。**`-` はそのまま値に残す**。
- 理由: 捨てると「書いたのに画面から消えた」になり、原因が掴めない。
  残しておけば、画面に `-` が見えて**書き間違いだと分かる**。
