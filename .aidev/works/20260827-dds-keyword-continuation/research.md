# 調査: キーワード欄の継続規則（実機で判定）

## 調査の問い

- Q1: 機能欄（45-80 桁）に収まらない値は、どう次の行へ続けるのか。
- Q2: `+` と `-` で何が違うのか。継続記号なしでも続くのか。
- Q3: リテラルの外（キーワード名・括弧の途中）でも切れるのか。3 行以上は？
- Q4: DBCS を含むリテラルも継続できるのか。
- Q5: いまの本 PJ は継続行をどう読んでいるのか。

## 判定の手段（原典が無いので実機に判定させた）

ローカルの原典スナップショット（`docs/origin/dds/`）に**継続規則のページが無い**。
AGENTS.md「原典と実機が食い違ったら、実機のパーサーに判定させる」「判定は副作用の無い形で行う」に従い、
**実機のコンパイラに判定させた**。

- 実機: `SR-OSAKA`（IBM i **7.3** / 5770SS1 V7R3M0）。ライブラリ `ASAOLIB`（利用者の許可済み）。
- 経路: `ts5250` の `@ts5250/hostserver`（コマンドサーバー / IFS / SQL）と
  `@ts5250/tn5250`（5250 セッション）。5250 の装置は既存の `ASA1`-`ASA4`
  （**自動構成は許可されていない**——新しい装置名は `8940` で拒否される）。
- **観測の主力は「コンパイル・リストの Expanded Source」**。`CRTDSPF` の
  リストには**解決後の定数**が長さつきで出る（例 `3 12'ABC DEF'   7`）。
  画面を出すより速く、値がそのまま読める。
  取り出しは `CPYSPLF FILE(<member>) TOFILE(*TOSTMF) TOSTMF('…')` →
  IFS 読み出し → **CCSID 5035 で復号**（ジョブの CCSID で書かれ、行末も EBCDIC の NL(0x15) なので
  UTF-8 として読むと 1 行に見える）。
- 画面での確認は `DCLF` ＋ `SNDRCVF` だけの CL ドライバを作って `CALL` し、
  5250 の画面バッファを読んだ。

## 判明した事実

### F1: 継続は 3 通りあり、結合の仕方が違う（実機の Expanded Source で確認）

| 書き方 | 結合の規則 | 実測 |
|---|---|---|
| 機能欄の**最後の非空白が `-`** | `-` を捨て、**次行の 45 桁目ちょうど**から続ける（空白も保つ） | `'ABC-` ＋ `   DEF'` → `ABC   DEF` |
| 最後の非空白が **`+`** | `+` を捨て、次行の**最初の非空白**から続ける | `'ABC+` ＋ `   DEF'` → `ABCDEF` |
| どちらでもなく**引用符が閉じていない** | **空白 1 つ**を挟み、次行の最初の非空白から続ける | `'ABC` ＋ (50 桁目から)`DEF'` → `ABC DEF`（長さ 7） |

行末に空白が何桁あっても**入る空白は 1 つだけ**（リテラルが 55 桁目で終わり、
継続行が 50 桁目から始まる形で長さ 7 ＝ 3+1+3 を確認）。

### F2: リテラルの外でも切れる。3 行以上も連鎖する

- `COLOR(-` ＋ `RED)` → Expanded Source は `'XYZ' COLOR(RED)`。**括弧の途中で切れる。**
- `'AAA-` / `BBB-` / `CCC'` → `'AAABBBCCC'`（長さ 9）。**連鎖可。**

### F3: DBCS も `-` で継続でき、結合後は 1 つの連なりになる

`'顧客-` ＋ `保守'` を実機で表示させると、`'顧客保守'` を継続せずに書いた場合と
**画面上の桁がまったく同じ**になる（下表）。ソース側は行ごとに SO/SI が入るが、
コンパイラが結合して 1 つの DBCS 連なりにする。

### F4: 描画モデルの DBCS 桁は実機と一致した（**ゴールデン取得**）

12 桁目に置いた定数の、実機の画面での占有（`ASA1` / 24×80）:

| 定数 | 実機の画面 | 占有桁 | 本 PJ の `constantSegments` |
|---|---|---|---|
| `'顧客保守'` | 13:顧 15:客 17:保 19:守 | **12-21（10 桁）** | so(1)+4×2+si(1) = 10 ✓ |
| `'ID:顧客'` | 12-14:`ID:` 16:顧 18:客 | 12-20（9 桁） | 3+so(1)+2×2+si(1) = 9 ✓ |
| `'あZい'` | 13:あ 16:Z 18:い | 12-20（9 桁） | so+2+si+1+so+2+si = 9 ✓ |
| `'ABCD'` | 12-15 | 12-15（4 桁） | 4 ✓ |
| `'顧客-`＋`保守'` | 13:顧 15:客 17:保 19:守 | 12-21（10 桁） | 継続なしと同じ ✓ |

**開始桁には SO が乗り、最初の文字はその次に出る**——描画モデルのコメントどおりで、
`printWidth` / `constantSegments` の桁勘定は**実機と一致している**。

### F5: いまの本 PJ は継続を知らず、**項目ごと落としている**

実機で通る DSPF（定数 5 個。うち 4 個が継続を含む）を `buildDspfRenderModel` に読ませると、
**描かれたのは 1 個だけ**だった。

原因は `toLogicalUnits`（`src/core/dds/ddsLogicalUnits.ts:137`）の分類:
継続元の行は引用符が閉じていないため `readConstant` が `undefined` を返し、名前欄も空なので
**「キーワードだけの行」と判定され、直前の単位（様式）へ吸収される**。

さらに結合は `` `${previous.keywords} ${keywordArea}` `` の**空白 1 つ固定**なので、
`COLOR(-` ＋ `RED)` は `COLOR(- RED)` になる（継続記号も余分な空白も残る）。

### F6: DBCS を含むソースの転送には CCSID の指定が要る（PJ skill の未確認事項を解消）

`.claude/skills/ibmi-remote/SKILL.md` は「**DBCS を含む場合は未確認**」としていた。確認した:

- `CRTSRCPF FILE(x) RCDLEN(112)`（既定）は **CCSID 1027（日本語 SBCS のみ）**の
  ソース物理ファイルを作る。ここへ `CPYFRMSTMF … STMFCCSID(1208)` で全角を入れると
  **黙って空白になる**（コンパイルは通り、画面には何も出ない）。
- `CRTSRCPF … CCSID(5035) IGCDTA(*YES)` で作れば、UTF-8 の全角がそのまま入り、
  SO/SI はコピー時に挿入される。実機の画面で F4 のとおり出た。

## 影響範囲

- `src/core/dds/ddsLogicalUnits.ts` — 継続の判定と結合（`toLogicalUnits` の前段）。
- そこから `dspfLayout` / `dspfOutline` / `dspfRenderModel` / `prtfLayout` / lint が**自動的に**直る。
- `src/core/dds/ddsEdit.ts` — 継続行にまたがる項目のキーワード欄の書き換えは**拒否**する必要がある
  （いまは代表行だけを書き換えるので、継続行が取り残されて壊れる）。

## 実現性 / リスク

- **リスク: 既存の読み取りを変えてしまう**。継続でない「キーワードだけの行」は
  従来どおり空白 1 つで連結しなければならない（`OVERLAY` を別行に書く形は普通）。
  → 継続と判定するのは**前の行が `-`/`+` で終わるか、引用符が閉じていない**ときだけ。
- **リスク: 引用符の状態の判定**。`''` はエスケープなので、そこで閉じない
  （`parseKeywordEntries` で同じ判定を既に書いてある）。
- **リスク: PRTF / PF・LF**。同じ `toLogicalUnits` を通るので直るはずだが、
  **実機で確かめたのは DSPF だけ**。

## 実装時の注意

- **継続記号は「機能欄の最後の非空白」で判定する**。行全体の末尾ではない
  （81 桁目以降は DDS が読まない。実際、80 桁を超えた行は `CPD7508`
  「閉じ引用符が無い」になって別の理由で落ちた）。
- **`unit.line`（代表行）は変えない**。位置・長さ・用途は代表行の桁から読む。
  変えるのは `unit.keywords` と `sourceLines` だけ。
- 継続に使った行は `sourceLines` に入れる。**削除がまとめて消せなくなる**と、
  継続行だけが取り残される。

## spec への申し送り

- 結合は `toLogicalUnits` の**前段の純関数**に切り出す（単体で規則だけを固定できる）。
- 継続行にまたがる項目のキーワード欄の書き換えは**拒否**する（生成は別 work）。
- 実機の実験は再現できる形で残す（この work の `verify/`）。
