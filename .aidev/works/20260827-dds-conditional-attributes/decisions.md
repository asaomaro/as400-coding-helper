# 決定記録

## D1: `keywords`（全部の連結）の意味は変えない

- 背景: 条件つきのキーワードを条件として扱うには、連結した `keywords` から
  条件つき分を分ける必要がある。
- 決定: `keywords` は**そのまま**残し、**追加の見方**として `keywordGroups` を足した。
  連結が `keywords` に一致することをテストで固定している。
- 理由: `keywords` は `readConstant` / `fieldWidth` / `readSpacing` /
  チップ表示 / `setKeywords` の 5 か所が読んでいる。ここから条件つき分を引くと、
  たとえば**条件つき `EDTCDE` で幅が変わる**——今回の狙い（見え方）を超えて振る舞いが動く。
- 影響: 見え方の解決だけが `keywordGroups` を見る。

## D2: 条件の解釈は `ddsConditioning` に置く（環状 import を避ける）

- 背景: `toLogicalUnits`（`ddsLogicalUnits.ts`）で条件を解きたかったが、
  `ddsConditioning.ts` が `ddsLogicalUnits.ts` を import しており逆向きにできない。
- 決定: `ddsLogicalUnits` は**桁を切り出すところまで**（`RawKeywordGroup`）を持ち、
  解釈は `ddsConditioning.resolveKeywordGroups` が行う。
- 影響: 画面と帳票の両方が同じヘルパを通る。

## D3: 先行する条件行はキーワードの条件にする

- 背景: 条件だけの行（`A  30`）の次にキーワードだけの行が来る形では、
  直す前は条件が**次の項目**へ持ち越されていた。
- 決定: キーワードだけの行に連結するとき、溜まっていた条件行も**そのキーワードの条件**に含める。
- 理由: 原典より条件は直後の指定に付き、「最後の (または唯一の) 標識は同じ行に指定」される。
  次の項目に無関係な条件が付くのは誤り。
- 影響: OR 条件（`A  30` ＋ `A O 31 … DSPATR(RI)`）もキーワードの条件として読める。

## D4: 未設定の標識は「効かせる」

- 背景: 3 値（未設定 / オン / オフ）のうち未設定をどう倒すか。
- 決定: **効かせる**（`hidden` と決まったものだけ落とす）。
- 理由: 項目の表示と**同じ倒し方**にそろえる。片方だけ別にすると、
  同じ標識で**項目は残るのに色だけ消える**が起きる。
  既定の見え方が変わらないという既存の担保（`applyIndicators(model, {})` は同一参照）も保てる。
