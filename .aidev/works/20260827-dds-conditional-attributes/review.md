# レビュー: 条件つきの `COLOR` / `DSPATR` を条件として扱う

## ラウンド 1（2026-08-27）

### 要件適合
- AC1 ✓ `hidden` と決まった群は効かない（単体・e2e とも）。
- AC2 ✓ 未設定は効かせる。既定の見え方は変わらない。
- AC3 ✓ プロパティに `条件つき` の行（条件・キーワード・いま効くか）。
- AC4 ✓ `applyIndicators(model, {})` は同一参照（テストで固定）。
  さらに**条件つきの群を持たない項目は作り直さない**ようにした。
- AC5 ✓ 帳票にも群が載り、連結が `keywords` と一致する（テストで全項目を確認）。

### 価値適合
狙いは「標識を倒したときの見え方が分かる」。実務の DSPF は
「エラーのとき赤」「入力中は反転」を条件つきキーワードで書くので、
**その見え方こそ確認したいもの**だった。直す前は倒しても何も変わらなかった。

### 正確性
- `COLOR` の「**有効になっているものの**最初」を守るため、**絞ってから最初を採る**。
  条件で最初の `COLOR` が落ちると次のものが効くことをテストで固定した。
- 先行する条件行を次の項目へ持ち越していた誤りも直った（D3）。
- 3 値の倒し方を項目の表示とそろえた（D4）。ずらすと「項目は残るのに色だけ消える」が起きる。

### 規約適合
- **写しを作っていない**（AGENTS.md「プロンプターは『モデルまで』では届いていない」）。
  UI は `applyIndicators` の結果を描くだけで、評価は core の 1 か所にある。
- 原典の引用（条件が付く対象は「フィールド**または**キーワード」／`COLOR` は
  「有効になっているものの最初」）をコードの注記に残した。

### 保守性
`keywords` の意味を変えず追加の見方にしたので（D1）、既存の 5 つの読み手は無傷。
連結が一致することを 4 つのソースで固定してあるので、片方だけ壊れれば落ちる。

### 指摘
must 0 / should 0 / nit 0。

**残り**: 条件つきの `EDTCDE` は幅に効くが、今回は見え方だけを条件で解いている。
幅は連結した `keywords` から求めたまま（＝条件に関係なく効く）。
別の話（幅が変わると配置も変わる）なので backlog に残す。
