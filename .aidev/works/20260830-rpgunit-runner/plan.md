# 計画: RPGUnit ランナー

## 実装方針

**実機に触らない部分を先に作り、`--self-test` で確かめてから実機に繋ぐ。**
実機の段は 1 つずつ足して、そのつど本物で通す（この道具の検証は実機でしか成立しない）。

## 作業順序と依存関係

1. **T1** 骨格 ＋ 純粋な部分（`parseArgs` / `summarize`）＋ `--self-test`（依存: なし）
2. **T2** 前提の確認と接続（依存: T1）
3. **T3** 転送（ローカル → IFS → メンバー → `SRCTYPE`）（依存: T2）
4. **T4** ビルド（`SBMJOB RUCRTRPG` ＋ 完了待ち ＋ 失敗時のスプール名）（依存: T3）
5. **T5** 実行と XML 取得（依存: T4）
6. **T6** 表示・`--xml` 保存・終了コード・後始末（依存: T5）
7. **T7** `tools/README.md`（依存: T6）
8. **T8** skill `rpgunit-test` から案内する（依存: T7）
9. **T9** 実機で通し確認（合格のみ / 失敗あり / SQLRPGLE / ビルド失敗）（依存: T6）

## リスク / 留意点

- **実機が要るので CI では回せない。** `--self-test` が唯一の自動で回せる部分になる。
  純粋な部分をそこに寄せる（spec 設計方針 1）。
- **ゴミとジョブを残さない。** `finally` で IFS を消す。`INQMSGRPY(*DFT)` を必ず付ける。
  T9 の後に実機の残留を数えて確かめる。
- **スプールは消さない**（規約）。増えることは受け入れ、名前を報告する。
- **秘密を読まない。** `.env` の中身は参照しない。
- **cwd の取り違え**に注意。ts5250 の `--env-file` を使うため `cd /workspaces/ts5250` が要るが、
  **git 操作をそこで走らせない**（本セッションで実際に別リポジトリへコミットしかけた）。

## テスト方針

| 層 | 見るもの | AC |
|---|---|---|
| `--self-test`（実機なし） | 引数の既定値の解決（`--pgm` 省略・拡張子からの `SRCTYPE`）と `summarize` の抽出 | AC2, AC3, AC7 |
| 実機・合格のみ | 通ること・**終了コード 0** | AC1, AC4 |
| 実機・失敗あり | **終了コード 1** ＋ 失敗の内訳が出る | AC4, AC7 |
| 実機・SQLRPGLE | 同じ入口で通る | AC3 |
| 実機・ビルド失敗 | **終了コード 2** ＋ スプール名とジョブ名が出る | AC8 |
| `--xml` | ローカルに保存され `<testsuite>` として妥当 | AC6 |
| 後始末 | IFS に作業ファイルが残らない | AC5 |

**「落ちること」も確かめる**——わざと壊した入力で終了コード 1 と 2 を出させる。
成功ケースだけ見て「動いた」としない。
