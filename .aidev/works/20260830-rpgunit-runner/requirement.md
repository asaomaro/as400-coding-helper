# 要件: RPGUnit のテストを 1 コマンドで回して結果を採る

## 背景 / 課題

RPGUnit は SR-OSAKA に導入済みで、テストを書いて実行し結果を採ることは**手順としては
確立している**（`docs/workflow/rpgunit-install.md` / skill `rpgunit-test`）。
しかし**それを実行する道具が無い**。

リポジトリを調べた実測:

```
RUCALLTST を扱う再利用可能なスクリプト : 0 件
hostserver に繋ぐ使い捨てスクリプト     : 65 件（.aidev/works/*/verify/ に散在）
うちスプールを読むもの                  : 12 件
```

**毎回その場で書いて捨てている。** 接続の型・ジョブの完了待ち・スプールの読み方を
書き直すたびに同じ罠を踏む（実際、`readSpooledPages` の引数名を間違えて 2 回やり直した）。

設計書 4.2 が想定する「**AI がテストを書いて実機で回す**」ループは、この 1 本が無いと
成立しない。いまは毎回人（または AI）がつなぎ役をやっている。

## 目的 / ゴール

**ローカルのテストソース 1 本を渡せば、転送・ビルド・実行・結果採取までが 1 コマンドで
終わり、失敗が終了コードで分かる**状態。CI からも AI の自律ループからも同じ入口で回せる。

今回確かめた罠（`SRCMBR` はプログラム名と揃える / `INLLIBL` ＋ `RPGUNIT/` 修飾 /
`INQMSGRPY(*DFT)` / 既定 20 秒では足りない / スプール名は `RPGUNIT`）を
**道具の中に閉じ込め、使う側が知らなくてよい**状態にする。

紐づく charter ゴール: 主要 3 本柱を支える検証基盤（`品質基準`「テスト通過」）。

## ユーザーストーリー

- **US1**: 本 PJ の開発者として、テストを書いたら 1 コマンドで実機の結果まで見たい。
  なぜなら、**つなぎのスクリプトを毎回書くコストがテストを書く動機を殺す**から。（AC1〜AC5）
- **US2**: CI を組む者として、**終了コードと JUnit XML** が欲しい。
  なぜなら、それがあれば GitHub Actions のテストレポーターにそのまま載せられるから。（AC6, AC7）
- **US3**: 自律ループを回す AI として、**失敗の理由を機械可読で受け取りたい**。
  なぜなら、スプールを人が読む前提だと修正ループが閉じないから。（AC7, AC8）

## スコープ

### 対象
- ローカルのソース → IFS → ソース物理ファイルのメンバー → `RUCRTRPG` → `RUCALLTST`。
- **結果の採取**: JUnit XML の取得・ローカル保存・要約表示・終了コード。
- 失敗時の詳細（どのテストが・どこで・何と言って落ちたか）の表示。
- RPGLE / SQLRPGLE の両方。

### 対象外
- テストコードの生成（AI や人が書く。本ツールは回すだけ）。
- Windows 版（PowerShell）の用意。
- pub400 対応（RPGUnit が入らない）。
- スプールの取得（**XML で足りる**。日本語機では化けるため人が読む用途にも向かない）。
  ただし失敗時の手掛かりとして**スプール名とジョブ名は表示**する。

## 機能要件

- ローカルのソースファイルとテストプログラム名を受け取り、最後まで通す。
- ソースタイプ（`RPGLE` / `SQLRPGLE`）を指定できる。省略時は拡張子から決める。
- **XML をローカルに保存できる**（CI が成果物として拾えるように）。
- 結果を人が読める形で要約する（件数・失敗の内訳）。
- **失敗があれば終了コード 1、道具自体の異常は 2**。
- 途中で落ちたときに**どの段で落ちたか**が分かる。

## 非機能要件 / 制約

- **秘密を読まない・出さない**。`/workspaces/ts5250/.env` は `--env-file` で渡すだけ
  （あちらの規約）。識別子は `.env.verify` から取る。
- **実機にゴミを残さない**。IFS の作業ファイルは消す。**スプールは消さない**（規約）。
- ジョブを `MSGW` で残さない。
- 既存の CI を壊さない（名指しで実行されない場所に置く）。

## 完了条件 (受け入れ基準)

- [ ] **AC1**: ローカルのソース 1 本を渡すと、転送・ビルド・実行が通り、結果が表示される。
- [ ] **AC2**: `SRCMBR` の制約（プログラム名と揃える）を利用者が意識せずに済む。
- [ ] **AC3**: SQLRPGLE でも同じ入口で通る（`SRCTYPE` の指定漏れで落ちない）。
- [ ] **AC4**: 合格だけのテストで**終了コード 0**、失敗を含むテストで**終了コード 1**。
- [ ] **AC5**: 実行後、IFS に作業ファイルが残らない。
- [ ] **AC6**: `--xml <path>` でローカルに JUnit XML が保存され、`<testsuite>` として妥当。
- [ ] **AC7**: 失敗時に**どのテストが・どこで・何と言って**落ちたかが表示される。
- [ ] **AC8**: ビルドに失敗したときに、**コンパイル・リストのスプール名とジョブ名**が
      表示される（次に読む先が分かる）。
