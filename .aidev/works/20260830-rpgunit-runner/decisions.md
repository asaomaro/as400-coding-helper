# 決定記録

## D1: 置き場所は `tools/` を新設した

- 背景: 本リポジトリの最上位は `docs/` と `vscode-extension/` だけ。
- 決定: **`tools/` を新設**。
- 理由 / 代替案: `vscode-extension/scripts/` にある 5 本は**実機に触らない**検証系で、
  ts5250 のチェックアウトに依存するものを混ぜると性質が違うものが同居する。
  `docs/origin/*.sh` にも実機に触る前例はあるが、あちらは**原典取得**の道具で用途が違う。
  CI は名指しの script だけを実行するので、新設しても CI に影響しない（確認済み）。
- 影響: `tools/README.md` に「ここのものは CI では検証されない」と明記した。

## D2: 終了コードでビルド失敗（2）とテスト失敗（1）を分けた

- 背景: どちらも「赤」だが、CI にとって意味が違う。
- 決定: `0`=全合格 / `1`=テストが失敗 / `2`=道具の異常（前提不足・ビルド失敗・XML が取れない）。
- 理由: 混ぜると **CI が「テストが落ちた」と「そもそも回せなかった」を区別できない**。
  後者はテストの赤ではなく環境の問題なので、扱いが変わる。
- 影響: ビルド失敗時は**コンパイル・リストのスプール名とジョブ名**を出す（次に読む先が分かる）。

## D3: メンバー名を利用者に選ばせない

- 背景: `RUCRTRPG` は `SRCMBR` に別名を渡すと `getMemberType` が**プログラム名**の
  メンバーを探して `CPF9815` で落ちる（本セッションで 2 回再現）。
- 決定: **メンバー名は常にプログラム名**にする。`--srcmbr` を用意しない。
- 理由 / 代替案: オプションとして出すと、渡せるのに効かないものを見せることになる。
  原因（RUCRTRPG の仕様か `SBMJOB` 経由特有か）は切り分けていないが、
  **揃えれば起きない**ことは確かなので、道具の側で揃える。
- 影響: `--pgm` を指定するとメンバー名もそれになる。README とヘルプに明記した。

## D4: 純粋な部分を `--self-test` で確かめられるようにした

- 背景: 実機が要る道具は**そのままでは自動の回帰が書けない**（CI から実機に届かない）。
- 決定: `parseArgs` と `summarize` を実機非依存にし、`--self-test` で 13 件を確かめる。
- 理由: 引数の既定値の解決（拡張子 → `SRCTYPE`）と XML の読み取りは、
  **壊れても実機に行くまで気付けない**種類の欠陥。ここだけでも自動で守る。
- 影響: `summarize` のテストには**実機が実際に出した XML** を使っている（作り物にしない）。

## D5: スプールの取得は道具に入れない

- 背景: 結果の出口は XML とスプールの 2 つある。
- 決定: **XML だけ**を採る。スプールは**名前とジョブ名を出すに留める**。
- 理由: XML は JUnit 形式で機械可読。スプールは日本語機で化けるため人が読む用途にも
  向かない（実機で確認済み）。両方採ると道具が太るだけ。
- 影響: 失敗の調査でスプールが要るときは、出した名前を使って手で読む。
