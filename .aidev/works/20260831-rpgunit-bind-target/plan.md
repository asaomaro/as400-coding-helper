# 計画: テスト対象のバインド

## 実装方針

**research の段で実機に通してから作った**（プロトタイプの解決と `BNDSRVPGM` の書式が
文書だけでは決まらなかったため）。実装は確かめた形を写すだけにする。

## 作業順序と依存関係

1. **T1** 実例 3 本を書き、対象を実機でビルドする（依存: なし）※ research で実施済み
2. **T2** `--bnd` の解析と `BNDSRVPGM` の組み立て（依存: T1）
3. **T3** `SBMJOB` の成否確認（依存: なし。T2 の誤りで必要性が判明）
4. **T4** `--self-test` に追加（依存: T2）
5. **T5** 実機でバインドして緑を確認（依存: T2, T3）
6. **T6** **対象を壊して落ちることを確認**し、戻して緑に復帰（依存: T5）
7. **T7** `tools/example/` と README・skill（依存: T6）

## リスク / 留意点

- **通っただけでは意味が無い。** バインドが効いていなくても自己完結のテストは緑になる。
  **T6（壊す検査）が本体。**
- **壊した対象を実機に残さない。** T6 の後に必ず戻して緑を確認する。
- ゴミとジョブを残さない。スプールは消さない。

## テスト方針

| 層 | 見るもの | AC |
|---|---|---|
| `--self-test` | `--bnd` の既定・大文字化・繰り返し・不正形式 | AC6 |
| 実機・正しい対象 | `SUCCESS 2 tests, 0 failure`・終了 0 | AC1, AC2 |
| 実機・壊した対象 | `FAILURE 2 tests, 2 failure`・終了 1 | **AC3** |
| 実機・復帰 | 戻して再び緑 | AC3 の後始末 |
| 実機・`--bnd` 省略 | 従来どおり通る | AC5 |
