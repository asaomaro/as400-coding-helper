# 仕様: 条件つきの `EDTCDE` を幅に効かせるか決める

## 設計方針

**原典に規定を見つけられないので、実機に判定させる**（AGENTS.md）。
ローカルの原典スナップショットは `EDTCDE` の索引項目しか持たず、
「オプション標識が有効か」を書いた詳細ページが無い。

判定は**副作用の無い形**で行う（コンパイルするだけ。作ったファイルは消す）。

## 対象範囲

- `verify/probe-conditionable-keywords.mjs`（新規・work 内）
- `src/core/dds/ddsFieldWidth.ts` — 結果の記録

## 振る舞いの詳細

実機（IBM i 7.3 / 2026-08-27）の結果:

| キーワードを条件付ける | `CRTDSPF` |
|---|---|
| `DSPATR(RI)` | **通る** |
| `COLOR(RED)` | **通る** |
| `EDTCDE(J)`（`B` / `O` とも） | **通らない**（`CPF7311`） |
| `EDTWRD(...)` | **通らない** |
| `CHECK(RB)` | **通らない** |

したがって**条件つき `EDTCDE` は有効なソースに存在しえない**。
幅を条件で解く必要は無く、いまの実装（連結したキーワードから求める）が正しい。

## ドメイン固有の考慮

**「直さない」という結論こそコードに残す。** `keywordGroups` があるので、
後から見た人が「幅も条件で解けるのに解いていない」と読んで直しにかかりうる。
実機の結果を注記に置いて、直すべきでないことが分かるようにする。
