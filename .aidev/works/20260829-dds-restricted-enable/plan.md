# 計画: 確かめた欄だけを lint の対象にする

## 作業順序

1. 全空間の網羅を 1 回のコンパイルで流す（表示装置 38 桁）
2. 一括の読み取りが当てになるか、単独の判定と突き合わせる
3. 原典に無いのに通った値を単独で確かめる（対照つき）
4. `PROVEN_COMPLETE` を置き、`restricted` を出す
5. 規則を既定 ON にし、**偽陽性を数える**
6. 既定の規則集合を固定しているテストを**理由つきで**更新する

## リスク / 留意点

- **R1: 一括の読み取りは当てにならないことがある。** リストが 2 部構成で、
  後半が前半を上書きする。**単独の判定と突き合わせて検算する。**
- **R2: 対照が落ちたら結果を採らない。** PF はこれで弾いた。
- **R3: 既定の規則集合を変える。** 数を書き換えるだけにせず、
  **なぜ変わったか**をテストに残す。

## テスト方針

| 見るもの | どこで |
|---|---|
| 印が付く範囲 | `ddsPositionalValues.test.ts`（`["DDS-DSPF:38"]` を固定） |
| 規則が実機の弾く値を指摘する | 同上（`Z` と `0`） |
| 既定 ON | 同上 ＋ `lintRules.test.ts` |
| 偽陽性 | `docs/src` 11 件を lint して 0 件 |
