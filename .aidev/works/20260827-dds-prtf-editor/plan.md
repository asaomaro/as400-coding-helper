# 計画: PRTF をビジュアルエディタで開く

## 作業順序と依存関係

1. 翻訳を切り出す（`ddsRenderItem.ts`）— 依存なし。**既存の import を壊さない**
2. `PlacedItem` に翻訳に要る欄を足す — 依存なし
3. `prtfRenderModel.ts` — 依存: 1, 2
4. `moveColumn` と `row-from-spacing` — 依存なし
5. ホストの結線（`.prtf` の登録・設定・単独起動の題材）— 依存: 3
6. UI（種別での出し分け・横だけのドラッグ・オーバーフロー行）— 依存: 3, 4
7. 単体テスト — 依存: 3, 4
8. GUI e2e — 依存: 5, 6
9. **実機で行送りを確かめる** — 依存: 3
10. 記録 — 依存: 全部

## リスク / 留意点

- **切り出しで既存を壊さない**。`dspfRenderModel` から再輸出し、import 元を変えない。
- **`PlacedItem` は足すだけ**（プレビューと lint が同じ型を使う）。
- **プロトコルに新しい編集を通し忘れる**と、UI が「適用中…」のまま止まる
  （`parseEdits` が捨てて何も返らない）。
- **UI が種別で出し分けを漏らす**と、帳票に効かない切替が残る。

## テスト方針

- **単体**（`test/unit/prtfRenderModel.test.ts` 新規）: 種別・紙面・行送りで決まる行・
  `rowFromSpacing`・占有に属性文字を含めない・一覧が「位置なし」にならない・
  実サンプル・編集の拒否と桁だけの移動。
- **回帰**: `npm test` / `npm run verify` / lint / GUI e2e（DSPF が変わらないこと）。
- **GUI e2e**: 帳票を開く・行送りの行・帳票に無いものが出ない・オーバーフロー行・
  **横だけ動く**・**行欄に書き込まない**。
- **実機**: 帳票をコンパイルし、RPG で書いてスプールを作り、
  **印刷結果の行・桁**と本 PJ の解決結果を突き合わせる。
