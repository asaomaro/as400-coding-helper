# 決定記録

## D1: 翻訳を切り出し、解決だけを種別ごとに持つ

- 背景: 描画に要るのは「文字と、それが何桁を占めるか」で、これは画面か紙かに依らない。
  違うのは**どこに置くか**（配置解決）だけ。
- 決定: `toRenderItem` と区切りの組み立てを `ddsRenderItem.ts` へ切り出し、
  `resolveDspfLayout` / `resolvePrtfLayout` のどちらの結果からも同じ `RenderModel` を作る。
- 理由 / 代替案: `prtfRenderModel` に翻訳を書き写す案もあったが、
  **SO/SI の桁勘定が 2 か所になる**——ここは実機と突き合わせて合わせ込んだところで、
  写せば必ず片方だけ直る日が来る。
- 影響: `dspfRenderModel` から再輸出して既存の import 元を変えていない（8 か所）。

## D2: **行送りで決まる行は書き換えない**（`moveColumn` を足す）

- 背景: 実務の PRTF は位置欄に**行番号を書かない**（サンプルの 4 項目すべてが空）。
  行は `SPACEA` / `SPACEB` / `SKIPA` / `SKIPB` で決まる。
  そこへ行番号を書き込むと**行送りが無効になる**（原典。`prtfLayout` も診断している）。
- 決定: 桁だけを動かす編集 `moveColumn` を足す。`move`（行も書く）は
  行番号を書いていない項目に対して `row-from-spacing` で拒否する。
  UI は**縦のドラッグを起こさない**（`cursor: ew-resize`）。
- 理由 / 代替案:
  - `move` のまま行欄を黙って書かない案 → **黙って別のことをする**ことになる。
  - 縦のドラッグを拒否で返す案 → 掴むたびに拒否が出て使えない。
  **操作そのものを起こさない**のが一番手応えが良い。
- 影響: プロトコルに 1 種類増えた。**通し忘れると UI が「適用中…」で止まる**
  （実際に踏んだ。`parseEdits` が捨てて何も返らないため）。

## D3: 一覧の「位置なし」を帳票の見方に直す

- 背景: `buildDspfOutline` は**位置欄だけ**を見るので、行番号を書かない帳票の項目を
  すべて `no-position`（位置なし）と判定する。実際にはキャンバスに描かれている。
- 決定: `fromPrtfLayout` が、**配置できた項目**に解決後の行・桁を入れて理由を落とす。
- 理由 / 代替案: `buildDspfOutline` に種別を渡す案もあったが、
  あちらは**位置欄の読み方**を知っているだけで、行送りの解決は知らない。
  解決を知っているのは `resolvePrtfLayout` の結果を持つ側なので、そちらで直す。

## D4: 帳票に無いものは**切替ごと出さない**

- 背景: 属性文字（項目の前後 1 桁）も 5250 の配色も**表示装置のもの**。
  PRTF のキーワード一覧に `DSPATR` は無い。
- 決定: 描かないだけでなく、ツールバーの切替を `hidden` にする。
- 理由: **押しても何も起きないボタンは「壊れている」と読まれる**
  （`20260826-dds-display-toggles` でスナップを作らなかったのと同じ理由）。

## D5: 紙面の大きさは**帳票プレビューと同じ設定**から採る

- 背景: `PAGESIZE` / `OVRFLW` は `CRTPRTF` のパラメータで、**DDS に書かれていない**。
- 決定: `rpgClSupport.prtf.pageLength` / `pageWidth` / `overflowLine` を読む。
- 理由: 同じソースが**2 つの画面で別の紙面に見えない**ようにする。
- 影響: 単独起動は設定を持たないので `CRTPRTF` の既定（66 × 132 / 60）。

## D6: 実機の印刷結果で `resolvePrtfLayout` を確かめた

- 背景: `resolvePrtfLayout` は**原典から起こしたまま、実機で確かめていなかった**。
  行がずれても画面では分からず、印刷して初めて気づく。
- 決定: 帳票と、それに書く固定長 RPG を実機でコンパイルして呼び、
  **スプールをテキストとして読んで**行・桁を突き合わせた（`verify/verify-prtf-rows.mjs`）。
- 影響: `SKIPB(1)`＋`SPACEA(2)` → 1 行目、`SPACEA(1)` → 3 行目、`SKIPB(10)` → 10 行目が
  **実機と一致**した。この work が触っていない既存コードの裏取りにもなった。
  なお外部記述の印刷装置ファイルは**コンパイル時に解決される**ので、
  `ADDLIBLE` を `CRTBNDRPG` より先に置く必要がある（`RNF2120` を踏んだ）。
