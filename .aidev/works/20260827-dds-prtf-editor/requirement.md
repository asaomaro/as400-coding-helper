# 要件: PRTF をビジュアルエディタで開けるようにする

## 背景 / 課題

DDS ビジュアルエディタは **DSPF だけ**を開く（`contributes.customEditors` の対象は
`*.dspf` と `*.mnudds`）。PRTF（帳票）は**読む側までしか対応できていない**。

| 機能 | DSPF | PRTF |
|---|---|---|
| ルーラー / SOSI / プロンプター / 補完 / lint / アウトライン | ✅ | ✅ |
| プレビュー（読むだけ） | ✅ | ✅ |
| **ビジュアルエディタ** | ✅ | ❌ |

そのため PRTF は、**桁を数えて位置欄を直す**という SEU 時代の作業のままになっている。
画面（DSPF）と同じ作業が帳票でできない理由は無い——`prtfLayout` は既に
`SPACEA`/`SPACEB`/`SKIPA`/`SKIPB` を解いて**絶対の行・桁**を出しており、
編集エンジン（`ddsEdit`）も位置欄と長さ欄しか触らないので**種別に依存していない**。

紐づく charter ゴール: **DDS（DSPF/PRTF）の視覚的な確認と編集**を第 4 の柱として加える。

## 目的 / ゴール

**PRTF をビジュアルエディタで開いて、DSPF と同じように直せる状態**。
紙面の上で項目を掴んで動かし、長さを変え、キーワードを直せる。

**帳票に無い概念を持ち込まない状態**（属性文字・5250 の配色は画面ファイルのもの）。

## ユーザーストーリー

- US1: 帳票を直す開発者として、**項目を掴んで動かしたい**。
  なぜなら、いまは桁を数えて 42-44 桁目を書き換えており、
  **1 桁ずれても実際に印刷するまで分からない**から。（受け入れ: AC1, AC2）
- US2: 帳票を直す開発者として、**行送りで決まる位置も紙面で見たい**。
  なぜなら、`SPACEB(2)` と `SKIPA(10)` が混ざると**何行目に出るのかソースから読めない**から。
  （受け入れ: AC3）
- US3: 帳票を直す開発者として、**行送りで位置が決まる項目を勝手に固定されたくない**。
  なぜなら、行番号を書き込むと `SPACE`/`SKIP` が無効になり、**別のものになる**から。
  （受け入れ: AC5）

## スコープ

### 対象
- PRTF の描画モデル（`prtfLayout` から作る）。
- ビジュアルエディタを `*.prtf` でも開けるようにする。
- 帳票に無いものを出さない（属性文字・5250 配色）。
- 行送りで位置が決まる項目の**移動を拒否**する。

### 対象外
- **CPI / LPI と紙面の比率**（プレビューモード）。**次の work**。
- 帳票の色・強調（`HIGHLIGHT` / `UNDERLINE` / `COLOR`）。
- 複数ページの表示（`prtfLayout` は 1 ページ分を返す）。
- `PAGRTT`（ページの回転）・`CHRSIZ`（文字サイズ）。

## 機能要件

- `.prtf` を「DDS ビジュアルエディタ」で開ける（既定のエディタは奪わない）。
- 紙面の大きさは `prtfLayout` の `PrtfPage`（既定 66 行 × 132 桁）。
- 行送り（`SPACEA`/`SPACEB`/`SKIPA`/`SKIPB`）で決まった**絶対の行**に描く。
- **属性文字を描かない**（帳票に無い）。**5250 配色を出さない**（画面ファイルのもの）。
- 行番号を書いていない項目は、**行を変える移動を拒否**して理由を出す。
- キーワードの編集・条件標識・SO/SI 表示・グリッド・ズームは**そのまま使える**。

## 非機能要件 / 制約

- **既存の DSPF の挙動を変えない**。
- core は `vscode` を import しない。
- 診断は `prtfLayout` が既に出しているものをそのまま使う（作り直さない）。

## 完了条件 (受け入れ基準)

- [ ] AC1: `.prtf` をビジュアルエディタで開き、項目が紙面に描かれる。
- [ ] AC2: 項目を掴んで動かすと、桁欄が書き換わる（DSPF と同じ操作）。
- [ ] AC3: `SPACEB` / `SKIPA` で決まる行が、**解決後の行**として描かれる。
- [ ] AC4: **属性文字と 5250 配色が出ない**（帳票に無い概念）。
- [ ] AC5: 行番号を書いていない項目の**行を変える移動が拒否**され、理由が出る。
      **桁だけを変える移動は通る**。
- [ ] AC6: `prtfLayout` の診断（重なり・はみ出し・2 重印刷など）が一覧に出る。
- [ ] AC7: DSPF の挙動・見え方がこの変更の前と一致する。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 右クリックから「DDS ビジュアルエディタ」で開ける。
- [ ] AC-I2 確定 / 取り消し: DSPF と同じ（ドラッグの確定はホストの往復後）。
- [ ] AC-I3 キーボードだけで完結するか: DSPF と同じ（矢印で移動）。
- [ ] AC-I4 フォーカスの行き先: DSPF と同じ。
- [ ] AC-I5 既存の操作を妨げないか: DSPF 用の切替（属性バイト・5250 配色）は
      **PRTF では出さない**（押しても何も起きないボタンを置かない）。
