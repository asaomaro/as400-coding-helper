# 決定記録

## D1: 標識の状態は UI が持ち、規則だけを core に置く

- 背景: 描画モデルは**ホストが組み立てて UI に送る**（`editorProvider` / `dev/standalone.ts`）。
  標識の状態をモデルに載せるなら、切り替えるたびにホストへ作り直しを頼む往復が要る。
- 決定: 状態（`{ "01": "on" }`）は UI の中だけに持ち、core には
  **`applyIndicators(model, states) → model` という純関数を 1 つ**置く。`protocol.ts` は変えない。
- 理由 / 代替案: 直前の work（`20260826-dds-display-toggles`）で「**表示の状態はホストへ送らない**」
  という境界を引いており、標識も**ソースを 1 文字も変えない表示**なので同じ側にある。
  往復させる案（`setIndicators` メッセージ）は、両ホストにそれぞれ実装が要るうえ、
  切替の反映が非同期になる。
  「UI は判断を持たない」という原則とは、**判断（規則）は core、状態は UI** で両立する。
- 影響: `protocol.ts` / `editorProvider.ts` / `dev/standalone.ts` が無変更。
  代わりに WebView バンドルへ core の実行時コードが入る（単独起動側は元から入っている）。

## D2: 状態が空なら引数のモデルを**同一参照で**返す

- 背景: 「何も指定しなければ今までと同じ」（AC7）は、値を比較するテストでは守りきれない
  （新しい配列を作れば `deepStrictEqual` は通るが、参照が変われば下流の最適化や
  「変わっていない」判定が壊れうる）。
- 決定: `Object.keys(states).length === 0` のとき `model` をそのまま返す。テストも**参照**で比べる。
- 理由 / 代替案: 常に組み直す実装のほうが分岐が減って綺麗だが、**既定の挙動が変わっていないこと**を
  以後ずっと検査で追いかける必要が出る。分岐 1 本で構造的に保証できるならそちらが安い。
- 影響: `dspfOutline.test.ts` の既存ドリフト検査が、標識機能の追加後もそのまま意味を持つ。

## D3: 標識の一覧は論理単位ではなく**生の行**から集める

- 背景: 原典は条件が付く対象を「フィールド**または**キーワード」としている。
  `toLogicalUnits` は**キーワードだけの行**を直前の項目へ連結する際、その行の条件付け欄を捨てる
  （項目の表示を決めるのは項目自身の条件だけなので、その扱い自体は正しい）。
- 決定: `collectIndicators` は注記行・空行を除く**全行**の 7-16 桁を `readConditioning` に通す。
- 理由 / 代替案: 単位から集めると `30 DSPATR(RI)` のような**キーワードを条件付ける標識が一覧から消える**。
  一覧は「このファイルで意味を持つ標識」を出すものなので、項目に効くかどうかで絞ってはいけない。
  `toLogicalUnits` 側でキーワード行の条件を保持する案もあるが、**項目の表示判定に混ざる恐れ**があり、
  既存の診断（重なり抑制）に波及する。列挙だけのために既存の解決経路を触らない。
- 影響: `dev/` の `indicators.dspf` と e2e で、この形を実際に確かめている。

## D4: 重なりの厳密化はせず、**状態を明示したときだけ**足す

- 背景: `isMutuallyExclusive` は「片方でも条件が付いていれば排他」に倒してあり、
  条件付きの重なりを報告しない。原典は条件違いの重なりを正当と認めている
  （「一時点で画面に表示されるのは 1 つだけ」）。
- 決定: 既存の判定は**触らない**。標識を 1 つ以上指定しているときに限り、
  その状態で**同時に出ると決まった**項目どうしの重なりを `overlap-under-indicators` で足す。
- 理由 / 代替案: 静的に厳密化すると `01` と `02` の重なりを報告することになり
  （同時にオンになりうるので静的には排他でない）、実務の DSPF で誤検出が出る。
  利用者が組み合わせを言い切ったときだけなら、その前提が置ける。
- 影響: 診断コードを 1 つ増やした。既存の `overlap` と混ぜないのは**前提が違う**ため
  （前提が同じ引き出しに入っていると、何を直せば消えるのかが読めない）。

## D5: 3 択はラジオグループ（巡回ボタンにしない）

- 背景: 「未設定 / オン / オフ」を 1 つのボタンで巡回させると実装は小さい。
- 決定: APG の Radio Group（`role="radiogroup"` ＋ ローミング `tabindex` ＋ 矢印キー）にする。
- 理由 / 代替案: 巡回ボタンは**現在値と次の値が読み取れない**（読み上げでは「01 ボタン」としか
  分からない）。tri-state checkbox の `aria-checked="mixed"` は「部分的に選択」の意味で、
  「未設定」には当たらない。ラジオグループなら標識が並んでも `Tab` の回数が増えない。
  requirement の `AC-I3` は当初「`Enter`/`Space` で巡回」と書いていたが、research F7 を受けて改めた。
- 影響: 矢印キーを **`stopPropagation` で止める**必要がある（止めないと選択中の項目が動く）。
  e2e で実際に押して確かめている。

## D6: 標識が使われていなくても見出しは残す

- 背景: `AC-I1` は「標識が 1 つも使われていないファイルでは、カード自体を出さずに
  『使われていません』と出す」と書いていた。
- 決定: **見出し（`条件標識`）は常に出し**、中身を「このソースでは使われていません」の 1 行にする。
- 理由 / 代替案: 見出しごと消すと、**その機能があること自体が見えなくなる**
  （条件を持たないファイルを最初に開いた利用者は、パネルの存在を知らないまま終わる）。
  1 行の説明なら場所も食わない。
- 影響: AC-I1 の文言とは厳密には違う実装になっている（意図——空のカードで場所を食わない——は満たす）。
