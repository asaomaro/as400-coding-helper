# 要件: 複数ページの帳票を見る

## 背景 / 課題

`resolvePrtfLayout` は**1 ページ分しか返さない**。`SKIPB` で改ページが起きる帳票は
2 ページ目以降が見えず、しかも**行が逆走する**——40 行目のあと `SKIPB(3)` で
`cursor.row = 3` と素直に戻すので、1 枚の紙に別のページの項目が重なって描かれる。

前 batch では「原典が後戻りのときを規定していない」として着手を見送っていたが、
**規定は `SKIPB` ではなく `LPI` の詳細ページにあった**:

> データは、**行番号ではなく位置に基づいて**順次に処理されます。ある行番号への
> スキップを指定した場合に、それが**現在位置より前の位置**であれば
> (**たとえその行番号が現在の行番号より大きくても**)、**改ページが生じます**。

同じページに、**LPI がページの途中で変わるときの計算例**も載っている。

## 目的 / ゴール

改ページが起きる帳票で、**各ページを別々に見られる**状態。
位置の計算が原典の例と一致する。

## ユーザーストーリー

- US1: 帳票を書く人として、2 ページ目に何が出るかを見たい。
  なぜなら 1 枚に重ねて描かれると、**どちらのページの項目か分からない**から。
  （受け入れ: AC1, AC2, AC3）
- US2: 同じ人として、LPI を変える帳票でも位置が合っていてほしい。
  なぜならスキップ先は**用紙上の絶対位置**で決まり、行番号だけでは決まらないから。
  （受け入れ: AC4, AC5）

## スコープ

### 対象
- 位置（インチ）と LPI を追う配置解決。
- 後戻りするスキップでの改ページ。
- ページの切替（UI / CLI）。

### 対象外
- **行の高さを LPI ごとに変えて描く**こと。位置は正しく持つが、キャンバスは
  まだ「行 ＝ 一定の高さ」。別項目として残す。
- 実機での印刷による裏取り（前 batch で取れなかった。原典が規定しているので不要）。

## 完了条件 (受け入れ基準)

- [ ] AC1: 後戻りするスキップで**ページが増える**。前に進むスキップでは増えない。
- [ ] AC2: 各項目が**何ページ目か**を持つ。
- [ ] AC3: UI と CLI で**ページを切り替えられる**。1 ページなら切替を出さない。
- [ ] AC4: 位置（インチ）が**原典の計算例と一致**する
      （6 LPI で 24 行 → 8 LPI で 24 行 → 48 行目が 7 インチ）。
- [ ] AC5: LPI は**レコードの終わりでファイル・レベルへ戻る**。
- [ ] AC6: 1 ページに収まる帳票（実サンプル）の絵は変わらない（回帰）。

## 相互作用の受け入れ基準

- [ ] AC-I1 端で押せない: 最初のページで「戻る」、最後で「進む」を押せない。
- [ ] AC-I2 いまどこか分かる: 「1 / 2」のように出す。
