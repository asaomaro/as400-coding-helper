# 計画: 複数ページの帳票

## 作業順序と依存関係

1. `Cursor` に位置・LPI・ページを足し、`skipTo` / `advance` を作る（依存: なし）
2. 項目に `page` / `inches` を持たせる（依存: 1）
3. `selectPrintPage`（依存: 2）
4. UI のページ送り / CLI の `--page`（依存: 3）
5. 単体テスト（**原典の計算例をそのまま**）（依存: 2, 3）
6. e2e（依存: 4）

## リスク / 留意点

- **既存の絵を変えない**。LPI が 1 つなら位置 ∝ 行番号なので同じ答えになるはず。
  既存テスト（帳票の配置・描画・CLI・golden）が通ることで確かめる。
- **静的な絵はソースの順序で歩く**。実際の印刷順はプログラムが決めるので、
  ページが増えるのはソースの並び自体が後戻りを起こすときだけ。

## テスト方針

- 単体: **原典の計算例をそのままテストにする**（7 インチ / 6.875 インチ / 7.5 インチ）。
  改ページの有無・LPI の戻り・ページの絞り込み。
- e2e: ページ送りが出る・送れる・端で押せない・1 ページなら出ない。
- 戻して落ちることを 2 通りで確かめる（改ページを外す / LPI を見ない）。
