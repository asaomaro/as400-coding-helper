# 要件: F4 プロンプターを VSCode 非依存（standalone 基準）に作り替える

## 背景 / 課題

F4 プロンプターの UI は `src/prompter/binding.ts`（**1,401 行**）が
HTML・CSS・**インラインスクリプト 827 行**を文字列で組み立てている。
`<script>` の中身は**テンプレートリテラルの中の素の JS** なので、次がすべて成り立たない。

- **型検査が効かない。** `tsc` から見ればただの文字列で、綴り間違いも `null` 参照も通る。
- **自動で動かせない。** WebView の中は拡張ホストからも触れず、統合テストでも
  「例外なく開けた」までしか見られない（`20260828-f4-integration-test` で確認済み）。
  押して動くかは**誰も確かめていない**。
- **同じ規則が 2 か所に散る。** 依存規則・相関制約の判定はサーバ（`model.ts`）と
  クライアント（インライン JS）の両方にあり、`binding.ts` に
  「片方だけ直すと食い違う」と注意書きが要る状態になっている。

実際に PR#93〜#98 で 3 回踏んでいる（`dependencies` が WebView に渡っておらず
**一度も画面に出ていなかった**／`promptControl` が入力に追従しない／`maxLength` が
CL 変数の入力を打ち切る）。**いずれも `buildInitialState()` を見るテストは通っていた。**

DDS ビジュアルエディタ（PR #109）では同じ問題を構造で解いた——判断はコア / UI は描くだけ /
`acquireVsCodeApi` は bridge の 1 か所 / ホスト能力を宣言 / 単独起動して Playwright で操作する。
**その構造をプロンプターにも適用する。**

## 目的 / ゴール

**F4 プロンプターの UI が VSCode の外で動き、実際に操作して自動で確かめられる状態。**

- UI のコードが `vscode` を**型ごと**参照できない状態（`tsconfig.webview.json` の `types: []`）。
- 画面の中身（入力・条件表示・必須・繰り返し・ヘルプ・F4 in F4）が、
  ブラウザで**押して確かめられる**状態。
- サーバ/クライアントで同じ判定が二重に書かれていない状態。

紐づく charter ゴール: `.aidev/charter.md` が無いため該当なし。

## ユーザーストーリー

- US1: **この拡張を触る開発者**として、プロンプターの画面の振る舞いを**壊したら落ちる**形で
  持ちたい。なぜなら現状は「開けた」までしか自動で見ておらず、**画面の中の後退は
  利用者が触るまで分からない**から。（受け入れ: AC1, AC2, AC3）
- US2: **この拡張を触る開発者**として、条件表示・相関制約の判定を**1 か所**に持ちたい。
  なぜなら写しが手書きだと、片方だけ直したときに**黙って食い違う**から。（受け入れ: AC4）
- US3: **拡張の利用者**として、いまと同じように F4 が開き、同じように書き戻されてほしい。
  なぜならこれは作り替えであって、**機能の変更ではない**から。（受け入れ: AC5, AC6, AC7）

## スコープ

### 対象

- `src/prompter/` の WebView 層（`binding.ts` の HTML/CSS/script 部分）を
  `src/prompter/webview/`（`protocol.ts` / `bridge.ts` / `ui.ts` / `ui.css` / `main.ts`）へ移す。
- HTML の殻を `vscode` 非依存の純関数に切り出す（DDS の `webviewHtml.ts` と同じ形）。
- 束ね（`esbuild.webview.mjs`）と型検査（`tsconfig.webview.json`）にプロンプターを載せる。
- 単独起動ハーネス（`dev/prompter.html` / `dev/prompter-standalone.ts`）と
  Playwright の e2e（`dev/prompter-e2e.mjs`）を作り、**CI の `gui-e2e` に載せる**。
- ホスト側（`src/prompter/webview.ts`）を、束ねた資産を配る形に変える。

### 対象外

- **プロンプターの機能追加・画面の作り直し**。見た目と操作は現状を保つ
  （構造の入れ替えと、それにより初めて可能になる検証だけを行う）。
- 定義 JSON（`resources/prompter/`）の変更。
- `applyChanges.ts` / `clCommandParser.ts` / `model.ts` の**判断ロジック**の変更。
  これらは既にコア側にあり、そのまま使う。
- F4 の起動経路（キーバインド・`resourceExtname`）の変更。

## 機能要件

- UI は `Bridge`（`post` / `onMessage`）だけを通じてホストと話す。
- ホストが何を肩代わりするかを `PrompterHost` として宣言し、UI はそれを見て自前の部品を出し入れする
  （単独起動では F4 in F4 の入れ子・ヘルプの表示先が VSCode 版と変わる）。
- UI → ホストのメッセージは**受け口で検証**する（不正なら捨てる。例外にしない）。
- 単独起動ハーネスは、**同梱の定義 JSON を実際に読んで**画面を作る（作り物の定義で誤魔化さない）。

## 非機能要件 / 制約

- `npm run verify`（19 検査）と `npm test` が通ること。
- CSP を緩めない。**インライン `<script>` を無くす**ので `nonce` は外部スクリプト用になる。
- e2e は CI で**落ちたら止まる**（`continue-on-error` を付けない）。載せる前に安定を確かめる。

## 相互作用の受け入れ基準

作り替えであり**新しい部品は作らない**が、既存の操作は e2e で固定する。

- [ ] AC-I1 開く / 閉じる: F4 で開き、`Cancel` / `Esc` で閉じる。閉じたとき値は捨てられる。
- [ ] AC-I2 確定 / 取り消し: `OK`（submit）で確定し、検証に落ちたら閉じない。
- [ ] AC-I3 キーボードだけで完結する: `Tab` で巡回、`F1` ヘルプ、`F10` 追加、`F4` 入れ子、`Esc` 取消。
- [ ] AC-I4 フォーカスの行き先: 開いたら最初の入力欄。ヘルプを閉じたら元の欄。
- [ ] AC-I5 既存の操作を妨げない: ヘルプ表示中の `Tab` はヘルプを閉じてから巡回する。
