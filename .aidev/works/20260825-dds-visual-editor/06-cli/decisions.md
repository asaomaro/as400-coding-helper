# 決定記録

## D1: `init` を CLI に足し、`PatchOp` は 4 種のまま保った

- 背景: plan 時点で **AC7 が達成不能**だと判明した。`PatchOp` は 4 種ともアイテム単位で、
  `addItem` は既存のレコード様式を要求する。**空の状態から DSPF を作れない。**
- 決定: CLI に `dds init <file> --record NAME` を足す。`PatchOp` は増やさない。
- 理由 / 代替案: 代替は `addRecord` 操作の追加だが、様式の追加は requirement の **L4**（後続 work）。
  `init` は「ファイルを新規に作る」＝**編集操作ではなく足場作り**で、GUI の「新規ファイル」に対応する。
  `PatchOp` を 4 種に保てるので、**AC4 の「GUI と 1:1」という主張が濁らない**。
- 影響: **`init` は AC4 の「同等」の対象外**。AC4 が言う同等は L1 の編集能力についてであり、
  足場作りは別物。ヘルプ・`ac7-transcript.md`・本記録に明記した。

## D2: Shift_JIS のエンコーダを `TextDecoder` から自作した（依存を増やさない）

- 背景: 03 の `decisions.md` D4 から「Shift_JIS の書き戻しは 06 送り」と申し送られていた。
  Node には Shift_JIS の**エンコーダが無い**（`TextDecoder` はデコード専用）。
- 決定: `TextDecoder` で有効なバイト列を総当たりデコードし、**`文字 → バイト列` の逆引き表**を
  作ってエンコーダにする（9,334 件・初回のみ構築）。`iconv-lite` は入れない。
- 理由: 表の出所が Node（ICU）自身なので、**自前の変換表を持ち込まずに済む**。
  依存を増やさない利点もあるが、それ以上に「変換表の出所が明確」であることが大きい。
- 影響: **読み込んだエンコーディングで書き戻す**（勝手に UTF-8 化しない）。
  Shift_JIS で表せない文字があれば `EncodingError` で落とす——**黙って化けさせない**。
  往復テストで固定した。

## D3: 35 桁目は「データ型」ではなく「キーボードシフト属性」だった（原典と実機で確定）

- 背景: AC7 の実行中に、実機のコンパイルが `CPD7408` で落ちた。
  原因を追う過程で、**35 桁目をデータ型として扱っていた**のが誤りだと分かった。
- 決定: 原典（`docs/origin/dds/DDS-DSPF.pdf`）と実機で規則を確定させ、
  `effectiveDataType` / `isNumericField` を入れた。35 桁が空白でも 36-37 桁があれば数値。
- 理由: 原典の記述と実機の "Expanded Source"（compiler の正規化）が一致した。
  `5  0` → `5S 0`、`5   ` → `5A  ` と展開される。
- 影響: **レンダラの型判定を 35 桁だけに依存させない**ようにした。
  `validate` に `DDS7108`（数値キーボードシフトなのに小数桁が空白＝エラー）を足した。
  この規則が**テストのフィクスチャ自体の不正**（`EMPNO 6S B` に小数桁なし）を検出し、修正した。

## D4: 占有幅と「見える内容」の幅を分けた（符号位置）

- 背景: AC7 で実機に画面を出したとき、フィールド情報が `(3,15) len=4` を返した。
  **長さ 3 のフィールドが画面上は 4 桁を占めていた。**
- 決定: `itemWidth`（占有・検証用）と `itemContentWidth`（見える内容・描画用）を分け、
  `signPositions` で符号位置を求める。実機で規則を確定:

  | 35 桁 | 使用 | 追加桁 |
  |---|---|---|
  | `S` | `B` / `I` | **+1** |
  | `S` | `O` | 0 |
  | `Y` | `B` / `O` | 0 |
  | `A` | `B` | 0 |

- 理由: 符号を**入力する場所**が要るため、`S` かつ入力可のときだけ増える。
  `Y`（数値のみ）は符号を持たないので増えない——**推測ではなく実機で 8 通り確かめた**。
- 影響: **描画は影響を受けない**（符号位置は画面上では空白）ので、
  05 のゴールデンと AC7 の一致はどちらも保たれた。`validate` の隣接・桁溢れ判定だけが正確になった。

## D5: AC7 の失敗をすべて記録した

- 背景: AC7 は 1 回目で失敗した（実機コンパイルが `CPD7408`）。
- 決定: **失敗した箇所をすべて `docs/dds-golden/ac7-transcript.md` に残す**。
  取り繕って手で補わない。
- 理由: AC7 が検証しているのは**エージェントの能力ではなく CLI 表面の完全性**。
  補ってしまうと、測りたかったものが測れなくなる。
- 影響: 記録には 4 つの穴（新規作成手段が無い / `decimals` が無い / データ型の解釈が誤り /
  符号位置が足りない）が残っている。**1 回目で通っていたら、どれも見つかっていない。**
