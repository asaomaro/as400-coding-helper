### 指摘

#### should-1: `--write` と `--stdout` を同時指定すると、黙って破壊側に倒れる

実測:

```
dds patch a.dspf --ops - --write --stdout   → exit 0、ファイルが書き換わる
```

`--stdout` は「ファイルを書き換えない」という意思表示なのに、`--write` が黙って勝つ。
**非破壊のつもりで付けた指定が無視されて破壊される**のは、最も避けたい種類の挙動。

対応: **矛盾する指定は受け付けない**（使用法エラーで落とす）。

#### should-2: 終了コード 2（パース失敗）が宣言されているのに発生しえない

`EXIT.parseFailed = 2` は定義されているだけで、**どのコマンドからも返されない**。
パーサは解釈できない行をすべて `opaque` にするので、**parse は決して失敗しない**。

その結果、**DDS ですらないファイルが黙って成功する**。実測:

```
$ cat b.txt
これは DDS ではありません

$ dds parse b.txt     → exit 0 「[utf8, LF, 1 行]」
$ dds validate b.txt  → exit 0 「問題は見つかりませんでした」
$ dds render b.txt    → exit 0（空の画面）
```

エージェントは終了コードで成否を判断する（本 subtask の設計前提）。
**間違ったファイルを渡しても 0 が返る**なら、その前提が崩れる。

対応: **何も解釈できなかったとき**（レコード様式もアイテムも 0 件で、ファイルが空でない）に
終了コード 2 を返す。実機も同じ状況を `CPD5238 No valid record found in source` として
エラーにしているので、実機の判断と揃う。

#### nit-1: `--record --json` のように値が省略されたフラグは真偽値として扱われる

`--record` の直後が `--` で始まると値なしとみなし、`--record` は真偽値になる。
結果として「様式指定なし」＝最初の様式が描かれる。**誤った様式が描かれるより安全**な倒れ方だが、
利用者は指定が効いていないことに気づきにくい。実害は小さいので直さない。

### 判定

**should 2 件**のため、coding へ差し戻す。

## ラウンド 2（2026-08-26・差し戻し対応後）

### 対応内容

- **should-1 解消**: `--write` と `--stdout` の同時指定を**使用法エラー（1）で拒否**し、
  ファイルを書き換えないようにした。`--stdout` は「書き換えない」という意思表示なので、
  **黙って `--write` に負けるのが最も危ない**。
- **should-2 解消**: **何も解釈できなかったとき**（レコード様式もアイテムも 0 件で、
  内容が空でない）に**終了コード 2** を返すようにした。
  これで宣言だけだった `parseFailed` が実際に発生し、
  **DDS でないファイルが黙って成功する**ことが無くなった。
  実機も同じ状況を `CPD5238 No valid record found in source` としてエラーにしているので、
  **実機の判断と揃った**。
  - `init` 直後（様式はあるがアイテムが無い）は**成功**のまま。
  - 空ファイルも**成功**（内容が無いだけで、解釈の失敗ではない）。
  - この 2 つを回帰テストで固定した。
- nit-1（値が省略されたフラグ）は直さない。**誤った様式が描かれるより安全な倒れ方**で、実害が小さい。
