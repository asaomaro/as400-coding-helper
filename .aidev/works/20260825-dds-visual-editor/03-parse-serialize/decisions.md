# 決定記録

## D1: `DdsItem.keywords` を `string[]` ではなく `string`（生テキスト）にした

- 背景: spec の型定義は `keywords: readonly string[]` だったが、**配列にするには
  トークン分割＝解釈が要る**。spec 本文は同じ箇所で「walking skeleton では解釈しない」と述べており、
  型と方針が食い違っていた。
- 決定: 機能欄（45-80 桁）の**生テキストをそのまま `string` で保持**する。
- 理由 / 代替案: 「未解釈で保持する」を最も忠実に表すのは生文字列。配列にすると、
  空白区切りなのか括弧の対応を見るのかという**解釈の判断が型に紛れ込む**。
  L3（キーワード編集）でここを `Keyword[]` に差し替えるとき、
  呼び出し側が「未解釈の塊」として扱っていたほうが移行が局所化する。
- 影響: spec の型定義と実装が食い違う。**spec 側を実装に合わせるべき**だが、
  承認済み成果物なので本 subtask では変更せず、ここに記録して親の統合 review に上げる。

## D2: 名前欄が DDS の名前として不正な行は `opaque` にする（spec に無い判断）

- 背景: T6 の opaque 保持テストで、`     A?? …（日本語）…` という壊れた行が
  **`item` として解釈されてしまう**ことが判明した。6 桁目が `A` でありさえすれば、
  名前欄に何が入っていても「変な名前のフィールド」として取り込んでいた。
- 決定: 名前欄が `^[A-Z#$@][A-Z0-9#$@_]{0,9}$`（大小無視）に合わなければ `opaque` にする。
- 理由: 壊れた行をモデルに取り込むと、**後段の編集がその行を書き換えて壊しうる**。
  requirement の原則「扱えない要素があることは許容するが、扱えない要素を壊すことは許容しない」に
  従えば、疑わしいものは解釈せず素通しするのが正しい。
  弾かれた行も `raw` で保持されるので**失われない**。
- 影響: パーサが取りこぼす行が増える方向（安全側）。
  なお **名前欄は 19-28 桁の 10 桁固定なので「11 文字の名前」は原理的に存在しない**
  （11 文字目は名前欄の外に落ちる）。テストでこれを誤って前提にしていたので修正した。

## D3: `DdsDoc` に `finalNewline` と `encoding` を足した（spec の型には無い）

- 背景: spec の `DdsDoc` は `eol` / `bom` / `lineWidth` / `lines` / `records` だけだった。
- 決定: `finalNewline`（最終行の後に改行があったか）と `encoding`（判定結果）を足した。
- 理由:
  - `finalNewline` が無いと、**編集していないのに末尾 1 バイトだけ差分が出る**。
    これは AC2 違反の中で最も気付きにくい形。
  - `encoding` は AC10 の判定結果を呼び出し側へ伝えるために要る。
    Shift_JIS が偶然 UTF-8 として妥当になった場合に**呼び出し側が気付けるようにする**
    （黙って隠さない）。
- 影響: spec の型定義との差分。D1 と同様、親の統合 review に上げる。

## D4: Shift_JIS の往復バイト比較はコアのテストで行わない

- 背景: 往復テストは**バイト列比較**で行う方針だが、Node の `Buffer` は
  Shift_JIS への**エンコード**を持たない（`TextDecoder` はデコード専用）。
- 決定: Shift_JIS フィクスチャについては**モデルの同一性**（UTF-8 版と一致すること）までを
  コアのテストで確認し、バイト単位の書き戻しは検証しない。
- 理由 / 代替案: エンコード用の依存（`iconv-lite` 等）を入れれば可能だが、
  **コアを依存ゼロに保つ価値のほうが大きい**。
  実際に Shift_JIS で書き戻すのはファイルを扱う CLI の責務なので、**06-cli で扱う**。
- 影響: **AC10 の「読める」は検証済みだが、「Shift_JIS のまま書き戻せる」は未検証**。
  06-cli へ申し送る。

## D5: 実機の DDS メンバをフィクスチャに取り込んだ（ユーザー承認済み）

- 背景: 合成フィクスチャは自分が想定した形しか含まない。往復バイト不変を
  実世界の雑多な DDS で試せる価値が大きい。
- 決定: `ASAOLIB/QDDSSRC(GRIDTST3)` を UTF-8 へ変換して
  `packages/dds-core/test/fixtures/real-gridtst3.dspf` に置いた（5,625 バイト・86 行）。
- 理由: この 1 本に **CRLF 改行・継続行（`+`）・8 つのレコード様式・`WINDOW`/`GRDBOX`/`GRDLIN` の
  ネストした括弧・`'+-+||+-+'` のような特殊文字を含む定数・空白だけの定数**が入っている。
  合成では思いつかない組み合わせで、実際に**パーサの穴（D2）を炙り出した**。
- 影響: リポジトリに実機由来のソースが入る。ユーザーの承認を得て取り込んだ。
