# 決定記録

## D1: 表示幅を超える桁は末尾索引を返す（エラーにしない）

- 背景: `columnToCharIndex(text, column)` で、文字列の表示幅より右の桁を指されたときの扱いが
  plan / spec で明示されていなかった。
- 決定: `{ index: text.length, straddles: false }` を返す。エラーにしない。
- 理由 / 代替案: DDS のソース行は**空白で右詰めされる固定長**であり、「内容より右の桁を指す」のは
  正当な操作（フィールドを行末寄りに置く等）。ここでエラーにすると呼び出し側が
  常に長さを気にすることになる。一方、桁 0 以下は**桁が 1 始まりという規約の違反**なので
  `RangeError` を投げる（こちらは正当な操作ではない）。
- 影響: なし。挙動は JSDoc に明記済み。

## D2: サロゲートペアの後続コード単位を指されたら、先頭側の開始桁を返す

- 背景: `charIndexToColumn(text, index)` で、サロゲートペアの 2 つ目のコード単位を指されたときの
  扱いが未定義だった。判定範囲はすべて BMP なので DBCS にはならないが、
  2 コード単位を消費する文字は存在しうる。
- 決定: その文字の**開始桁**を返す（先頭側へ寄せる）。
- 理由 / 代替案: 代替は `RangeError`。しかし索引の途中を指すのは呼び出し側の軽微な誤りであり、
  例外にすると扱いが重い。**桁 → 索引の方向には `straddles` があるので、跨ぎの検出はそちらで行える**。
  なお EBCDIC に対応する文字が無いため、実務の DDS では現れない経路。
- 影響: なし（テストで挙動を固定済み）。
