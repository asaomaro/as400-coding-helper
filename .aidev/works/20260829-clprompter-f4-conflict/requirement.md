# 要件: clPrompter との F4 衝突を確かめる

## 背景 / 課題

`CozziResearch.clprompter`（= `bobcozzi/clPrompter`）は **IBM の拡張パック同梱**で、
**F4 に割り当てられている**。本 PJ も F4 でプロンプターを開く。
併用時に何が起きるかが**未確認**のまま残っていた
（`docs/research/code-for-ibmi.md`「F4 の衝突。clPrompter と併用された場合の挙動は未確認」）。

## 目的 / ゴール

**どのファイルで衝突し、どちらが勝ち、利用者がどう直せるかが分かっている状態。**

紐づく charter ゴール: 「横断する技術的負債の解消」（競合との差を再現できる事実として残す）。

## ユーザーストーリー

- US1: **IBM の拡張パックと併用する利用者**として、F4 が思ったのと違うものを開いたときに
  理由と直し方が分かってほしい。なぜなら、**どちらが勝つかは拡張の読み込み順**で決まり、
  利用者側からは原因が見えないから。（受け入れ: AC1, AC2, AC3）

## スコープ

### 対象
- 両拡張の `when` 句を**実際のマニフェストから**突き合わせる。
- どのファイル種別で重なるかを表にする。
- 利用者側の回避手段を書く。

### 対象外
- **本 PJ の挙動を変えること**。衝突の確認が目的で、譲るかどうかは別の判断。
- clPrompter 側への働きかけ。

## 完了条件 (受け入れ基準)

- [ ] AC1: 両者の `when` 句を**一次情報（マニフェスト）から**引いて記録している。
- [ ] AC2: **どの拡張子で重なるか**が根拠つきで表になっている。
- [ ] AC3: 利用者が直せる具体的な手段（`keybindings.json` の記述）が書いてある。
- [ ] AC4: 調査文書の「未確認」が事実に置き換わっている。
