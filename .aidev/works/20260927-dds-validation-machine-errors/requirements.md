# 要件: 検証を実機の誤りに揃える

## 背景 / 課題
2026-09-27 の実操作調査（`docs/research/20260927-dds-editor-exploration/findings.md` の D18）で、DDS ビジュアルエディタの検証タブ・lint が、
実機で重大度 20 以上になった誤り（CPD7443 潜在フィールドに位置 / CPD7490 SFLCLR 等に条件なし / CPD7508 リテラルが閉じない）を 1 つも指摘しなかった。
どれもソースの形だけで判定できる。帳票の使用 `B`（CPD7410）も同じ（同じバッチの帳票の件で実機確認）。

## 目的 / ゴール
実機が作成しない形を、エディタの検証タブと lint が実機に持っていく前に指摘する。実機で通るソースには出さない。

紐づく charter ゴール: DDS の桁支援（ビジュアルエディタ・lint）

## 完了条件 (受け入れ基準)
- [ ] AC1: 条件が必須のキーワード（原典から生成。SFLCLR / SFLDLT / SFLEND）に条件が無いと指摘する。条件があれば指摘しない（単体テスト）。
- [ ] AC2: 位置を持てない使用（画面 H・P・M、帳票 P）に位置があると指摘する（単体テスト）。
- [ ] AC3: 帳票の使用が 空白・O・P 以外なら指摘する（単体テスト）。
- [ ] AC4: 80 桁目までに閉じず次の行にも続かないリテラルを指摘する。継続（`-` / 継続記号なし）と 81-100 桁の注記は咎めない（単体テスト）。
- [ ] AC5: 検証タブに出る（GUI e2e）。lint の規則として既定で有効（設定で切り替えられる）。
- [ ] AC6: 実機で通ったリポジトリ内の DDS（docs/src・実機検証の見本）に新しい指摘が 0 件。実機で作成できなかった見本はすべて指摘される。
