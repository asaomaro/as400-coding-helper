# 要件: 5250 の配色でキャンバスを描く

## 背景 / 課題

DSPF の見え方は **`COLOR` と `DSPATR`** で決まる。実機の画面は緑・白・赤・空・黄・ピンク・青の
7 色と、反転表示・下線・明滅・非表示・桁区切り線の組み合わせで出る。

デザイナのキャンバスは**すべて同じ色**で描いている。そのため:

- **`COLOR(RED)` と `DSPATR(RI)` の効き方が画面から分からない。** キーワードを読めるように
  したので何が書いてあるかは分かるが、**どう見えるか**は実機に出すまで分からない。
- **組み合わせの落とし穴が見えない。** 原典は
  「`UL`・`HI`・`RI` の 3 つを同時に指定すると `ND`（非表示）と同じ結果になる」と書いている。
  **書いたのに出ない**という事故が、コンパイルも通り、画面にも警告が出ないまま起きる。
- `COLOR` を書かずに `DSPATR(CS/HI/BL)` を書くと**色が変わる**（原典の表）。
  「強調したかっただけなのに白になった」が読めない。

紐づく charter ゴール: **DDS（DSPF/PRTF）の視覚的な確認と編集**を第 4 の柱として加える。

## 目的 / ゴール

**キャンバスが実機と同じ配色で出ている状態**。`COLOR` / `DSPATR` を変えると、
その場で見え方が変わる。

**「書いたのに出ない」組み合わせが画面で分かる状態**（`UL`＋`HI`＋`RI` ＝ 非表示）。

## ユーザーストーリー

- US1: DSPF を直す開発者として、**実機と同じ色で見たい**。
  なぜなら、いまは色を変えるたびに実機に出して確かめており、往復が 1 回増えるから。
  （受け入れ: AC1, AC2, AC4）
- US2: DSPF を直す開発者として、**非表示になる組み合わせに気づきたい**。
  なぜなら、`DSPATR(UL HI RI)` はコンパイルも通り警告も出ず、
  **実機に出して初めて「消えている」と分かる**から。（受け入れ: AC3）
- US3: DSPF を読む開発者として、**配色を切れるようにしたい**。
  なぜなら、桁を数えたいときは色より**桁の見やすさ**が要るから。（受け入れ: AC5）

## スコープ

### 対象
- `COLOR` / `DSPATR` から**実機の表示属性**を解決する（原典の対応表に基づく）。
- キャンバスをその配色で描く。切替できるようにする。
- 非表示になる組み合わせを**それと分かる形**で出す。

### 対象外
- **条件標識で切り替わる `COLOR` / `DSPATR`**（`50 COLOR(RED)` のような形）。
  条件の解決は済んでいるが、**キーワード単位の条件**は `toLogicalUnits` が捨てている
  （`20260826-dds-indicators` の research F3）。別の話として backlog に残す。
- `DSPATR(&P フィールド)`（プログラムが実行時に決める）。ソースからは決まらない。
- `CHGINPDFT` によるファイル/レコード・レベルの既定の変更。
- 明滅の**アニメーション**（点滅させない。目に障る）。
- PRTF（色の概念が違う）。

## 機能要件

- 色は原典の 7 色（`GRN` `WHT` `RED` `TRQ` `YLW` `PNK` `BLU`）。
- `COLOR` を書かない場合、色は **`CS` / `HI` / `BL` の組み合わせ**で決まる（原典の表）。
- `UL` ＋ `HI` ＋ `RI` は**非表示**として扱う（原典: 「`ND` を指定した場合と同じ結果」）。
- 反転表示・下線・桁区切り線・明滅・非表示を、それと分かる形で描く。
- **対応表は原典から生成する**（手で書かない）。

## 非機能要件 / 制約

- **既定は今までと同じ見え方**にはしない——配色は既定で**入**にする
  （実機の見え方を出すのがこの機能の目的で、切りたい人だけが切る）。
- 対応表の出所は**原典**（`docs/origin/dds/detail/rzakc_rzakcmstdfdspat.htm` の
  16 進表と、`…dfcolor.htm` の色の表）。
- core は `vscode` を import しない。**ファイルも読まない**（生成した JSON を束ねる）。
- 明滅は**点滅させない**（静的な印で示す）。
