# 計画: 5250 の配色

## 作業順序と依存関係

1. 原典から対応表を生成（`generate-dds-attributes.mjs`）— 依存なし
2. 検査（`verify-dds-attributes.mjs`。原典の 2 表の一致まで）— 依存: 1
3. core（キーワード → 見え方）— 依存: 1
4. **実機との突き合わせ**（全通り）— 依存: 3 ← ここで規則を確定する
5. 描画モデルに載せる — 依存: 3
6. UI（配色と切替）— 依存: 5
7. 単体テスト — 依存: 3, 4
8. GUI e2e — 依存: 6
9. 記録 — 依存: 全部

**4 を 5 より先に置く**のが要点。原典の散文（「無視されます」）から規則を起こすと
必ずどこかを取り違えるので、**UI を作る前に実機で確定させる**。

## リスク / 留意点

- **原典の 2 つの表が食い違う**（16 進表の「完全な色」欄と COLOR ページの表）。
  一致するところだけを使い、食い違う `桁区切り線` はモデルに入れない。
- **原典と実機が食い違う**（`COLOR` ＋ `RI` ＋ `UL`）。実機を採り、根拠を残す。
- 表の抽出で脚注番号を値に混ぜない（`空1` → `空`）。
- 配色を既定で入れるので、**いままでの見え方が変わる**（requirement で決めた）。

## テスト方針

- **単体**（`test/unit/dspfAttributes.test.ts` 新規）: 7 色 / 色の表 8 通り /
  反転・下線 / 非表示の 2 経路 / `COLOR`＋`RI`＋`UL` / 効かないキーワード /
  **DSPATR 全 32 通りが 32 個の別のバイトになる**。
- **原典検査**: `npm run verify` に足す（原典の 2 表の一致）。
- **実機**: 全 61 通り（7 色 × 4 ＋ 32 ＋ ND）を画面の属性と突き合わせる。
- **GUI e2e**: 既定で入 / 色が付く / **桁と位置が変わらない** / 非表示 / 切替。
