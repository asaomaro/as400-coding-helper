# 決定記録

## D1: 最新の v6.0.2.r ではなく v4.0.3.r を入れた（判断を 2 度覆した）

- 背景: 当初「最新（v6 系）は V7R5 ビルドなので 7.3 に入らない」と報告し、ユーザーは
  v4.0.3.r を選んだ。その後 `DSPSAVF` で v6 の `TGTRLS` が `V7R3M0` と分かり、
  「最新が入る」と訂正してユーザーは v6 を選び直した。実際に導入もできた（34 オブジェクト）。
  ところが `RUCRTRPG` が **7.3 に存在しない `TGTCCSID` キーワード**を発行して失敗した。
- 決定: **v4.0.3.r を入れる**（＝ユーザーの当初の選択に戻す）。
- 理由 / 代替案: `TGTRLS(V7R3M0)` は**保存形式の互換**であって、コマンドが発行する
  キーワードの互換ではない。v6 は復元できても 7.3 ではビルドできない。
  ソースから 7.3 向けにビルドし直す案は工数が大きく、当面の目的
  （固定長で書けるか・出力形式は何か）には v4.0.3.r で足りる。
- 影響: 3 年前の版になる。原典（現行ドキュメント）は v6 向けなので記述が食い違う場面がある。

## D2: バイト列から `TGTRLS` を判定したのは誤りだった

- 背景: SAVF を cp037 で読んで `V7R5M0` / `V7R3M0` の文字列を数え、それを復元可否の
  根拠にした。**これはオブジェクトの作成リリース**で、`TGTRLS` ではない。
- 決定: **判定は `DSPSAVF` の `Release level` で行う。**
- 理由: 実測で両者が食い違った（v4: 文字列 `V7R3M0` / `TGTRLS` は `V7R1M0`。
  v6: 文字列 `V7R5M0` / `TGTRLS` は `V7R3M0`）。
- 影響: ユーザーに誤った前提で選択させ、選び直しを 1 往復増やした。
  **「原典・実機で確かめる」を、バイト列を眺めることで代替しようとしたのが原因。**

## D3: 混在した `RPGUNIT` は `CLRLIB` で入れ直した（`DLTLIB` は使えなかった）

- 背景: v6 の上に v4 を `RSTLIB` したところ、`DLTLIB` が `CPF2113` で失敗したまま
  `RSTLIB` が走り、**v4 のプログラムと v6 のソース物理ファイルが混在**した
  （21 復元 / 11 は `CPF3283` で拒否）。
- 決定: `CLRLIB RPGUNIT` → `RSTLIB` で素の v4 に入れ直した（32 オブジェクト・拒否ゼロ）。
- 理由 / 代替案: ロックの主は `QZRCSRVS` の**事前開始ジョブ 2 本**（`ADDLIBLE` の名残で
  `*SHRRD` を保持）。`ENDJOB` で落とせば `DLTLIB` は通るが、**他人の接続を巻き込む**。
  `CLRLIB` はライブラリーの排他を要さないので通り、目的は同じく達せられる。
- 影響: 手順としては `CLRLIB` → `RSTLIB` を正とする（spec「エラー処理」に反映）。

## D4: 非対話のジョブが `MSGW` で残った件

- 背景: CL の `MONMSG` を `RUCALLTST` の行にしか付けておらず、`RUCRTRPG` の失敗が
  関数チェック（`CPF9999`）になって照会メッセージを出し、**バッチジョブが `MSGW` で
  150 秒以上残った**。
- 決定: `ENDJOB … OPTION(*IMMED)` で即座に片付け、以後は
  `SBMJOB … INQMSGRPY(*DFT)` を必ず付ける。
- 理由: 利用者の機械に応答待ちのジョブを残さない。**非対話の経路では、監視していない
  例外は必ず照会になって固まる**と考えて組む。
- 影響: spec「エラー処理」と plan「リスク」に明記した。
