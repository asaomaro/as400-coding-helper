# 要件: RPGUnit を SR-OSAKA に導入する

## 背景 / 課題

RPGUnit（iRPGUnit）は IBM i 上の RPG 単体テスト・フレームワーク。本 PJ の設計書 4.2 が
「AI にテストを書かせる場合の方針」の実行基盤として想定しているが、**どこにも入っていない**。
pub400 は不可と確定済み（`20260829-rpgunit-pub400-feasibility`。`RSTLIB`/`RSTOBJ`/`CRTLIB` が
すべて `CPF9802`）。SR-OSAKA なら `*ALLOBJ`＋`*SAVSYS` があり標準経路で入る。

さらに**本 PJ 固有の未確認事項**がある。原典の例はすべて `**free` で、
**固定長（H/P/D/C 仕様）でテストが書けるかの実例が無い**。本 PJ の対象は固定長だけなので、
書けなければ RPGUnit は本 PJ の用途に使えない。

## 目的 / ゴール

SR-OSAKA で **固定長の RPG 単体テストが書けて・コンパイルできて・実行結果が採れる**状態。
併せて `RUCALLTST` の出力形式が分かっており、後段（CI・AI によるテスト生成）が
何を読めばよいか決められる状態。

紐づく charter ゴール: 主要 3 本柱を支える検証基盤（`品質基準`「テスト通過」）。

## ユーザーストーリー

- **US1**: 本 PJ の開発者として、固定長 RPG のテストを実機で走らせたい。
  なぜなら、**桁位置の支援が正しいかを最終的に決めるのは実機のコンパイラと実行結果**だから。（AC1〜AC4）
- **US2**: 後段の自動化を書く者として、`RUCALLTST` の**出力の形**を知りたい。
  なぜなら、失敗は `CPF9897` の例外で伝わり EVFEVENT とは別経路なので、
  何を parse するかを決めないと CI に載せられないから。（AC5）

## スコープ

### 対象
- SR-OSAKA への RPGUnit 導入（既定ライブラリー名 `RPGUNIT`）。
- 固定長のテストケースでの動作確認（合格・失敗の両方）。
- `RUCALLTST` の出力形式の採取。

### 対象外
- pub400 への導入（不可と確定済み）。
- CI への組み込み、AI によるテスト生成の方式策定（いずれも別項目）。
- Eclipse / RDi プラグイン側の導入。

## 完了条件 (受け入れ基準)

- [ ] **AC1**: SR-OSAKA に RPGUnit のライブラリーが導入され、主要オブジェクト
      （`RUCALLTST` / `RUCRTRPG` / `RUTESTCASE`）が揃っている。
- [ ] **AC2**: **固定長**（`**free` でない）の RPG ソースが RPGUnit の include を
      `/COPY` してコンパイルできる。**対照として `**free` 版も併せて確かめる**。
- [ ] **AC3**: 固定長のテスト・サービスプログラムが `RUCRTRPG` で作成できる。
- [ ] **AC4**: `RUCALLTST` で実行でき、合格と失敗が正しく区別される。
- [ ] **AC5**: `RUCALLTST` の出力形式が記録されている（件数・失敗の書式・ソース位置）。
- [ ] **AC6**: 作業で作った一時オブジェクト・IFS ファイルを片付けてある
      （スプールは消さず名前を報告する）。
