# レビュー: DDS の操作を CLI に載せる

## ラウンド 1（2026-08-27）

### 要件適合
- AC1 ✓ `parse` が様式・項目・桁・キーワード・条件を JSON で出す。
- AC2 ✓ `render --format text` が桁の合った絵を出す（DBCS・非表示を含む）。
- AC3 ✓ `patch` は 2 段で断る（**書けない** / **書けるが画面が壊れる**）。
  1 つでも引っかかれば何も書かない。
- AC4 ✓ `--write` で書き換え、宛先以外の行は 1 バイトも変わらない（テストで固定）。
  改行コードと末尾改行も保つ。
- AC5 ✓ 画面（`.dspf`）と帳票（`.prtf`）の両方。用紙は `--page-*` で指定できる。
- AC6 ✓ 0 / 1 / 2 の規約は `lint.js` と同じ。

### 価値適合
狙いは「エージェントが桁を数えずに DDS を扱える」。
**`render --format text` がその中心**——固定長のソースを読むのと、絵を見るのは別物で、
DBCS が混じると人も機械も数え間違える。

そして**CLI を通した瞬間に穴が 1 つ出た**（1 桁目への移動が通る。`decisions.md` D2）。
GUI ではキャンバスが桁を持つので到達しにくく、見えていなかった。

### 正確性
- 置き換え指示を**後ろから**当てる（前からだと後続の行番号がずれる）。
- 拒否は JSON でも読める形（エージェントが `code` で分岐できる）。
- 指摘の増分で止める設計は、規則を 1 つも写さず `resolveDspfLayout` を唯一の真実源に保つ。
  元からある指摘は数えない（「1 か所も直せない」を避ける）。

### 規約適合
- **`validate` を作らなかった**（D1）。lint が同じ判定を出しており、
  2 つ目の入口は「どちらが正か」を生む。
- 拡張子を CLI に数え上げず `resolveDdsType` に委ねた。
- 桁の書き戻しは `ddsEdit` / `ddsEditWriteBack` に任せ、CLI では 1 桁も数えていない。

### 保守性
`lint.ts` の骨格（`UsageError` / `run(argv): number` / `require.main` 判定）を
そのままなぞったので、2 つの CLI が同じ読み方で読める。

### 指摘
must 0 / should 0 / nit 0。

GUI からは到達しにくいが穴ではあるので backlog に残した。
