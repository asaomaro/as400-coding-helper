# 計画: DDS の操作を CLI に載せる

## 実装方針
`lint.ts` の骨格（引数解析 → `run()` → 終了コード）をなぞる。
コマンドごとの処理はコアを 1 回呼ぶだけにする。

## 作業順序と依存関係
1. 引数解析と `run()` の骨格（依存: なし）
2. `parse`（依存: 1）
3. `render`（json → text の順。text は絵の組み立てがある）（依存: 1）
4. `patch`（依存: 1）
5. package.json のスクリプト（依存: 1）
6. テスト（`run()` を直接呼ぶ）（依存: 2-4）

## リスク / 留意点
- 置き換え指示を**前から**当てると行番号がずれる。後ろから当てる。
- 改行コードと末尾改行を保つ（保たないと差分が全行になる）。
- 絵の桁数え。`segments.cols` をそのまま使い、CLI で `printWidth` を呼び直さない。

## テスト方針
- `run()` を直接呼び、標準出力を捕まえて検査する（プロセスを起こさない）。
- **触っていない行が 1 バイトも変わらない**ことを見る。
- 拒否されたときに**ファイルが変わっていない**ことを見る。
- 画面と帳票の両方で走らせる。
