# 要件: DDS の操作を CLI に載せる

## 背景 / 課題

いまの CLI は **lint だけ**（`out/cli/lint.js`）。DDS を**読む・描く・直す**手段が
VSCode の中にしかない。

コア（`src/core/dds/`）は既に `vscode` を import しない純粋なコードで、
GUI エディタも単独起動ハーネスもそこに載っている。**CLI だけが無い。**

## 目的 / ゴール

**VSCode を起動せずに、DDS の中身を読み・画面の絵を得て・編集を当てられる状態。**

紐づく charter ゴール: DDS の視覚的な確認と編集（第 4 の柱）。

## ユーザーストーリー

- US1: AI エージェントとして、**DDS がどう見えるかをテキストで受け取りたい**。
  なぜなら固定長のソースを読んでも桁が頭に入らず、**DBCS が混じると数え間違える**から。（受け入れ: AC2）
- US2: AI エージェントとして、**編集を桁を数えずに当てたい**。
  なぜなら 30-34 桁の右寄せや 45-80 桁の折り返しを自前で書くと必ずずれるから。（受け入れ: AC3, AC4）
- US3: この PJ を直す開発者として、**GUI を起動せずにコアの挙動を確かめたい**。
  なぜなら WebView を開くのは遅く、差分の確認に向かないから。（受け入れ: AC1, AC2）

## スコープ

### 対象
- `parse` — 様式と項目（`buildDspfOutline`）を JSON で
- `render` — 描画モデルを JSON で、または**画面の絵をテキストで**
- `patch` — 編集（`DdsEdit[]`）を検証して当てる

### 対象外
- `validate` — **`lint` が既に同じ判定を出している**（`src/lint/rules/layout.ts` が
  `resolveDspfLayout` / `resolvePrtfLayout` をそのまま包んでいる）。
  同じ判定に 2 つ目の入口を作らない（AGENTS.md「同じ概念集合を複数箇所で列挙しない」）。
- 対話的な編集・undo（GUI の仕事）

## 完了条件 (受け入れ基準)

- [ ] AC1: `parse` が様式・項目・桁・キーワード・条件を JSON で出す
- [ ] AC2: `render --format text` が**桁が合った画面の絵**を出す（DBCS を含めて）
- [ ] AC3: `patch` が編集を検証し、**当てられないものは理由つきで拒否**して何も書かない
- [ ] AC4: `patch --write` が元のファイルを書き換え、**触っていない行は 1 バイトも変わらない**
- [ ] AC5: 画面（`.dspf` / `.mnudds`）と帳票（`.prtf`）の両方で動く
- [ ] AC6: 終了コードが lint と同じ規約（0=成功 / 1=拒否あり / 2=使用法・入出力エラー）
