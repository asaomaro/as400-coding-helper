# 要件: CAnn / CFnn がキーワードのデータから丸ごと落ちているのを直す

## 背景 / 課題

DDS キーワードの補完データ（`resources/completion/dds-keywords{,.en}.json`）は
原典の索引ページから生成している。その**名前の取り出しが大文字しか受け付けない**ため、
原典が `CAnn` / `CFnn`（`CA01`-`CA24` / `CF01`-`CF24` の総称）と書いている 2 件が
**丸ごと落ちていた**。

- `CF03` は**実サンプル（`docs/src/CUSTMNT.dspf`）にも書かれている**、DSPF で最も使われる部類の
  キーワードで、それが**補完にもヘルプにも出てこない**。
- 落ちていたのに `verify-dds-keywords.mjs` は通っていた。件数の下限（原典のリンク数の 7 割）で
  見ていたため、**1〜2 件の欠落では割らない**。
- 詳細ページ（構文の出所）も、同じ取り出しを使う経路で拾われるため**取得されていなかった**。

紐づく charter ゴール: **プロンプター定義の拡充 / 横断する技術的負債の解消**（原典との齟齬）。

## 目的 / ゴール

**原典の索引に名前として書かれているキーワードが、1 件も欠けずにデータに入っている状態**。
そして、**次に同じ落ち方をしたら検査で止まる**状態。

## ユーザーストーリー

- US1: DSPF を書く開発者として、**`CFnn` の補完とヘルプが出てほしい**。
  なぜなら、機能キーの割り当ては DSPF で必ず書くもので、
  いまは**最も使う部類のキーワードだけが候補に出てこない**から。（受け入れ: AC1, AC2）
- US2: 原典データを保守する開発者として、**取りこぼしを検査で止めたい**。
  なぜなら、今回の欠落は**件数の下限では検出できず**、
  たまたま別の作業で気付くまで残っていたから。（受け入れ: AC3, AC4）

## スコープ

### 対象
- 生成側 2 本（索引・構文）の名前の取り出し。
- 取得できていなかった詳細ページ 4 件（日英 × CAnn / CFnn）。
- 補完データの再生成（日英）。
- 検査の強化（**名前で突き合わせる**）。

### 対象外
- `CAnn` を `CA01`-`CA24` の 24 件に展開すること。**原典の書き方をそのまま持つ**
  （展開すると 1 キーワードが 48 件に膨れ、原典との対応も崩れる）。
- 補完の挿入形（`CAnn` を選んだときに `nn` を埋める補助）。別の話。
- 他の生成データ（RPG・CL）の同種の取りこぼし調査。

## 完了条件 (受け入れ基準)

- [ ] AC1: `CAnn` / `CFnn` が日英の DSPF キーワードデータに入っている（和名・レベル・構文・説明つき）。
- [ ] AC2: 既存の 174 件は**1 件も内容が変わらない**（追加だけ）。
- [ ] AC3: `verify-dds-keywords.mjs` が、**原典の索引にある名前がデータに無ければ落ちる**。
- [ ] AC4: 修正前のデータをその検査にかけると**実際に落ちる**（検査が効くことの確認）。
- [ ] AC5: `npm run verify` が通る。
