# 決定記録

## D1: 工程の順序が前後した（先に欠落を見つけてから文書を書いた）

- 背景: 別の work（`20260826-dds-keyword-help`）の調査中に、
  カタログを原典の索引と突き合わせて `CAnn` / `CFnn` の欠落を見つけた。
  その時点で原因（大文字しか受け付けない正規表現）まで判明していた。
- 決定: この work を切り出し、**実装のあとで requirement / spec / plan を書いた**。
- 理由 / 代替案: 見つけた欠落を元の work に混ぜると、
  **200KB の再生成 JSON の差分が UI の PR に混ざる**（レビューが成立しない）。
  切り出しは正しいが、切り出した時点で既に直っていた。文書は**事実に合わせて**書いた。
- 影響: `metrics.yml` の工程の所要時間は実態を表さない（retro で読むときの注意）。

## D2: 詳細ページ 4 件の取得元

- 背景: `CAnn` / `CFnn` の詳細ページ（構文の出所）は**取得されていなかった**
  （索引の取り出しが同じ正規表現を使うため、名前ごと落ちていた）。
- 決定: 既存の経路と同じ IBM Documentation のコンテンツ API から取得した。

  | 保存先 | URL |
  |---|---|
  | `docs/origin/dds/detail/rzakc_rzakcmstdfcann.htm` | `https://www.ibm.com/docs/api/v1/content/ssw_ibm_i_74%2Frzakc%2Frzakcmstdfcann.htm?parsebody=true&lang=ja` |
  | `docs/origin/dds/detail/rzakc_rzakcmstdfcfnn.htm` | 同上（`…dfcfnn.htm`） |
  | `docs/origin/dds-en/detail/rzakc_rzakcmstdfcann.htm` | 同上（`lang=en`） |
  | `docs/origin/dds-en/detail/rzakc_rzakcmstdfcfnn.htm` | 同上（`lang=en`・`…dfcfnn.htm`） |

  取得日: 2026-08-27。いずれも HTTP 200。
- 理由 / 代替案: `manifest.yml` には載せない——**DDS の詳細ページは元から対象外**
  （索引ページ 6 件だけが載っている）。ここだけ載せると扱いが不揃いになる。
- 影響: `docs/origin/README.md` の件数を 285→287 / 291→293 に直した。

## D3: `CAnn` を 24 件に展開しない

- 背景: 利用者が書くのは `CA03` で、データにあるのは `CAnn`。
- 決定: **原典の書き方をそのまま持つ**（1 件）。
- 理由 / 代替案: 展開すると `CA01`-`CA24` ＋ `CF01`-`CF24` で 48 件に膨れ、
  補完の一覧が機能キーで埋まる。さらに**原典との 1:1 対応が崩れ**、
  次に原典が変わったときの突き合わせができなくなる。
  `CA03` から引き当てたい側は、**末尾 2 桁を `nn` に正規化して引く**（利用側の責務）。
- 影響: この work の対象外だが、キーワードのヘルプを出す work
  （`20260826-dds-keyword-help`）は 2 段の引き当てが要る。そちらの spec に申し送る。

## D4: 検査は「件数」ではなく「名前」で突き合わせる

- 背景: 既存の検査は原典の索引リンク数の **7 割**を下限にしていた。
  174 件に対して 2 件の欠落は、この下限では**絶対に検出できない**。
- 決定: 索引から**名前を取り出して**データと突き合わせ、欠けていれば落とす。
  取り出しの規則は**生成側と同じ**にした。
- 理由 / 代替案: 下限を厳しくする（例 99%）案は、原典の索引にキーワード以外のリンクが
  混ざる以上、閾値の調整が続くだけで**何が欠けたかを言えない**。
- 影響: 修正前のデータでこの検査を走らせると実際に落ちる（`test.md` AC4）。
  今後、生成側が特定の綴りを落とせば `npm run verify` で止まる。
