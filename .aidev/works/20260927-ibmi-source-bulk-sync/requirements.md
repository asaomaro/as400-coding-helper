# 要件: ソース・ファイル単位でメンバーを一括で送受信する

## 背景 / 課題
いまの IBM i 同期（`rpgClSupport.ibmiSourceSync.upload/download`）は**開いている 1 メンバーだけ**を送受信する。
2026-09-27 利用者の依頼で、`QRPGSRC` などのソース・ファイル ⇔ ローカルのフォルダ（`src/<LIB>/<SRCFILE>/`、既存と同じ対応づけ）
の単位で、転送元のメンバーを一覧してチェックボックスで選び、転送先の有無・情報を見て、差分も確かめてから送受信できるようにする。

決定（1 件ずつ確認。backlog `workflow.md` に記録）: 専用の画面（表）/ 起動はフォルダの右クリックとコマンドパレットの両方 /
状態は更新日時の新旧だけ（記録ファイルは持たない）/ 転送先の方が新しいものを上書きするときだけ確認 /
新規ダウンロードのファイル名は `メンバー名-テキスト記述.<ソース・タイプ小文字>`。

## 完了条件 (受け入れ基準)
- [x] AC1: IBM i のメンバー一覧（名前・ソース・タイプ・テキスト記述・行数・更新日時）を SSH の 1 コマンド（`RUNSQL` → `QSYS2.IFS_WRITE_UTF8` の UTF-8 JSON）で取る。
      日時は UTC に直す。ソース・ファイルが無い（ソースでない物理ファイルを含む）ことを見分ける（単体テスト・実機で SQL と対照）。
- [x] AC2: ローカルのフォルダの一覧（既存の `resolveMemberTarget` が読めるファイル）と突き合わせ、行ごとに転送元・転送先の日時・行数・記述と、
      どちらが新しいか（秒単位。同じ時刻は「同じ」）を出す。同じメンバーのファイルが複数ある・名前が読めないファイルは選べず理由を出す（単体テスト）。
- [x] AC3: 専用の画面（WebView）で、向き（ダウンロード／アップロード）を切り替え、チェックボックスで選び（全選択あり）、転送できる。
      行の「差分」で VS Code の差分エディターを開く（左 = 転送先・右 = 転送元）（GUI e2e・単体テスト）。
- [x] AC4: 転送先の方が新しいメンバーを上書きするときだけ、名前を並べて確認する（単体テスト）。
- [x] AC5: ダウンロードで新しく作るファイルは `メンバー名-テキスト記述.<ソース・タイプ小文字>`。記述がファイル名に使えない文字を含む・空ならメンバー名だけ。
      ソース・タイプが空なら `.txt`。転送後はローカルの更新日時を IBM i の更新日時に揃え、転送した直後は「同じ」と出る（単体テスト）。
- [x] AC6: 起動はエクスプローラーの `src/<LIB>/<SRCFILE>` フォルダの右クリックと、コマンドパレット（ライブラリー・ソース・ファイルを入力）の両方。
      未保存の変更があるファイルは転送しない（理由を出す）（統合テスト・単体テスト）。

## スコープ外
- 前回の転送の記録（利用者が「更新日時の新旧だけ」を選んだため）。
- SSH 経路そのものの実機確認（検証環境は host server 経由で、SSH 接続情報を使えない。既存の同期も同じ制約）。
