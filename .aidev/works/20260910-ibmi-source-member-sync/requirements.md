# 要件: IBM i ソースメンバーの手動同期と SEU 色属性の保持

## 背景 / 課題

IBM i のソースは IFS ではなく、ライブラリー内のソース物理ファイルとメンバーで管理される。VS Code で編集するローカルのコードベースと IBM i 上のソースメンバーの対応が明示されていないため、編集結果を安全かつ一貫して送受信しにくい。

既存メンバーには、5250/SEU で行や行内を色分けするための属性が埋め込まれているものがある。一般的な文字列転送ではその属性を失う、または識別・編集できないため、VS Code と IBM i の往復で属性を保持できない。

## 目的 / ゴール

開発者が VS Code で開いているローカルソースを IBM i のライブラリー／ソース物理ファイル／メンバーと対応付け、自身が設定した接続先へ明示的に送受信できる状態にする。SEU 色属性は VS Code 上で意味の分かる可視記号と色表示として扱え、往復後も IBM i 側の属性を失わない。

紐づく charter ゴール: IBM i ソースメンバー同期。

## ユーザーストーリー

- US1: IBM i 開発者として、`src/<LIB>/<SRCFILE>/<MEMBER>.<extension>` に置いたソースを、設定済みの IBM i 接続先の対応メンバーへアップロードしたい。なぜなら、VS Code の固定長編集支援で行った変更を実機のソース物理ファイルへ反映したいからである。（受け入れ: AC1, AC2, AC4, AC5）
- US2: IBM i 開発者として、対応する IBM i メンバーを現在開いているローカルファイルへダウンロードしたい。なぜなら、実機上の内容をローカルのコードベースへ取り込み直したいからである。（受け入れ: AC1, AC3, AC4, AC5）
- US3: SEU 色属性を使う開発者として、VS Code 上で赤属性を `Ŕ` のように識別・入力し、色付きでコードを読んだうえで IBM i へ戻したい。なぜなら、既存の色分け規約を失わずに VS Code でも利用したいからである。（受け入れ: AC9, AC10, AC11）

## スコープ

### 対象

- ワークスペース内の `src/<ライブラリー>/<ソース物理ファイル>/<メンバー>.<拡張子>` と、IBM i のライブラリー／ソース物理ファイル／メンバーの対応付け。
- 本拡張が管理する IBM i 接続先の host、port、ユーザー名、認証方式等の非機密設定と、その接続を使う SSH/SFTP ベースの送受信。
- パスワードまたは秘密鍵のパスフレーズなどの機密情報を、VS Code の暗号化されたシークレット保管領域に保存・削除する操作。
- 対応付け済みの現在のエディター上のファイルを対象にした、IBM i へのアップロードと IBM i からのダウンロード。
- 色属性バイトと可視記号（赤属性の `Ŕ` を含む）の可逆対応、記号のキーボード入力、記号に応じた VS Code 上の色表示。
- エディター右クリックメニューおよびコマンドパレットからの明示操作。
- 利用者が選んだ送信方向での上書き。保存時の自動同期はしない。

### 対象外

- Code for IBM i の接続プロファイル、認証情報、公開・非公開 API、内部 SFTP client の参照・再利用。
- IBM i 上のライブラリー、ソース物理ファイル、メンバーをブラウズ・選択してローカルツリーを生成する機能。
- フォルダーまたは複数メンバーの一括同期、継続的同期、更新日時による自動競合解決。
- コンパイル、デバッグ、実機上のオブジェクト操作。

## 機能要件

- 対応するパス形式の現在のローカルファイルから、転送先／元となる IBM i のライブラリー、ソース物理ファイル、メンバーを一意に解決できること。
- 接続に必要な非機密値を本拡張の設定から読み、機密値を設定 JSON、ログ、通知に保存・表示せずに認証できること。
- 利用者がアップロードを実行すると、現在のローカルファイルの内容を解決済みメンバーへ反映し、既存のメンバー内容を上書きすること。
- 利用者がダウンロードを実行すると、解決済みメンバーの内容で現在のローカルファイルを上書きすること。
- 色属性を含む受信内容を、対応する可視記号へ変換して表示できること。赤属性は `Ŕ` として識別・入力できること。
- 可視記号を含むローカル内容を送信すると、対応する元の色属性を IBM i 側へ復元できること。
- 色属性は元の位置を保ち、可視記号から次の色属性または行末まで、対応する色でコードを表示できること。
- コマンドは対応付けできるローカルファイルでのみ実行可能とし、非対応パス、未設定接続、認証失敗、到達不能、または変換不能時は理由と必要な利用者操作を通知すること。
- 転送の成功・失敗を利用者に通知し、失敗時にローカルまたは IBM i の内容を曖昧に成功扱いしないこと。

## 非機能要件 / 制約

- IBM i 側の正本はソース物理ファイルのメンバーであり、IFS は SFTP 転送時の一時経路としてのみ使用する。
- host、port、ユーザー名、認証方式、秘密鍵ファイルパス等の非機密値は、同期専用の VS Code 設定として管理する。パスワードと鍵のパスフレーズは settings JSON に書かない。
- 送受信と色属性の変換は Code for IBM i の導入有無に依存しない。
- 色属性の可視記号は固定長の1文字として扱い、送信時に属性バイトへ戻すことで固定長の桁位置を保つ。
- 日本語・DBCS を含む IBM i ソースと色属性を同時に転送しても、通常文字、属性位置、固定長の内容を失わないこと。
- 既存のルーラー、SOSI、プロンプター、DDS 機能を妨げないこと。

## 完了条件 (受け入れ基準)

- [ ] AC1: `src/TESTLIBL/TESTSRC/TESTRPG.rpg` を開いたとき、同期対象が `TESTLIBL/TESTSRC` の `TESTRPG` メンバーとして一意に解決される。
- [ ] AC2: 対応付け済みファイルでアップロードを実行すると、IBM i の対応メンバーがローカル内容で上書きされ、成功または失敗が通知される。
- [ ] AC3: 対応付け済みファイルでダウンロードを実行すると、ローカルファイルが IBM i の対応メンバー内容で上書きされ、成功または失敗が通知される。
- [ ] AC4: Code for IBM i の接続設定が無くても、本拡張の設定済み接続先だけで同期でき、機密値が settings JSON や通知に現れない。
- [ ] AC5: 両コマンドはエディター右クリックメニューとコマンドパレットから実行でき、対応付けできないファイルでは実行理由を示す。
- [ ] AC6: 接続設定不足、機密情報未登録、認証失敗、または到達不能時、同期は実行されず、利用者が取るべき設定または接続操作を示す。
- [ ] AC7: 保存だけでは IBM i への送信も IBM i からの受信も起きない。
- [ ] AC8: 日本語・DBCS を含む対象ソースを送受信しても文字が欠落せず、固定長の内容を保てる。
- [ ] AC9: 赤の SEU 色属性を含むメンバーをダウンロードすると、元の属性位置に `Ŕ` が入り、`Ŕ` とその有効範囲が VS Code で赤系に表示される。
- [ ] AC10: VS Code で `Ŕ` を入力してアップロードすると、対応位置の IBM i メンバーに赤の色属性が復元され、属性前後の固定長の桁位置が変わらない。
- [ ] AC11: 調査で確定した全てのサポート対象色属性について、ダウンロード→無変更アップロードで属性種別・位置・通常文字が一致する。

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: エディター右クリックまたはコマンドパレットでアップロード／ダウンロードを開始し、確認ダイアログを挟まずに選んだ方向の上書き処理を完了または失敗通知で閉じる。
- [ ] AC-I2 確定 / 取り消し: コマンドの選択が確定操作であり、転送開始前に別途確認しない。利用者はコマンドを実行しなければ同期しない。
- [ ] AC-I3 キーボードだけで完結するか: コマンドパレットから対象コマンドを選び、色属性記号を直接入力して同期できる。
- [ ] AC-I4 フォーカスの行き先: 同期後も現在のエディターにフォーカスが戻る。
- [ ] AC-I5 既存の操作を妨げないか: 同期コマンドと色表示は対象エディターのコンテキストに限定し、既存の F4・タブ・保存操作を横取りしない。

## 未確定事項 / 確認したいこと

- 色属性の属性バイト、色・強調の意味、VS Code 上の可視記号の対応表を IBM i の一次資料と実機の生データで確定する。
- 色属性を失わずに source physical file member と一時 IFS ファイルを往復する、SSH/SFTP と IBM i コマンドの正確な経路・CCSID 指定を実機で確定する。
- password 認証と SSH 秘密鍵認証の両方について、VS Code のシークレット保管と接続 UI の利用手順を確定する。
