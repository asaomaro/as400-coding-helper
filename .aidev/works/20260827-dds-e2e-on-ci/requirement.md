# 要件: エディタの GUI e2e を CI に載せる

## 背景 / 課題

`dev/e2e.mjs`（単独起動ハーネスを**実操作する** 109 件）は**手元でしか走っていない**。

この e2e が受け持つのは、他のどのテストも見られない範囲——WebView の中は拡張ホストから
触れず、単体テストは `buildInitialState()` までしか見ない。**掴んで動かす・つまみで伸ばす・
チップを外す・標識を倒す**が実際に効くかは、ここでしか落ちない。

実際、この 3 日で e2e だけが捕まえた欠陥が複数ある（`moveColumn` が `parseEdit` に無く
ホストが黙って捨てていた件など。型検査も単体テストも通っていた）。

**手元で走らせ忘れれば、その保護は無い。**

## 目的 / ゴール

**PR ごとに GUI e2e が自動で走り、落ちたら止まる状態。**

紐づく charter ゴール: DDS の視覚的な確認と編集（第 4 の柱）。

## ユーザーストーリー

- US1: この PJ に PR を出す開発者として、**GUI が壊れたら PR で止まってほしい**。
  なぜなら壊れたことに気付くのが「次に誰かが手で走らせたとき」では遅すぎるから。（受け入れ: AC1, AC3）
- US2: この PJ を保守する開発者として、**CI の赤を信用したい**。
  なぜなら不安定なテストが混ざると**赤を無視する習慣**がつき、CI 全体が効かなくなるから。（受け入れ: AC2）

## スコープ

### 対象
- CI でブラウザを用意する（キャッシュ込み）
- `dev/e2e.mjs` を PR ごとに走らせる
- 不安定でないことを**先に測る**

### 対象外
- e2e の中身を増やす（別の話）
- `playwright-core` を `dependencies` に入れる（CI 以外では要らない）

## 完了条件 (受け入れ基準)

- [ ] AC1: PR と main への push で GUI e2e が走る
- [ ] AC2: **落ちたらそのジョブが失敗する**（非ブロッキングにしない）
- [ ] AC3: 再現率を実測し、記録として残す（**10 回連続で緑**が条件）
- [ ] AC4: ブラウザをキャッシュし、毎回ダウンロードしない
- [ ] AC5: 既存のジョブを遅くしない（別ジョブで並行に走る）
