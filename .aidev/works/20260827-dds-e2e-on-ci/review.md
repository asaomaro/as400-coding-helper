# レビュー: エディタの GUI e2e を CI に載せる

## ラウンド 1（2026-08-27）

### 要件適合
- AC1 ✓ `gui-e2e` ジョブ。`on:` はワークフロー全体（PR と main への push）を共有。
- AC2 ✓ `continue-on-error` を付けていない。前提不足も終了コード 2 で落ちる。
- AC3 ✓ 10 回連続緑を実測（`verify/stability-2026-08-27.txt`）。測り直しの手順も残した。
- AC4 ✓ `actions/cache` で `~/.cache/ms-playwright`。鍵は**固定した版**。
- AC5 ✓ `needs` を付けていないので `verify` と並行に走る。

### 価値適合
狙いは「GUI が壊ったら PR で止まる」。この e2e が受け持つのは他のどのテストも見られない
範囲で、実際にこの数日で e2e だけが捕まえた欠陥がある（`moveColumn` がホストに届かず
黙って捨てられていた件は型検査も単体テストも通っていた）。

**不安定なまま載せない**という backlog の条件を守った。守らないと赤を無視する習慣がつき、
CI 全体が効かなくなる——この項目の value はそこにあるので、**測ってから載せる**が本体。

### 正確性
- 版を固定しないとキャッシュの鍵が毎回変わり、キャッシュが意味を失う。
- `--with-deps` を付けない理由（sudo・遅い・`--no-sandbox` なので不要）を注記した。
- 「走らなかった」を「通った」と読み違えない（終了コード 2 で落ちる）ことを明記。

### 規約適合
`playwright-core` を依存に入れない方針は維持した。README の説明が古かった
（「CI にブラウザ本体が無く動かせない」）ので、実態に合わせて書き直した。

### 保守性
不安定になったときの方針を README に書いた——**非ブロッキングにするのではなく
原因を直すか外す**。ここを曖昧にすると、いずれ `continue-on-error` が足される。

### 指摘
must 0 / should 0 / nit 0。

**未検証**: CI 上で実際に緑になることは PR を出すまで確かめられない（AC1/AC4 の本番検証）。
PR の CI 結果で確認する。
