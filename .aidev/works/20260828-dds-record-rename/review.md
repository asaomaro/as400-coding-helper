# レビュー: 様式の改名と参照追随

## ラウンド 1（自己レビュー）

### 要件適合

- AC1 名前の欄が出て `R XXXX` が変わる → e2e 2 件 ＋ 単体 3 件。
- AC2 様式を指す参照も変わる → 単体 8 件 ＋ e2e 1 件（`PASSRCD` / `ERASE`）。
- AC3 **項目の参照を巻き込まない** → 単体 2 件（表が別・同名の項目があっても不変）
  ＋ e2e 1 件（`CSRLOC` が変わらない）。
- AC4 名前の重複を拒否 → 単体 2 件 ＋ e2e 2 件（拒否とソース不変・理由が出る）。
- AC5 空・11 桁は拒否 → 単体 3 件。
- AC6 実機で通る（対照つき） → `verify/verify-record-rename-compiles.mjs`。
  追随ありは通り、**追随なしは通らない**。
- AC-I1 項目と同じ約束 → `recordNameInput` を `attributeInput` と同じ形で書いた。
- AC-I2 拒否が見える → `dds-reject` に出す。e2e で確認。
- AC-I3 何が一緒に変わるか → 断り書きに 6 つのキーワードを並べた。

### 価値適合

「どのキーワードが様式名を採るかを覚えている必要がある」をなくすのが目的。
**覚える必要がなくなったのは 6 つのキーワードだけ**で、そのうち 2 つ
（`MNUBARDSP` / `MNUBARCHC`）は実機で確かめられていない。表の `origin` に
書き分けたので、後から確かめ直せる。

### 正確性

- **実機で対照つきに確かめた**。`SFLCTL` / `ERASE` / `PASSRCD` は追随しないと
  コンパイルが通らない（値打ちの裏づけ）。
- `HLPRCD` は**コンパイラーが見ていない**ことが分かった（存在しない様式でも通る）。
  誤って追っても実機は教えてくれないので、原典の条件（引数が 1 つのときだけ）を
  厳密に守り、単体で固定した。**条件を外すと落ちる**ことを確認済み。
- **落ちないテストを 1 件見つけて直した**（`decisions.md` D7）。
  `&` の守りが `looksLikeName` と重複しており、外してもテストが通っていた。

### 規約適合

- **原典と実機の根拠を書き分けた**（D4）。確かめられなかったことを
  「確かめた」と書かない。
- **同じ規則を 2 か所に置かない**（D7）。
- **対照を必ず置く**——`HLPRCD` と `MNUBARDSP` はどちらも対照が落ちて、
  最初の読み（「通らない」）が誤りだと分かった。

### 保守性

追随の当て方は項目と共有し、追う先だけを引数で差し替える（D2）。

### 指摘

- must: 0 / should: 0 / nit: 0

作業中に自分で見つけて直したもの:
1. `HLPRCD` の最初の probe は**対照も落ちていた**（`HELP` が要る）
2. メニュー・バーの probe も**対照が落ちた**（原典のみを根拠にすると決めた）
3. `&` の守りが重複しており、**外してもテストが通った**（D7）
4. e2e が `li.record` を押しても選択が起きなかった（`.label` を押す。D6）
