# 計画: 様式の改名と参照追随

## 作業順序と依存関係

1. 実機で規則を確かめる（重複・参照の要否・`HLPRCD`・`MNUBARDSP`）
2. `RECORD_ARGUMENTS` と `findRecordReferences` / `renameRecordReferences`（依存: 1）
3. `renameRecord` の型・検証・適用（依存: 2）
4. プロトコルと UI（名前の入力欄・断り書き・件数）（依存: 3）
5. 単体テスト（依存: 3）
6. e2e（依存: 4）
7. 実機で書き出しを確かめる（対照つき）（依存: 3）

## リスク / 留意点

- **項目の参照を巻き込む**と、正しいソースが壊れる。表を分け、単体で固定する。
- **`&` で始まる引数を様式名として扱う**と `MNUBARDSP` の 2 つ目の形式が壊れる。
- 一覧で様式を選ぶとき、**入れ子の項目行**を掴まないようにする（e2e の作り）。

## テスト方針

- 実機: 重複・参照の要否を先に確かめ、最後に書き出しを対照つきで通す。
- 単体: 見つける / 置き換える / 編集に組み込む / 拒否、の 4 群。
- e2e: 名前の欄が出る → 変わる → 参照も変わる → 項目の参照は変わらない →
  重複は拒否されソースが変わらない。
