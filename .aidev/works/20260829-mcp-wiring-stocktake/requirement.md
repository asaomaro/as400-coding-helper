# 要件: MCP 配線 3 件の棚卸し

## 背景 / 課題

backlog の 3 件（SQL / 任意 CL・IFS / スプール読み取りの MCP 配線）は
`(repo:as400-web-emulator)` と付いており、**別リポジトリなので着手できない**と判断していた。

**リポジトリは `ts5250` に改名されており、`/workspaces/ts5250` にある。**
しかも**この一連の作業で実機アクセスに使っていたのは、まさにそのリポジトリ**だった。

## 目的 / ゴール

**3 件が済んでいるのか未着手なのかが、現物の根拠つきで決着している状態。**

紐づく charter ゴール: 「横断する技術的負債の解消」。

## ユーザーストーリー

- US1: **backlog から次を選ぶ人**として、済んでいる項目を選ばされたくない。
  なぜなら、着手して初めて完了済みと分かるのは時間の無駄で、実際 2026-08-01 に
  同じことが起きているから。（受け入れ: AC1, AC2）

## スコープ

### 対象
- 3 件それぞれについて、**ts5250 の現物**で済否を確かめる。
- 受け入れ条件（特に SQL の「対象スキーマ検証」）まで満たしているかを見る。
- 満たしていない部分は残件として分ける。

### 対象外
- **ts5250 のコードを変えること**。棚卸しが目的。
- 未実装と分かった部分の実装（別項目に送る）。

## 完了条件 (受け入れ基準)

- [ ] AC1: 3 件それぞれの済否が、**ファイルと行番号**で示されている。
- [ ] AC2: MCP に**実際に公開されている**ことを登録経路まで辿って確かめている
      （定義があるだけでは「到達可能」ではない）。
- [ ] AC3: 受け入れ条件のうち**満たしていない部分**が残件として分かれている。
- [ ] AC4: リポジトリ名の変更が backlog に反映されている。
