# 要件: プロンプト・タイプとデータ域（ACS と同じ。P15）

## 背景 / 課題
2026-09-27 の実操作調査（`docs/research/20260927-f4-prompter-exploration/findings.md` の P15）で、空行で F4 すると英語で断られ、
空の `C` の行は必ず従来形式（C-SPEC）で開き、拡張演算項目 2 の形式（C-NEW）で開くには 26 桁目に命令を先に手で打つしかなかった。
2026-09-27 に利用者が **ACS に揃える**と決めた: 空行で F4 → プロンプト・タイプ `**` で、桁の目盛りつきの「データ域」を開く。
プロンプト・タイプの欄に C / CX / H / F / D / P などを入れると、その仕様書のプロンプトに切り替わる（C = 従来形式、CX = 拡張演算項目 2）。

## 完了条件 (受け入れ基準)
- [ ] AC1: RPG の空行で F4 → プロンプト・タイプ `**` のデータ域（目盛りつき、1-80 桁の 1 欄）が開き、OK で行をそのまま書く（本物の VS Code）。
- [ ] AC2: RPG のどのプロンプトにもプロンプト・タイプの欄があり、変えて OK すると書かずにその仕様書のプロンプトで開き直す。
  他の欄の必須は咎めない（空の C の行でも CX に切り替えられる）（本物の VS Code）。
- [ ] AC3: 空行から仕様書のプロンプトで書くと、6 桁目に仕様書の文字が入る（本物の VS Code）。
- [ ] AC4: タイプの対応（`**` / C / CX / H / F / D / I / O / P、RPG III は E / L も・CX 無し）と、使えないタイプの扱い（単体テスト）。CL・DDS のプロンプトは変わらない（既存テスト・e2e）。
