# 要件: 描画全体を実機のゴールデンと突き合わせる

## 背景 / 課題

`dspfRenderModel` の描画が実機の見え方と一致するかは、**いま目視でしか確かめていない**。

部分的には実機と突き合わせてある——DBCS の桁（`20260827-dds-keyword-continuation`）、
`COLOR` / `DSPATR` の全 61 通り（`20260827-dds-5250-colors`）——が、
**「この様式を出したら画面がこうなる」を丸ごと**比べたことは一度も無い。

**ずれても気付けない。** 桁が 1 つずれた・属性文字の分を数え落とした・
用途（`I`/`O`/`B`）を取り違えた、はいずれもコンパイルが通り、テストも通る。

## 目的 / ゴール

**実機の画面を採取したものが repo にあり、描画モデルとの一致が
オフラインで（実機に繋がずに）検査できる状態。**

紐づく charter ゴール: DDS の視覚的な確認と編集（第 4 の柱）。

## ユーザーストーリー

- US1: この PJ を直す開発者として、**描画を変えたときに実機とずれたら落ちてほしい**。
  なぜなら描画のずれは**動かして目で見るまで分からず**、その頃には別の変更が積み重なっているから。（受け入れ: AC1, AC2, AC3）
- US2: この PJ を直す開発者として、**実機に繋がなくても検査したい**。
  なぜなら実機は共用で、往復も遅く、CI からは触れないから。（受け入れ: AC4）

## スコープ

### 対象
- 実機の画面を採取して repo に固定する仕組み（採取スクリプト＋ゴールデン）
- 採取したものと `buildDspfRenderModel` を突き合わせる**オフラインのテスト**
- DBCS を含む様式（SO/SI が桁を消費するので最もずれる）

### 対象外
- PRTF の紙面ゴールデン（行送りは `20260827-dds-prtf-editor` で実機確認済み）
- 採取の自動化（CI から実機を叩かない。採取は人が回す）

## 完了条件 (受け入れ基準)

- [ ] AC1: **定数**の文字が、モデルの言う桁に 1 桁もずれずに出ている（DBCS を含む）
- [ ] AC2: **フィールド**の位置・桁数・入力可否が実機の入力欄と一致する
- [ ] AC3: **属性文字と見え方**（色・反転表示・下線・非表示）が一致する
- [ ] AC4: 突き合わせが `npm test` で走る（実機に繋がない）
- [ ] AC5: 採取スクリプトが work に残り、**採り直せる**
