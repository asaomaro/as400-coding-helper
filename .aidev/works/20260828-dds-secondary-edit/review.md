# レビュー: 2 次画面サイズでの編集

## ラウンド 1（自己レビュー）

### 要件適合

- AC1: 上書き行の位置欄だけが変わり、項目の行は変わらない
  → `moveSecondary` の置換の枝。単体「行を増やさず位置欄だけを書き換える」
  ＋「項目の行（1 次の位置）は変わらない」で固定。**済**
- AC2: run の直後に作られ、条件名は `DSPSIZ` の 2 次に対応する
  → `unitRunEnd` ＋ `conditionNameFor`。単体 4 件（継続あり / ユーザー定義名を含む）。**済**
- AC3: 作る行は条件名と位置だけ
  → `buildAlternatePositionLine` は名前・長さ・型・用途・キーワードを**受け取らない**。**済**
- AC4 / AC5: `screen-size-not-declared` / `screen-size-not-editable`。**済**
- AC-I1: 2 次で掴める（早期 return を外した）。e2e 2 件。**済**
- AC-I2: resize は掴ませず理由を出す。e2e 1 件。**済**
- AC-I3: 1 次の `move` は不変。単体 3 件 ＋ 既存テスト全通過。**済**

### 価値適合

「2 つのサイズを行き来しながら桁を合わせるのに、片方だけテキストで数えない」
——作る・動かす・消すの 3 つが揃って初めて成立する。**D2 で消す操作を足した**のは
この節の判断（作れるが消せないと、結局テキストエディタへ戻る）。

### 正確性

- **実機で確かめた形と一致するか**: `verify/verify-written-form.mjs` が
  編集の出力そのものを `CRTDSPF` に通す。通る。
- **入力が壊れているとき**: 上書き行が 2 本ある（実機は通さない）場合は先頭を採る。
  `findAlternatePosition` にその旨を書いた。
- **挿入で行番号がずれる**: `applyDdsEdits` は降順で返す（既存の約束）。
  単体の `apply` ヘルパーはソートせずそのまま当てて確かめている。

### 規約適合

- 原典に無い規則は**実機に判定させ、再現できる形で残した**（`verify/` の 3 本）。
- **同じ判定を 2 か所に置かない**: 上書き行の引き当ては `findAlternatePosition` に
  一本化し、`resolveDspfLayout`（描く側）と `applyDdsEdits`（書く側）が同じ関数を通る。
  写していたら「見えている項目を掴んだのに別の行が書き換わる」が起こりえた。
- **到達可能性**: core → protocol → UI → e2e まで辿った。CLI は `parseEdits` 経由。

### 保守性

- 鍵の意味の衝突（`screenSize`）を**入れる前に**解いた（D3）。
- `buildAlternatePositionLine` は `buildItemLine` の隣に置いた（行を作る責務は 1 か所）。
