# 計画: キーワード欄の編集

## 作業順序と依存関係

1. `foldKeywordArea` / `buildKeywordLine`（折り返し）— 依存なし
2. `setKeywords`（適用と検証）— 依存: 1
3. 継続にまたがる `text` を同じ経路へ — 依存: 2
4. プロトコル（`parseEdit`）— 依存: 2
5. UI（`✕` / `＋` / 生テキストの編集）— 依存: 4
6. 単体テスト（折り返しの表・**往復の総当たり**・拒否）— 依存: 1-3
7. GUI e2e — 依存: 5
8. 実機で往復を確かめる — 依存: 6
9. 記録 — 依存: 全部

## リスク / 留意点

- **往復が合わないと黙って壊れる**（値が消える・空白が増える）。総当たりで固定する。
- **注記行が挟まった項目**を区間で置き換えると注記が消える。拒否する。
- **定数のリテラルが消えると項目ごと消える**。拒否する。
- 既存の `setAttributes.text` の経路は**変えない**（`ddsAttributeEdit.test.ts` が固定している）。

## テスト方針

- **単体**（`test/unit/ddsKeywordEdit.test.ts` 新規）:
  - 折り返しの表（収まる / 切れ目で折る / `-` で切る / 空）。
  - **往復の総当たり**: 原典の表 176 件から作った入力（引数あり / 引数なし / 長いリテラル）を
    折って読み直し、区切りの並びが一致すること。
  - 拒否 2 種と、継続にまたがる `text` が通ること。
- **回帰**: `npm test` / `npm run verify` / lint / GUI e2e。
- **実機**: 折り返した結果がコンパイルを通り、`Expanded Source` が編集前と同じであること。
