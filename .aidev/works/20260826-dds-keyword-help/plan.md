# 計画: キーワード欄のチップ表示と原典ヘルプ

## 実装方針

**解析を先に固める**（純関数なのでテストで詰められる）→ 型と引き当て → プロトコル →
ホスト 2 つ → UI。UI に触る前に core と結線が済んでいる状態にする。

分割（subtask）はしない。**編集は別 work**（この work は読むだけ）なので、これ自体が既に薄い。

## 作業順序と依存関係

1. 解析（`parseKeywordEntries`）— 依存なし
2. 解説の型と引き当て（`DdsKeywordHelp` / `findKeywordHelp`）— 依存なし
3. 既存の補完が core の型を使うようにする（振る舞いは変えない）— 依存: 2
4. `load` に解説表を足す（任意フィールド）— 依存: 2
5. VSCode 側で表を読んで渡す — 依存: 4
6. 単独起動側で表を束ねて渡す — 依存: 4
7. UI: チップと解説 — 依存: 1, 2, 4
8. 見た目（CSS）— 依存: 7
9. 単体テスト — 依存: 1-6
10. GUI e2e — 依存: 7, 8
11. 記録（設計文書・backlog）— 依存: 全部

## リスク / 留意点

- **リテラルを「原典に無いキーワード」と出さない**。定数を選ぶたびに誤った印が出る。
- **表が渡らないときに印を出さない**。単独起動で表を束ね忘れると、全部に `?` が付く。
- **140KB を毎回送らない**。`load` だけに載せる。
- **チップ上のキーをキャンバスへ漏らさない**（`Delete` で項目が消える）。
- `src/language/ddsKeywordCompletion.ts` の型の寄せ替えは**振る舞いを変えない**こと。
  変えると DDS の補完に波及する（別機能）。

## テスト方針

- **単体**（`test/unit/ddsKeywords.test.ts` 新規）:
  - 解析の表（spec の表をそのまま）。閉じない括弧・引用符も。
  - 引き当ての 2 段（`CA03` → `CAnn`）。`CA0` や `CA123` で誤って当たらないこと。
  - **実データで引く**（`resources/completion/dds-keywords.json` を読み、
    サンプル `CUSTMNT.dspf` に出る全キーワードが引けること）。
    ここが原典との突き合わせにあたる。
- 既存の回帰: `npm test` / `npm run verify` / lint。
- **GUI e2e**: チップが出る・押すと解説が出る・`F1` でも出る・
  キーがキャンバスへ漏れない・生テキストが残っている。
