# 決定記録

## D1: 解説は `load` の**任意フィールド**でホストが渡す

- 背景: 解説の表は `resources/completion/dds-keywords{,.en}.json`（日本語 140KB）で、
  WebView にファイルシステムは無い。渡す手段はホストしかない。
- 決定: `load` メッセージに `keywords?` を足す。**任意**にして、渡せないホストでも
  チップの並びは出る（解説だけが出ない）。`applied` / `rejected` には載せない。
- 理由 / 代替案: キーワードごとにホストへ問い合わせる案（`askKeywordHelp`）は往復が増え、
  ホスト 2 つにそれぞれ実装が要る。表は**文書ごとに変わらない静的なデータ**なので 1 回で足りる。
  `applied` に載せると**編集のたびに 140KB を送り直す**ことになる。
- 影響: 直前 2 つの work では `protocol.ts` を変えずに済ませたが、これは
  **表示の状態ではなくホストが持つ参照データ**なので、モデルと同じ扱いで載せた。

## D2: 表が無いときは「原典に無い」の印を出さない

- 背景: 原典に無い綴りに印を付ける（AC6）が、表そのものが渡らないこともある（D1）。
- 決定: `this.keywordHelp.length === 0` のときは**印を出さない**。
- 理由: 表が無ければ全部が「引けない」ので、印は**必ず全部に付く**。
  それは「このソースは全部間違っている」と読め、事実と違う。
- 影響: 単独起動で表を束ね忘れると、印が一切出ない（＝静かに劣化する）。
  e2e が実際に印の有無を見ているので、束ね忘れはそこで落ちる。

## D3: 定数のリテラルをキーワードと区別する

- 背景: 定数の固定情報（`'顧客保守'`）は**キーワード欄の先頭**にあり、
  `unit.keywords` には同じ文字列として入っている。
- 決定: `KeywordEntry.kind` を `"keyword" | "literal"` にし、リテラルは
  押しても解説を出さず、「原典に無い」の印も付けない。
- 理由: 区別しないと、**定数を選ぶたびに「原典に無いキーワード」の印が付く**。
  定数はキーワードではないので、原典に無くて当然。
- 影響: e2e で「定数のリテラルに印が付かない」を固定した。

## D4: 様式（レコード・レベル）も選べるようにした（スコープを 1 つ広げた）

- 背景: 実装して実データで確かめたところ、**`OVERLAY` / `CF03` が一切読めない**ことが分かった。
  これらは様式宣言の行にあり、`OutlineRecord` はキーワードを持っていなかった。
  CUSTMNT.dspf の項目レベルのキーワードは `CHECK(RZ)` と `COLOR(RED)` の 2 つだけで、
  **この work の目的（キーワードが読める状態）が実質半分しか満たせない**。
- 決定: `OutlineRecord.keywords` を足し、様式ツリーの見出しを選べるようにして、
  様式のプロパティ（キーワードだけ）を出す。
- 理由 / 代替案: 別 work に切り出す案もあったが、
  `keywordSection` を「行 ＋ 生テキスト」で受ける形に変えるだけで済み（差分はごく小さい）、
  切り出すと**目的を満たさない PR を先に出す**ことになる。
- 影響: `OutlineRecord` に必須フィールドが 1 つ増えた（キーワードが無ければ空文字。
  `undefined` にしない——「無い」と「読んでいない」が区別できなくなる）。
  **ファイル・レベル**（`DSPSIZ` / `REF` / `INDARA` / `PRINT`）は依然として読めない。
  これは `toLogicalUnits` が論理単位にしないためで、直すには core の走査を変える必要がある。
  backlog に分けて残した。

## D5: 入れ子のツリーで「自分の行か」を `closest("li")` で見分ける

- 背景: 様式の見出し（`li.record`）の**中**に項目の `ul` があるので、
  項目のクリックもキーも見出しまで上がってくる。
- 決定: `target.closest("li") === heading` で自分の分だけ拾う。
- 理由 / 代替案: 最初は `.label` を持つかで見分けたが、**`.label` は項目側にもある**ので
  項目をクリックすると様式が選ばれた（実際に踏んだ）。
  選択の背景色も `li` に塗ると**入れ子の項目まで帯が伸びた**ので、`> .label` に限定した。
- 影響: e2e に「様式の中の項目をクリックしたら項目が選ばれる」を足した。

## D6: `CAnn` / `CFnn` の欠落は別 work で先に直した

- 背景: 調査中に、原典の索引と表を突き合わせて `CAnn` / `CFnn` が**表から丸ごと落ちている**
  ことが分かった（`CF03` はこのリポジトリのサンプルにも書かれている）。
- 決定: **別 work に切り出して先に直した**（`20260827-dds-keyword-cann` / PR #113）。
- 理由: 再生成データの差分（200KB）が UI の差分に混ざるとレビューが成立しない。
- 影響: この work は 176 件の表を前提にできる。引き当ては 2 段
  （そのまま → 末尾 2 桁を `nn` に正規化）。
