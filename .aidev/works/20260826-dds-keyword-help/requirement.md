# 要件: キーワード欄を読める形にする（チップ表示と原典ヘルプ）

## 背景 / 課題

DSPF の実質的な記述は **45-80 桁のキーワード欄**に集中する。
いまのデザイナは、この欄を**生テキストのまま 1 本の読み取り専用入力欄**に出しているだけで、

- `CHECK(RZ)` の `RZ` が何かは**知っている人にしか分からない**。
  原典のキーワード解説は既にリポジトリにある（`resources/completion/dds-keywords.json`、
  174 件・原典から生成し `verify-dds-keywords.mjs` が検査済み）のに、
  **テキストエディタの補完でしか出てこない**。デザイナからは読めない。
- 複数のキーワードが並ぶと（`DSPATR(RI) COLOR(RED) CHECK(RZ)`）**どこで切れているか**が読めない。
  キーワード継続行があると 1 本の欄に連結されるので、さらに読めなくなる。
- **原典に無い綴り**（打ち間違い・そのファイル種別では使えないキーワード）が
  黙って通る。コンパイルするまで気づかない。

紐づく charter ゴール: **DDS（DSPF/PRTF）の視覚的な確認と編集**を第 4 の柱として加える。

## 目的 / ゴール

**キーワード欄が「何が並んでいるか」と「それぞれが何か」の両方で読める状態**。
知らないキーワードに出会ったときに、**デザイナを離れずに原典の説明が読める**。

原典に無い綴りは、**コンパイルの前に画面で分かる**。

## ユーザーストーリー

- US1: DSPF を読む開発者として、**キーワードを 1 つずつに分けて見たい**。
  なぜなら、連結された 1 本の文字列からは**どこで切れているか**が読めず、
  継続行があると特に追えないから。（受け入れ: AC1, AC3）
- US2: DSPF を直す開発者として、**キーワードを選ぶとその意味が読めるようにしたい**。
  なぜなら、原典の解説は**既にリポジトリにあるのにデザイナからは辿れず**、
  いまはブラウザで IBM のページを開き直しているから。（受け入れ: AC4, AC5）
- US3: DSPF を直す開発者として、**原典に無い綴りをその場で知りたい**。
  なぜなら、いまは**コンパイルするまで**気づかず、往復が 1 回増えるから。（受け入れ: AC6）

## スコープ

### 対象

- core: キーワード欄の**解析**（名前と引数への分解。引用符・入れ子の括弧を壊さない）。
- core: 原典のキーワード解説を渡すための**型**と、名前での引き当て。
- ホスト（VSCode / 単独起動）が**原典の解説をエディタへ渡す**経路。
- UI: プロパティのキーワード欄を**チップの並び**にし、選ぶと解説が読める。

### 対象外

- **キーワードの編集**（追加・削除・引数の変更）。**この work では読むだけ**。
  書き戻しは別の話（1 つのキーワードが 45-80 桁に収まらない場合の扱いを決める必要がある）。
- **引数の中身の検証**（`DSPATR(RI)` の `RI` が妥当か）。原典の `syntax` は散文混じりで、
  機械的な検証に耐える形になっていない。**名前の存在とレベルだけ**を見る。
- 名前変更の参照追随（`SFLCTL(NAME)` 等）。別の話として backlog に残す。
- PRTF / PF・LF のキーワード。**種別ごとの表は渡す仕組みに載せる**が、
  いまのエディタは DSPF だけを開く。

## 機能要件

- キーワード欄を**名前と引数**に分ける。引用符の中の空白・括弧で切らない。
- 定数（固定情報）の**先頭のリテラル**はキーワードではないので、そう分かる形にする。
- 各キーワードについて、原典の**和名・使用レベル・構文・説明**が読める。
- 原典に無い名前は**そう分かる形**にする（消さない・並べ替えない）。
- 解説の言語は**ホストの設定に従う**（VSCode の既存のキーワード補完と同じ）。

## 非機能要件 / 制約

- **既存挙動を壊さない**: キーワード欄の生テキストは失わない（見る手段を残す）。
- core は `vscode` を import しない。**ファイルも読まない**（解説はホストが渡す）。
- 解説の出所は**原典から生成したデータ**（`resources/completion/dds-keywords.json`）に限る。
  ここで新しく説明を書き起こさない。
- キーワード欄は**この work では書き換えない**（読み取り専用）。

## 完了条件 (受け入れ基準)

- [ ] AC1: `DSPATR(RI) COLOR(RED)` が 2 つのキーワードに分かれる。
      `EDTWRD('  0. ')` のように**引用符の中に空白や括弧**があっても切れない。
- [ ] AC2: 定数の先頭のリテラル（`'顧客保守'`）がキーワードと区別される。
- [ ] AC3: キーワード継続行のキーワードも同じ並びに出る（連結されたままにしない）。
- [ ] AC4: チップを選ぶと、原典の**和名・使用レベル・構文・説明**が読める。
- [ ] AC5: 解説の言語がホストの設定（日本語 / 英語）に従う。
- [ ] AC6: 原典に無い名前のチップは、そうと分かる印が付く。
- [ ] AC7: 解説を渡せないホスト（データが無い）でも、**チップの並びは出る**（解説だけが出ない）。
- [ ] AC8: キーワード欄の生テキストが読める手段が残っている。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 解説は**チップを選ぶと同じペインの下に出る**（別窓を開かない）。
      もう一度選ぶ、または他の項目を選ぶと閉じる。
- [ ] AC-I2 確定 / 取り消し: 読むだけなので確定は無い。**ソースは変わらない**。
- [ ] AC-I3 キーボードだけで完結するか: チップは `Tab` で到達し、`Enter` / `Space` で解説が開く。
      `F1` でも開く（この PJ のヘルプ規約に合わせる）。
- [ ] AC-I4 フォーカスの行き先: 解説を開いてもフォーカスは**そのチップに残る**。
- [ ] AC-I5 既存の操作を妨げないか: チップ上のキーを**キャンバスへ漏らさない**
      （`Delete` で項目が消えない・矢印で動かない）。
