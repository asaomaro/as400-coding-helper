## 観点ごとの確認

### 要件適合

`spec.md` の対応表 13 項目に実装が対応している。**AC5 / AC6 / AC7 は自動検証していない**
（言語切替・原典に無い綴りの実例・表が渡らないホスト）。理由と代替の確認は `test.md` に明記した。

### 価値適合

ゴールは「**知らないキーワードに出会ったときに、デザイナを離れずに原典の説明が読める**」。
`CUSTMNT.dspf` を単独起動で開き、`CHECK(RZ)` を押して「検査」の解説が出ること、
様式 HEADER を選んで `CF03(03 '終了')` を押すと **`CFnn` の解説**が出ることを実操作で確認した。
後者は**この work の直前まで表から丸ごと落ちていた**もので（PR #113）、
「原典との突き合わせ」がそのまま価値になった例。

### 正確性

- 解析は**引用符の外でだけ括弧を数える**。`EDTWRD('   0. ')` / `DFT('(A)')` / `''` のエスケープを
  それぞれ単体で固定した。閉じない括弧・引用符も**捨てずに**行末までを 1 区切りにする。
- 引き当ては 2 段。`CA3` / `CA123` のような**原典の書き方でないもので誤って当たらない**ことも固定した。
- **実データで引く**テストを入れた（`resources/completion/dds-keywords.json` を読み、
  `docs/src/CUSTMNT.dspf` に出るキーワードが 1 つ残らず引けること）。手で作った表だけで通しても、
  実データの綴りと食い違っていれば意味が無い。

### 規約適合（AGENTS.md）

- **原典照合は主エージェントが実施**した。索引ページの生テキストから名前を機械的に取り出して
  表と突き合わせ、`CAnn` / `CFnn` の欠落を見つけた（別 work で修正）。
  解説の文章は**一切書き起こしていない**——出所は原典から生成したデータだけ。
- `languageId` / `contributes` / `activationEvents` は無変更。
- `src/language/ddsKeywordCompletion.ts` は**型を core に寄せただけ**で振る舞いは変えていない
  （DDS の補完に波及していないことは単体テストと `npm run verify` で確認）。

### 保守性

- 同じ JSON を読む先が 2 つ（補完・エディタ）になったので、**型は core に置いて共有**した。
- 解析は core の純関数で、UI は文字を数えない（既存の方針どおり）。
- 表の読み込みは**言語ごとに保持**（補完側と同じ形）。
