### 指摘と対応（このラウンドで直したもの）

#### must-1: 非表示用途の集合が 2 か所にあった（AC9 違反）

`dspfOutline.ts` が `new Set(["H","P","M"])` を**自前で持っていた**。`dspfLayout.ts` にも同じ集合があり、
**片方だけ直すとずれる**——ずれると「一覧には理由が出ているのにキャンバスには描かれている」、
あるいは逆に**どこからも触れない項目**ができる。

→ `dspfLayout` から `NON_DISPLAY_USAGE` を export して共有した。
加えて、**両者の食い違いを機械的に検査するテスト**を足した——
「理由が無い項目は必ず描かれている / 理由が付いた項目は描かれていない」
「描かれる項目はすべて一覧にも出る」を実サンプル込みで回す。**集合を共有しただけでは
順序のずれを防げない**ので、突き合わせ自体をテストにした。

#### should-1: 適用のたびにフォーカスが飛んだ

`applied` で `render()` するとプロパティを作り直すので、**「名前を直して次に長さを直す」の
途中でフォーカスが失われる**（blur → 適用 → 再描画 → クリック先が古い要素）。

→ 描き直す前に**編集中の欄（`data-key`）を覚え、描き直した後に戻す**ようにした。
`select` にも `data-key` を付けて対象にした。

### 実装中に踏んで直したもの（`decisions.md` に記録済み）

- **D4: 拒否のたびに往復が止まらなくなった。** 拒否 → 再描画 → 消えた欄の `blur` → もう一度 commit →
  拒否 … と循環した（単独起動はホストが同期なので即座に往復する）。
  **拒否では再描画しない**（文書は変わっていない）＋ **確定値を覚えて二重送信しない**で解消。
- **D6: 左ペインが中身の幅で膨らみ、右ペインがキャンバスに被った。** flex アイテムの
  `min-width` 既定は `auto`。`min-width: 0` ＋ `flex: 0 0 200px` で解消。
  **つまみが掴めなくなる**という形で現れ、e2e が拾った。

### 残る留意点（PR 本文へ）

- **数え方の割り切り**（D7）: 行長の上限 100 桁は **JS の文字数**で数える（lint と同じ）。
  DBCS を含む行は実バイトではもっと長い。**表示桁で数えるなら lint と同時に変える**必要がある。
- **名前変更は参照に追随しない**（D8）。`SFLCTL(NAME)` 等は古い名前のまま残る。
  プロパティに注意書きを出して**できないことを明示**している。追随は L3 の範囲。
- **小数桁を空にできない**（`sendAttribute` が空欄を無視する）。0 は書けるが、欄ごと消す手段が無い。
- **中央ペインは横スクロールする**（キャンバスが 80 桁ぶんあるため）。狭い画面では正常な挙動だが、
  **見えていない位置のつまみは掴めない**（e2e は `scrollIntoViewIfNeeded` してから掴む）。
- **キーワード欄は読み取り専用**。編集は L3（原典との突き合わせが前提）。
