# 要件: DDS デザイナの属性編集（L2）とプロパティ／様式ツリー

## 背景 / 課題

- PR #109 で **C1 デザイン（`docs/design/dds-designer/`）の中央キャンバスだけ**が入った。
  項目を**動かす・伸ばす・置く・消す**ことはできるが、**中身を変えられない**。
- 具体的に言うと、フィールドの**名前・型・小数桁・使用（I/O/B/H）**、定数の**文字列**を
  変える手段が無い。**新しく置いた項目の名前を間違えたら、消してもう一度置くしかない。**
- 確定した C1 デザインの 3 ペインのうち、**左（様式ツリー）と右（プロパティ）が未実装**。
  項目の一覧が無いので、**キャンバスで重なっている項目や、画面外に出た項目は選べない**
  （`missing-position` / `lineOutOfRange` の項目はキャンバスに描かれないため、GUI からは触れない）。
- 様式が複数ある DDS で、**どの様式を見ているのかが画面に出ない**。`CUSTMNT.dspf` は
  HEADER / DETAIL の 2 様式だが、キャンバスには両方が重なって出る。

## 目的 / ゴール

達成したい状態:

- **項目の中身を GUI で直せる状態**——名前・長さ・型・小数桁・使用、定数の文字列。
  消して置き直す必要がない。
- **キャンバスに描かれない項目にも手が届く状態**（位置が無い・画面外・幅不明の項目を
  一覧から選び、直せる）。
- **いま何を選んでいて、それがソースのどこで、画面のどこを占めるのかが同時に見える状態**
  （C1 の 3 ペイン: 様式ツリー / キャンバス / プロパティ）。
- **桁の勘定が画面で確かめられる状態**——占有（属性文字込み）と右端の余裕が数字で出る。
  「実機に持っていったら桁溢れだった」を GUI の時点で潰せる。

紐づく charter ゴール: 「**DDS（DSPF/PRTF）の視覚的な確認と編集**」（第 4 の柱）。
確定デザイン: `docs/design/dds-designer/README.md`（C1・スタンドアロン優先）。

## ユーザーストーリー

- **US1**: AS400 開発者として、置いた項目の**名前や型を後から直したい**。
  なぜなら **消して置き直すのは、位置もキーワードも作り直しになる**から。（受け入れ: AC1, AC2）
- **US2**: 開発者として、**キャンバスに出ない項目も一覧から選んで直したい**。
  なぜなら位置欄が空の項目・画面外の項目は**GUI からは存在しないのと同じ**になり、
  結局テキストエディタに戻ることになるから。（受け入れ: AC3）
- **US3**: 開発者として、選んだ項目が**画面のどこを占め、右端にどれだけ余裕があるか**を
  数字で見たい。なぜなら**属性文字を含む占有は目で数えられず**、実機のコンパイルまで
  分からないのでは遅いから。（受け入れ: AC4）
- **US4**: 複数様式の DDS を保守する開発者として、**どの様式の項目なのかを一覧で見たい**。
  なぜならキャンバス上は様式が重なって出るので、**見えている項目がどれに属すか判断できない**から。
  （受け入れ: AC5）
- **US5**: この機能を保守する開発者として、属性編集も**既存の編集と同じ経路**を通ってほしい。
  なぜなら**書き戻しが 2 系統になると、バイト不変の保証が片方で崩れる**から。（受け入れ: AC6, AC7）

## スコープ

### 対象

- **属性の編集操作**（定位置欄）: 名前（19-28）・長さ（30-34）・型（35）・小数桁（36-37）・
  使用（38）、および**定数の文字列**。
- **右ペイン: プロパティ**——選択中の項目の属性を表示・編集。占有（属性文字込み）と
  右端の余裕を数字で出す。対応するソース行も見せる。
- **左ペイン: レコード様式ツリー**——様式ごとに項目を一覧し、選択できる。
  **キャンバスに描かれない項目もここに出す**（位置なし・画面外・幅不明）。
- 3 ペインのシェル（C1 のレイアウト）。**VSCode と単独起動の両方で同じ構成**。

### 対象外（後続 work）

- **キーワード欄（45-80 桁）の編集**（`DSPATR` / `COLOR` / `EDTCDE` 等）— L3。
  構文の解釈が要り、**原典（`docs/origin/dds/`）との突き合わせが前提**になる。
- **条件標識の編集**——core に条件の解決が無い。
- **表示トグル**（SO/SI の `{ }` 表示・グリッド・スナップ・ズーム・5250 配色）。
- **ヘッダのファイル操作・コマンド・ヘルプ**（単独起動側の殻）。
- **PRTF**。
- **参照フィールド（29 桁の `R`）の参照解決**——幅不明のまま扱う。

## 機能要件

1. 選択中の項目の属性（名前・長さ・型・小数桁・使用／定数の文字列）を編集でき、
   **定位置欄の該当桁だけ**が書き換わる。
2. 属性の編集も既存の編集と**同じ経路**（検証 → 置き換え指示 → 適用）を通る。
3. **書けない値は適用前に拒否**し、理由が画面に出る（名前が 10 桁を超える等）。
   規則違反（重なり・はみ出し）は適用して診断で見せる（既存の方針を維持）。
4. 左ペインに様式と項目を一覧し、**キャンバスに描かれない項目も含める**。
   一覧から選ぶとプロパティに出る。
5. 右ペインに**占有（属性文字込みの開始〜終了桁）と右端の余裕**を数字で出す。
6. 選択はキャンバス・一覧・プロパティで**同期**する。
7. VSCode と単独起動で**同じ 3 ペイン**が出る（ホストが肩代わりする部分を除く）。

## 非機能要件 / 制約

- **判定を増やさない**。桁・幅・重なり・占有は `core/dds`（`dspfLayout` / `ddsFieldWidth` /
  `dbcs`）がすでに持つものを使う。プロパティに出す数字も**その計算結果**であって、
  UI で数え直さない。
- **UI は `vscode` に触らない**。属性の編集も `protocol.ts` のメッセージだけで会話する。
- **既存挙動を壊さない**——既存プレビュー・lint・アウトライン・補完・F4 は無変更。
  `npm test` と `npm run verify` を通す。
- 原典に根拠のある規則（桁の意味・右詰め等）は**引用を添える**（AGENTS.md）。
- **1 PR = 独立してレビュー可能な粒度**（charter）。

## 相互作用の受け入れ基準

- [ ] **AC-I1 選択の同期**: キャンバスで選ぶと一覧とプロパティが追従し、一覧で選ぶと
      キャンバスの該当項目が強調される（描かれない項目なら、その旨が出る）。
- [ ] **AC-I2 確定 / 取り消し**: プロパティの入力は **`Enter` またはフォーカスを外したときに確定**。
      `Esc` で編集前の値に戻り、**何も書き換わらない**。
- [ ] **AC-I3 キーボードだけで完結**: 一覧の項目を上下キーで移動して選べる。
      プロパティは `Tab` で項目間を移動できる。
- [ ] **AC-I4 フォーカスの行き先**: 拒否されたときフォーカスは**その入力欄に留まり**、
      理由がその場で読める（入力し直せる）。
- [ ] **AC-I5 既存の操作を妨げない**: キャンバスの移動・つまみ・`Delete`・矢印は従来どおり。
      **プロパティの入力中は矢印キーや `Delete` をキャンバスへ漏らさない。**

## 未確定事項 / 確認したいこと

- **定数の文字列を変えたとき、幅が変わる**（DBCS を含むと大きく変わる）。
  その結果として重なり・はみ出しが生じる場合の扱い（適用して診断、が既存方針）。
- **名前の変更が他所に影響するか**——同じ DDS 内でその名前を参照するキーワード
  （`SFLCTL` 等）があると壊れる可能性。本 work では**追跡しない**が、影響範囲は調べる。
- 一覧の並び順（ソース順か、画面上の位置順か）。
