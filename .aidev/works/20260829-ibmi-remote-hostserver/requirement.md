# 要件: `ibmi-remote` skill に、実際に使っている経路を書く

## 背景 / 課題

backlog「実機操作レシピを skill 化する」の**大部分は既に済んでいた**。
`.claude/skills/ibmi-remote/SKILL.md`（206 行）に ssh / pub400 経由の
メンバー送受信（CCSID 込み）・コンパイル（`*EVENTF`）・エラー取得
（`CPYTOSTMF` ＋ IBM 公式パーサー）が揃っている。**起票が閉じられていなかっただけ。**

**着手前に現物で裏を取って分かったこと**（AGENTS.md / `aidev-00-start`）。
足りないのは 2 つだけ:

1. **ライブラリー・リストの扱いが無い。** `ADDLIBLE` は**次のコマンドに効かない**
   （コマンドごとに別ジョブ）。知らないと外部記述ファイルの解決で `CPF5715` を踏み、
   **桁の問題と誤診する**（`20260828-rpg3-fspec-reclen` で実際に起きた）。
2. **いま実際に使っている経路が書かれていない。** ここ数セッションの実機検証は
   ssh ではなく **`ts5250` の hostserver ライブラリ**を Node から呼んでいる
   （`CommandConnection` / `IfsConnection` / `DbConnection` / `NetPrintConnection`）。

## この gap は実際に害を出した

2026-08-29、`CRTRPGPGM` のコンパイル・リストのスプール名を `QRPGLST` だと思って引き、
**0 件しか返らず全候補が「有効」に見えた**（メッセージが無い ＝ 正しい、と読んでしまう）。

ところが **この skill の 4.5 節には「スプール名は『メンバー名』」と既に書いてあった**
——`CRTDSPF` の話としてだが、同じ性質のこと。**先に読んでいれば踏まなかった。**

AGENTS.md「外部原典と同じだけ **PJ 内部の仕様**を先に読む」が、そのまま起きた形。

## 目的 / ゴール

**次にこの PJ で実機を触る人が、いま自分たちが使っている経路と落とし穴を
skill だけで把握できる状態。**

## ユーザーストーリー

- US1: **この PJ で実機検証をする人**として、どちらの経路を使うかを最初に知りたい。
  なぜなら**遅い経路を選んで時間を失う**か、そもそも繋がらないから。（AC1）
- US2: 同じ人として、**踏むと誤診に繋がる落とし穴**を先に知りたい。
  なぜなら `CPF5715` も「スプールが 0 件」も、**別の原因に見える**から。（AC2, AC3, AC4）

## スコープ

### 対象

- `.claude/skills/ibmi-remote/SKILL.md` に節を足す。

### 対象外

- **ssh 経路の書き換え。** pub400 では今も唯一の手段。消さない。
- RPGUnit（別項目）。

## 完了条件 (受け入れ基準)

- [ ] AC1: 「どちらの経路を使うか」の判断が冒頭にある。
- [ ] AC2: hostserver 経路の最小のレシピ（接続・コマンド・IFS・SQL・スプール）が載っている。
- [ ] AC3: **`ADDLIBLE` が次のコマンドに効かない**ことと回避が載っている。
- [ ] AC4: コンパイル・リストの読み方（**スプール名は対象の名前**・件数が多いときの
      読み方・`GENLVL` を上げたら成否で判定しない）が載っている。
- [ ] AC5: **対照を置くこと**と**片付けを数えて確かめること**が、実際に踏んだ例つきで載っている。
- [ ] AC6: 既存の ssh 経路の記述を消していない・矛盾させていない。

## 非機能要件 / 制約

- **秘密を書かない。** `/workspaces/ts5250/.env` は読まない・値を出さない。
  `--env-file` で渡すことだけを書く。識別子は `.env.verify`（読んでよい）。
- 例は**この PJ で実際に動いたもの**を写す。作り話の落とし穴を書かない。
