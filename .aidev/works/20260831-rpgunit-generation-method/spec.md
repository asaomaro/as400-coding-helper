# 仕様

手順は **skill `rpgunit-test` の 0 節に 1 か所だけ**置く。設計書 4.2 は方針のまま残し、
冒頭から手順の場所へ辿れるようにする（同じ内容を 2 か所に置かない）。

## 構成

| 節 | 内容 | 受け入れ条件 |
|---|---|---|
| 0.1 書く前に決める | オラクルの有無で検証／特性化を分ける。見分ける質問 1 つ | (1)(2) |
| 0.2 書く | 期待値の出所をヘッダーに残す。**機械で検査できる印** | (1)(2) |
| 0.3 検品する | コンパイル / 独立性 / 検出力の 3 つをコマンドで | (3)(4) |
| 0.4 網羅の数え方 | 設計書の条項に対して。特性化は数えない | — |
| 0.5 書けないとき | 壁 1（鶏と卵）と上から埋める順序。RPG III は不可 | — |

## 書式

ヘッダーは `VERIFICATION` / `CHARACTERIZATION` のどちらかを必ず含む。
**H 仕様より前の注記行**として書ける（実機で確認済み）。
