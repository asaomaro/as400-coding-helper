# レビュー: 編集の検証に DDS の種別を渡す

## ラウンド 1（2026-08-27）

### 要件適合
- AC1 ✓ 画面ファイルで **1 行 1 桁**への移動・追加・桁移動を断る。
  ※ 要件は「1 桁目」と書いていたが、実機に判定させた結果**1 行 1 桁だけ**が正しかった
  （`decisions.md` D1）。要件の方を実機に合わせた。
- AC2 ✓ 帳票では 1 行 1 桁も通す（属性文字が無い）。
- AC3 ✓ 必須引数。任意にすると渡し忘れが黙って検査を消す。
- AC4 ✓ `row-from-spacing` は帳票だけ。
- AC5 ✓ 本番の呼び出し 3 か所（デザイナ / CLI / 単独起動）が種別を渡す。
  **必須にした瞬間にコンパイルエラー 4 件が出て、それが洗い出しの手段になった。**

### 価値適合
狙いは「コンパイルが通らない編集を断る」。調べたら**起票の前提が半分まちがっていて**、
広く断ろうとしていたものの大半（重なり・はみ出し・2 行以降の 1 桁目）は
**実機が通す**形だった。断るのは実機が通さない 1 行 1 桁だけにした。

そのうえで**別の欠陥が出た**——`layout-column-one-reserved`（既定 ON・error）が
行を見ずに報告しており、**実機で通るソースを誤検出**していた。
誤検出は「正しいソースが CI で落ちる」に直結し、規則そのものを無視させる。

### 正確性
- 判定（`isRowOneColumnOne`）と文面（`COLUMN_ONE_MESSAGE`）を診断と編集で**共有**した。
  同じ規則を 2 か所に書かない。
- 実機の結果を注記に表で残した（どの位置が通るか）。
- 既存の判断（「規則違反は拒否しない」）を**否定せず**、実機で通るものは通すという
  形で保った。テスト名も「実機が通す形は拒否しない」に直した。

### 規約適合
- AGENTS.md「原典と実機が食い違ったら、実機のパーサーに判定させる」。
  判定は**副作用の無い形**（コンパイルするだけ。作ったファイルは消した）。
- 配線漏れの予防を**コンパイルエラー**で行った（grep 検査より確実）。

### 保守性
`EditableDdsType` を `DDS-PF` を含まない形にしたので、
「PF を編集しようとしたら」を考えなくてよい。

### 指摘
must 0 / should 0 / nit 0。

**副作用として直したもの**: `layout-column-one-reserved` の誤検出（D2）。
同梱サンプルには該当が無かったため CI の結果は変わらないが、
**利用者のソースでは落ちていた可能性がある**。
