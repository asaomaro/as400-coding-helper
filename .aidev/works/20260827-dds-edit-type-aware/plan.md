# 計画: 編集の検証に DDS の種別を渡す

## 作業順序と依存関係
1. `EditableDdsType` と引数追加（コンパイルを落として呼び出し元を洗い出す）（依存: なし）
2. 呼び出し元 3 か所を直す（依存: 1）
3. テスト 7 ファイルを直す（依存: 1）
4. 1 桁目の検査（依存: 1）
5. 行送りを帳票だけに（依存: 1）
6. テストを足す（依存: 4, 5）
7. 回帰

## リスク / 留意点
- **コンパイルエラーの数で呼び出し元の網羅を確かめる**（洗い出しの手段そのもの）。
- CLI のテスト「配置の指摘が増える編集は書かない」は、1 桁目が**より手前で**
  断られるようになるので題材を替える（はみ出しにする）。

## テスト方針
- 画面で断り、帳票で通ることを両方見る。
- 断ったときにソースが変わらないことまで見る。
- **直す前に戻して落ちることを確かめる。**
