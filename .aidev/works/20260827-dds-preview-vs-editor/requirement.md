# 要件: プレビューとビジュアルエディタの使い分けを案内する

## 背景 / 課題

DDS には**器が 2 つ**ある。

- **プレビュー**（`showDspfPreview` / `showPrtfPreview`）— 右クリックから開く WebView パネル。
  テキストエディタの**横**に出る。
- **DDS ビジュアルエディタ**（`rpgClSupport.ddsVisualEditor`）— `CustomTextEditor`。
  テキストエディタを**置き換える**。

どちらをいつ使うのかがどこにも書かれていない。**しかも片方は事実上到達できない**——
ビジュアルエディタは `contributes.customEditors` にしか無く、コマンドもメニュー項目も持たない。
既定のエディタも奪わない（`priority: "option"`）ので、**「エディターで開く…」を知っている
利用者しか辿り着けない**。

出所: `20260826-dds-editor-port` の `review.md:63`「利用者から見た使い分けの案内は無い」。

## 目的 / ゴール

**2 つの器が同じ場所に並んで見え、どちらを選ぶかを利用者がその場で決められる状態**。

紐づく charter ゴール: DDS の視覚的な確認と編集（第 4 の柱）。

## ユーザーストーリー

- US1: DDS を書く開発者として、**ビジュアルエディタの存在に気付きたい**。
  なぜなら「エディターで開く…」を知らないと**機能があること自体が分からない**から。（受け入れ: AC1, AC2）
- US2: DDS を書く開発者として、**読むだけなのか編集するのかで器を選びたい**。
  なぜなら編集の器はテキストエディタを置き換えるので、**ソースを見ながら確認したいときには向かない**から。（受け入れ: AC3）

## スコープ

### 対象
- ビジュアルエディタを開くコマンドと右クリック導線
- コマンド名（`title`）が器の役割を表すようにする
- 使い分けの文書

### 対象外
- 既定のエディタを奪う（`priority` は `option` のまま）
- プレビュー / エディタの機能そのものの変更

## 完了条件 (受け入れ基準)

- [ ] AC1: ビジュアルエディタが**右クリックから開ける**（`.dspf` / `.mnudds` / `.prtf`）
- [ ] AC2: 導線の対象拡張子が**カスタムエディタの `selector` と一致**することを機械検査する
      （AGENTS.md「追加したリソースは到達可能になって初めて完了」の配線検査）
- [ ] AC3: コマンド名から「読む器 / 編集する器」が読み取れる
- [ ] AC4: 使い分けが文書にあり、両器の**できること・できないこと**が具体的に書かれている
