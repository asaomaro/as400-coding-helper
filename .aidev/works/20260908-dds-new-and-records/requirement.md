# 要件: DDS を一から作れるようにする（新規作成とレコード様式）

## 背景 / 課題

ビジュアルエディタは**既存の DDS を直す道具**であって、**作る道具ではない**。
入口が塞がっていることを実測で確かめた。

| 確かめたこと | 結果 |
|---|---|
| エディタの登録 | `customEditors` の `selector` は `*.dspf` / `*.mnudds` / `*.prtf`、`priority: "option"`。**既存ファイルにしか付かない**。新規作成のコマンドは無い |
| 空ファイルを開いたら | `records: []` / `items: 0`。項目を置こうとすると **`record-not-found`「レコード様式 REC1 が見つかりません」** |
| 編集の語彙（`DdsEdit`） | `move` / `moveColumn` / `resize` / `remove` / `setAttributes` / `setKeywords` / `setCondition` / `setKeywordCondition` / `clearAlternatePosition` / `renameRecord` / `add`（既存様式への項目追加）。**`addRecord` / `removeRecord` が無い** |

**項目はレコード様式の中にしか置けない。** 様式が 1 つも無いファイルには何も置けず、
空ファイルを開いても行き止まりになる。様式は*名前を変えられる*だけで、*作れない*。

## 目的 / ゴール

**テキストエディタに一度も戻らずに、DSPF / PRTF を一から作り上げられる状態。**
新規作成から最初の項目を置くまでが、デザイナの中だけで完結している。

紐づく charter ゴール: **DDS（DSPF/PRTF）の視覚的な確認と編集を第 4 の柱として加える**

## ユーザーストーリー

- **US1**: 画面を新しく作る開発者として、**空のファイルからではなく、すぐ項目を置ける状態で**
  DSPF を作り始めたい。なぜなら、いまは新規作成の導線が無く、**テキストエディタで様式を手書きしてから
  でないとデザイナが使えない**から。（受け入れ: AC1, AC2, AC3）
- **US2**: 画面を作る開発者として、**様式を増やせる**ようにしたい。なぜなら、実用的な画面は
  見出し・明細・機能キーなど複数の様式で構成され、**1 つでは何も作れない**から。（受け入れ: AC4, AC5）
- **US3**: 画面を作る開発者として、**間違えて足した様式を消せる**ようにしたい。なぜなら、
  消せないとテキストエディタに戻ることになり、**US1 のゴールがその時点で崩れる**から。（受け入れ: AC6, AC7）
- **US4**: この拡張を VSCode の外で使う人として、**単独起動でも同じことができる**ようにしたい。
  なぜなら、スタンドアロンが本体で VSCode は埋め込み先の 1 つ、という設計（C1）を保つため。（受け入れ: AC8）

## スコープ

### 対象

- **新規作成の導線**。入口は**ホスト側**に置く（VSCode はコマンドと右クリック、単独起動は帯のボタン）。
  ファイル操作は `providesFileIO` ＝ ホストが肩代わりするものなので、C1 の方針に沿う。
- **雛形の中身は core が持つ**。両ホストで同じファイルができる。
- **雛形は最小限動く形**：DSPF は `DSPSIZ` ＋ 様式 1 つ、PRTF は様式 1 つ。
- **レコード様式の追加**（左ペインの一覧の見出しから）。
- **レコード様式の削除**（中の項目ごと消えるので、件数を示して確認を取る）。

### 対象外

- **罫線**（`20260908-dds-ruled-lines` で扱う）。
- 様式の**並べ替え**（順序はソースの並びで決まる。今回は末尾に足すだけ）。
- サブファイル（`SFL` / `SFLCTL`）の対の自動生成。様式は 1 つずつ足す。
- 既存ファイルの**種別変換**（DSPF ↔ PRTF）。

## 機能要件

1. 新しい DSPF / PRTF を作れる。作成直後に**そのままデザイナで開き、項目を置ける**。
2. 雛形は core の 1 か所で組み立て、**VSCode と単独起動で同一の内容**になる。
3. DSPF の雛形は `DSPSIZ` を**明示する**。省くと IBM 提供の画面サイズ条件名で条件付けされる
   （原典: 「ユーザー定義の画面サイズ条件名を指定しない場合には、IBM 提供の画面サイズ条件名を
   使用して条件付ける」）。
4. レコード様式を追加できる。名前は利用者が決め、**DDS の名前規則**（10 桁以内・英数字）で検証する。
5. 同じ名前の様式は作れない（重複を弾く）。
6. レコード様式を削除できる。**中の項目の件数を示してから**消す。
7. 追加・削除は既存の編集経路（`DdsEdit` → 書き戻し）に乗る。**undo は既存の仕組みで効く。**

## 非機能要件 / 制約

- **既存の桁を崩さない**。無変更で確定したとき、元のバイト列と一致すること（既存の検証と同じ基準）。
- **UI に `vscode` を持ち込まない**（`tsconfig.webview.json` の `types: []` と単体テストが見張っている）。
- 雛形の内容は**原典と照合できる形**にする（`DSPSIZ` の既定値・様式名の規則）。
- **3 ペインの構成は変えない**（C1 で「移植可能性の核心」と決めた）。

## 完了条件 (受け入れ基準)

- [ ] AC1: VSCode で「新規 DSPF」「新規 PRTF」を実行すると、ファイルが作られビジュアルエディタで開く
- [ ] AC2: 作成直後のファイルに、**テキストを一切触らずに**フィールドと定数を置ける
- [ ] AC3: 作られた DSPF に `DSPSIZ` が入っており、PRTF・DSPF とも様式が 1 つある
- [ ] AC4: 左ペインの一覧から様式を追加でき、追加後すぐその様式に項目を置ける
- [ ] AC5: 既存と同じ名前・DDS の名前規則に反する名前は弾かれ、**理由が画面に出る**
- [ ] AC6: 様式を削除でき、**中の項目も一緒に消える**
- [ ] AC7: 削除したら**消えた項目の件数**が知らされる（`EMPDTL を削除しました（項目 7 件）`）。

- [ ] AC11: 削除した様式を指す参照（`&名前` / `CSRLOC` / `HLPARA(*FLD)`）が残ったら、
      **検証タブに出る**。**黙って書き換えない**（書き換わると原因が掴めない）
- [ ] AC8: 単独起動ハーネスでも AC1〜AC7 と同じことができる（`dev/e2e.mjs` で確かめる）
- [ ] AC9: 追加・削除の直後に undo で元に戻る
- [ ] AC10: 既存の 196 件の e2e と 1167 件の単体テストが通り続ける
- [ ] AC12: 様式が 0 件のファイル（既存の空ファイル）でも `＋` を押して様式を作れる

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: 一覧の見出しの `＋` で**名前の入力欄がその場に開く**。`Esc` で閉じ、
      **入力中の値は捨てる**（様式は作られない）
- [ ] AC-I2 確定 / 取り消し: `Enter` で確定、`Esc` で取り消し。取り消したらファイルは変わらない。
      削除は**即座に効き、undo で元に戻る**（2026-09-08 修正。元は「確認を経てから消え」と
      書いていたが、AC7 で「確認ダイアログは出さない」と決めたのと矛盾していた。
      AC7 が後の判断なのでそちらに揃えた）
- [ ] AC-I3 キーボードだけで完結するか: `＋` に Tab で到達し、名前を打ち、`Enter` で作り、
      作った様式が**選択された状態**になるまでマウス無しで通せる
- [ ] AC-I4 フォーカスの行き先: `＋` を押したら入力欄へ移る。確定したら**作った様式の行**へ、
      取り消したら `＋` へ戻る。削除したら**隣の様式の行**へ移る（消えた行に残らない）
- [ ] AC-I5 既存の操作を妨げないか: 入力欄の上のキーを**キャンバスへ漏らさない**
      （漏らすと `Delete` で項目が消え、矢印で項目が動く。プロパティの入力欄で既に踏んだ罠）

## 未確定事項 / 確認したいこと

- **名前の入力手段**。既存の項目追加は `askItem`（ホストが入力箱を持つ）だが、
  様式の**改名は一覧の中のインライン入力**で既に実装されている。追加も同じ形にできるはずで、
  そちらの方が AC-I3 を満たしやすい。design で決める。
- **PRTF の雛形に `DSPSIZ` 相当は要らない**（紙面は `CRTPRTF` の `PAGESIZE` で決まり DDS には書かれない）。
  この非対称を利用者にどう見せるか（何も出さないか、注記を出すか）。
- 新規作成時の**保存先の決め方**（VSCode は保存ダイアログか、ワークスペース直下か）。
