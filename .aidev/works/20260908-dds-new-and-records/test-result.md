## 失敗の証跡

**製品の欠陥による差し戻しはこのラウンドで発生していない**（`sent_back` 0 回）。
ただし、**検証を書いている途中で 3 件の FAIL を観測した**ので、その生出力を残す。
うち 1 件は coding 中に見つけた製品の欠陥（既に直っている・`decisions.md` D1）、
2 件は**テスト側の誤り**だった。

### (1) 製品の欠陥（coding 中に e2e が捕まえた。`decisions.md` D1 で修正済み）

```
$ node dev/e2e.mjs
PASS **足した様式が選ばれ、その見出しに焦点がある**
FAIL ✕ で様式と中の項目がまとめて消える（確認は出ない） — 6 → 5 行（項目 0 件）
PASS **消えた件数が知らされる** — FOOTER を削除しました（項目 0 件）

=== 207/208 PASS ===
```

件数が 0 件になったのは、置いたはずの項目が **FOOTER ではなく REC1 に入っていた**ため。
`recordAt` の順序（行の見当が選択より先）が原因で、
**足したばかりの様式は項目が 0 件なので行の見当では絶対に引っかからない**。
順序を「選択中の見出し → 行の見当 → 末尾」に直して解消（`decisions.md` D1）。

### (2) テスト側の誤り: セレクタが入れ子の項目まで拾っていた

```
$ node dev/e2e.mjs
FAIL 削除したら**隣の様式**へ焦点が移る（消えた行に残らない） — '脚注'
```

`.dds-tree li.record .label` は**入れ子の項目の label まで一致する**ので、
隣の様式のつもりで項目のリテラル（`'脚注'`）を拾っていた。
`:scope > .label`（見出しの直下）に直した。**製品は正しく隣へ移っていた。**

### (3) テスト側の誤り: 期待そのものが事実と違っていた

```
$ node dev/e2e.mjs
FAIL **消えたフィールドを指す参照も出る**（CSRLOC / SFLCSRRRN） — "record-reference-not-found2 行目PASSRCD が指す様式 MAIN がありませんrecord-reference-not-found3 行目ERASE が指す様式 MAIN がありません"
```

見本（`references.dspf`）では `CSRLOC(CSRROW CSRCOL)` と `SFLCSRRRN(&SFLRRN)` が
**消した `MAIN` 自身のレコード・レベルのキーワード**なので、指す先のフィールドと
**一緒に消える**——出ないのが正しい。期待を「この形では指摘にならない（偽陽性を出さない）」に
書き換えた。別の様式から中のフィールドを指す形は単体テストが見ている
（`ddsNewAndRecords.test.ts`「消えたフィールドを指す参照も検証に出る」）。

> **AGENTS.md「落ちることの確認は、期待値の正しさを保証しない」の実例が 2 件出た。**
> どちらも「落ちた＝製品が悪い」ではなく、テストの方が誤っていた。

## 未検証の穴

- **VSCode の実 UI では押していない。** 新規作成コマンドの検証は
  `vscode` スタブ（`test/support/vscode-stub.js`。今回 `showSaveDialog` /
  `workspace.fs` / `showErrorMessage` を足した）と統合テストの範囲。
  **本物の保存ダイアログの見え方・右クリックメニューの並び順**は目視していない。
  一方、`＋` / `✕` / 焦点・キーの取り回しは**同じ UI コードが単独起動で動いている**
  （`ui.ts` はホストに依らない）ので、e2e の 25 件がそのまま効く。
- **PRTF の雛形（様式 1 つだけ）が `CRTPRTF` を通るかは未確認。** 実機に投げていない。
  この機能に作成直後のコンパイル経路が無く、受け入れ基準にも入っていない（spec で判断済み）。
  利用者は項目を置いてから作成するので、そこで初めて実機に当たる。
- **統合テストは webview の中身を見ていない。** 3 件は「例外なく起動する」までで、
  `npm run test:integration` が走らせるのは `npm run compile`（tsc のみ）なので、
  **束ねた資産（`out/dds-webview`）が無くても通る**。実際、
  `out/` を消した状態で走らせたとき、プロンプターの webview 資産が読めていない
  （`Webview.loadLocalResource - Error using fileReader`）のに 3 件とも通った。
  今回の変更が原因ではない**既存の穴**なので直していないが、
  「統合テストの緑は webview が描けている根拠にならない」ことは記録しておく
  （retro / follow-up 向き）。
- skip された検証は **0 件**（どのランナーも skip を出していない）。
