# DDS ビジュアルエディタ 探索メモ（2026-09-27）

本物の VS Code（1.137.0）で空の `.dspf` / `.prtf` から画面・帳票を作り、エディタの不足・不具合を記録する。
操作は `driver.mjs`（常駐・HTTP で JS 断片を実行）。画面は `shots/`。

## 画面（DSPF）

- **D1 ファイル・レベルのキーワードを 1 つ目から足す手段が無い**（不足・重大）。空のファイルでは一覧に「ファイル」の節が出ない
  （`ui.ts` の `if (model.fileKeywords.length > 0)`）。`DSPSIZ`・`INDARA`・`CAnn` を最初に書く場所がエディタに無く、テキスト側で書くしかない。
- **D2 様式の「＋ 追加」がファイル・レベルのキーワードも受け付ける**（不具合）。候補一覧には出ないが、`DSPSIZ` と打って Enter で
  様式の行に `DSPSIZ()` が付く。検証タブは `keyword-wrong-level` を出すが、書き込み自体は止めない。
- **D3 引数が要るキーワードを空の括弧 `()` で書く**（不具合）。`DSPSIZ()` は実機でコンパイルできない形だが、検証タブも指摘しない。
- **D4 `DATE` / `TIME` / `SYSNAME` / `USER` の項目（文字列を持たないキーワードだけの定数）を作れない**（不足）。「定数を置く」は空の文字列を
  黙って捨て（何も起きない・何も言わない）、置いた定数のキーワード欄を `DATE EDTCDE(Y)` に書き換えると「固定情報（定数）のキーワード欄は
  リテラルで始まる必要があります」で弾く。画面の見出しに日付・時刻を出す定石が作れない。
- **D5 書き換えを弾いたあと、ツールバーの状態が「適用中…」のまま戻らない**（不具合・軽微）。理由はプロパティ欄に出ているのに、状態表示は
  処理中のまま。
- **D6 フィールドを置くと型 `A`・使用 `B`（両用）が既定**。名前と桁数しか聞かない。数値の出力項目を作るには置いたあとプロパティで型・小数・使用を
  直す 2 段になる（不足・軽微）。
- **D7 空行・入力の自動インデント**（エディタ外・軽微）。`.dspf` は言語登録していないので、テキスト側で改行すると前の行の先頭の空白を
  引き継ぎ、固定長の桁がずれる（`R HEADER` が 5 桁右へずれ、エディタは `R HEADE` という様式と「様式の外」の項目として描いた）。
- **D8 キーワードに条件（標識）を付けられない——既に別の行に書かれているキーワードだけ**（不足・重大）。条件の欄（「キーワード行」）は
  継続行に分かれているキーワードにしか出ない（`describeConditionalKeywords` が 2 群目以降だけを出す）。キーワードの生テキストは 1 行の入力で、
  行を分ける手段が無い。`40 COLOR(RED)` のような**標識で属性を切り替える定石**が一から作れない。
- **D9 使用を `H`（潜在）に変えても位置（行・桁）が残る**（不具合の疑い）。エディタ自身は「位置: 画面に出ない用途」と表示するのに、
  ソースは `CUSKEY 7S 0H  8  3` のまま（実機のコンパイルで確かめる）。潜在フィールドを最初から位置なしで置く手段も無い。
- **D10 様式（レコード）・レベルのキーワードに条件を付けられない**（不足・重大）。様式のプロパティはキーワードの一覧と生テキストだけで、
  条件の欄が無い。サブファイル制御の `31 SFLDSP` / `N32 SFLCLR` / `34 SFLEND` のような**標識つきの様式キーワードが一から作れない**——
  サブファイル画面が組めない。
- **D11 キーワードの自動の折り返しが語の途中で切る**（軽微）。`WDWTITLE((*TEXT '顧客詳細') (*COL-` / `OR WHT))`。`-` 継続なので
  文法上は正しいが、ソースが読みにくい（語の区切りで折れば避けられる）。
- **D12 ウィンドウ様式（`WINDOW`）を描かない・位置を画面の絶対位置として描く**（不具合・重大）。`WINDOW(8 20 9 44)` の枠が出ず、
  ウィンドウ内の `2 2'コード：'` が画面の 2 行 2 桁（見出しの上）に描かれる。ウィンドウの中身は枠からの相対位置（実機では 10 行 22 桁あたり）。
  重なりの検査も絶対位置で判定することになる。
- **D13 サブファイルは 1 行しか描かない**（改善）。`SFLPAG(0012)` でも 7 行目の 1 行だけ。実機では 7〜18 行に 12 行並ぶ。
- 良かった点: 様式・項目・定数の追加、型・小数・使用の変更、ファイル／様式のキーワードの生テキスト編集、2 バイト文字の桁勘定
  （`'検索（顧客名）：'` と入力欄の重なりを検証タブが正しく指摘）。
- **D14 置き先の様式が「選んでいる様式」ではなく「クリックした場所にある様式」になる**（不具合・重大）。`WIN01` を選んでから
  2 行 2 桁などに置くと、そこに描かれている `SFCTL01` の項目の様式に入る。8 行目に置いた定数は 3 回とも `SFL01`（7〜8 行を占める）に入った。
  **何も言わずに別の様式へ入る**ので気づけない。ウィンドウ様式（D12）と重ねて使う場面で必ず踏む。
  - 原因は仕様（`ui.ts:2641` `recordAt`）: **様式の見出しを選んでいても、その様式に描かれた項目が 1 つでもあれば選択は無視され**、
    「押した行以上でいちばん下にある項目」の様式に入る。`FOOTER`（23〜24 行）を選んで 22 行目に置いた定数は `SFL01`（7 行目）へ、
    `SFCTL01` を選んで 5 行目に置いた罫線は `WIN01`（ウィンドウの項目が絶対位置で 2〜6 行に描かれる）へ入った。
    明示した選択より行の見当が勝つので、**置き先を利用者が決められない**。
- **D15 項目を別の様式へ移す手段が無い**（不足）。D14 で誤った様式に入った項目は、削除して置き直すしかない（置き直しても D14 で同じ所へ入る）。
- **D16 1 行（80 桁）に収まらない定数を継続行に分けずに書き、ファイルの構造が壊れる**（不具合・重大）。全角の `─` を 38 文字（SO/SI 込み 78 桁）の
  罫線として置くと、`5  2'────…'` を 1 行に書く。キーワード欄 45 桁目から始まるので 80 桁を大きく超え、**リテラルが閉じないまま後続の行を
  飲み込む**——一覧から `FOOTER` と `WIN01` が消え、`R FOOTER` の `OVERLAY` が 5 行目の文字として描かれた。検証タブは桁あふれを指摘しない。
  定数は `-` 継続で折る必要がある（キーワードの生テキストの折り返しはできているのに、定数の文字列では折っていない）。
  （罫線を置いた様式も D14 で `SFCTL01` になっていた。）
- **D17 D16 で壊れた定数を消すと、飲み込まれた後続の行（別の様式まるごと）も一緒に消える**（不具合・重大・データ消失）。
  長い罫線の定数を選んで Delete を押すと、`R FOOTER` 以下 9 行（`FOOTER` と `WIN01` の様式・項目）が消えた。
  エディタの Ctrl+Z で元に戻せた（元に戻す自体は効く）。

### 実機でのコンパイル（v1: エディタが書いたままのソース。`v1/CMPLXD.dspf`）

`CRTDSPF` は `CPF7311` で作成できない。リスト（スプール `CMPLXD`、QPRTJOB）の誤りは、上の指摘をそのまま裏づけた:

| メッセージ | 重大度 | 箇所 | 対応する指摘 |
|---|---|---|---|
| CPD7443 使用目的が H または P の場合には，フィールド（位置）をブランクにしなければならない | 20 | `CUSKEY` `RRN1` | D9 |
| CPD7490 示されたキーワードにはオプション標識が必要である | 20 | `SFLCLR` など（SFCTL01） | D10 |
| CPD7508 引用符つきストリングの終わりにアポストロフィがない／CPD7596 | 20/30 | 罫線の定数（80 桁で切れた） | D16 |
| CPD7866 条件づけの無い別のフィールドと重なる | 10 | ウィンドウの項目が `SFCTL01` に入った所 | D14 |

- **D18 エディタの検証が、実機で重大度 20 以上になる誤りを 1 つも指摘しない**（不足）。上の CPD7443 / CPD7490 / CPD7508 はいずれも
  ソースの形だけで判定できる（位置欄の有無と使用、`SFLCLR` 等の標識の有無、80 桁あふれ）。検証タブは `overlap` と `keyword-wrong-level` だけだった。

## 帳票（PRTF）

- **P1 行送り（`SPACEx` / `SKIPx`）で行が決まる様式にも、置くと行番号（39-41 桁）を書く**（不具合・重大）。`SKIPB(3)` の `PHEAD` に置いた
  `'CMPLXP'` は `3  2'CMPLXP'`。実機は **CPD7860（重大度 30）「スペースまたはスキップ・キーワードと一緒に行番号を使用することはできない」を 19 件**
  出して作成できない（v1）。文書（`docs/dds-editor-and-preview.md`）は「行送りで決まる項目は桁だけ動かせる」としているのに、置く操作は行を書く。
  行送りの様式に置いたら桁だけを書くべき。行番号を外すと作成できた（v2）。
- **P2 置いたフィールドの使用が `B`（両用）になる**（不具合）。印刷装置ファイルの使用は空白・`O`・`P` だけで、`B` は誤り。プロパティの「使用」の
  選択肢も画面用（I / O / B / H）がそのまま出る。検証タブも指摘しない。
- **P3 1 行に収まらない定数（D16 と同じ）**。80 桁の罫線 `'----…'` を 1 行に書き、後続の様式（`PRULE`・`PDETL`）が一覧から消えた。
  38 文字でも 45 桁目から書くと 84 桁で溢れる（1 行に入る文字列は 34 文字まで）。
- **P4 プロパティの文言が画面用のまま**（軽微）。帳票でも「占有: …（属性文字を含む）」「名前を変えると … CSRLOC / HLPARA(*FLD) も一緒に変わります」と出る。
- 良かった点: **重なりの検証が行送りを解いたうえで判定する**。`PRULE`（`SPACEB(1)`）の直後の `PDETL` を `SPACEA(1)` にしていた設計の誤り
  （罫線と同じ行に明細が重なる）を「実機では 2 重印刷になります」と正しく指摘した。行番号を外したあとの一覧も行送りから行を求めて表示する。

### 罫線（画面）

- **D19 画面の罫線のキーワード（`GRDRCD` / `GRDATR` / `GRDBOX` / `GRDLIN` / `GRDCLR`）を知らない**（不足）。候補（様式レベル 99 件）に無く、
  生テキストで書くと「?」のチップ（解説なし）になり、キャンバスにも線を描かない。実機は受け付ける（v3: `GRID01` に `GRDRCD` `GRDATR`
  `GRDBOX((*POS (5 1 18 80)) (*TYPE PLAIN))` `GRDLIN((*POS (6 2 78)) (*TYPE UPPER))` を書いて `CRTDSPF` が通った。ts5250 の
  `scripts/build-gridtest6.mjs` でも実機で罫線が出ることを確かめている）。原典の索引（`docs/origin/dds/DSPF-KEYWORDS.html`）に載っていないのが
  原因と見られる——エディタ側の辞書の取りこぼし。画面で罫線を引く手段がエディタに無い（全角の `─` の定数で代用するしかない）。

### エディタで作れず、テキスト側で直した箇所（＝エディタの不足の一覧）

| 箇所 | 理由 |
|---|---|
| ファイル・レベルの `DSPSIZ`（1 つ目） | D1 |
| `SFCTL01` の `31 SFLDSP` / `32 SFLDSPCTL` / `33 SFLCLR` / `34 SFLEND` | D10 |
| `STS` の `40 COLOR(RED) DSPATR(RI)`（継続行に分けた） | D8 |
| `CUSKEY` / `RRN1` の位置欄を空ける | D9 |
| ウィンドウの項目 4 行と `'F12=戻る'` を `WIN01` へ移す／置く | D12・D14・D15 |
| `FOOTER` の条件付き定数・罫線 2 本を正しい様式へ移す | D14・D15 |
| 1 行に収まらない罫線の定数を削る／34 文字に縮める | D16・P3 |
| 帳票の全項目の行番号（39-41 桁）を空ける | P1 |

### エディタ外で分かったこと（参考）

- 既存の `ASAOLIB/QDDSSRC` は CCSID 1027（1 バイト文字だけ）で、ここへ写すと DDS の日本語の定数が空白になる（初回の実行で画面の日本語が全部消えた）。
  CCSID 5035 の `QDDSJ` を別に作って解決。エディタの問題ではない。
- ウィンドウの見出し（`WDWTITLE((*TEXT '顧客詳細'))`）だけが ts5250 の画面で文字化けした。ソースと他の日本語は正しいので、
  ts5250 のウィンドウ見出し（WDSF）の DBCS の扱いの問題と見られる（未確認・ts5250 側）。
