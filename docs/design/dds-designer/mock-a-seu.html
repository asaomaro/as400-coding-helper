このパターンの狙いとトレードオフ

  • 狙い1: 学習コストゼロ。 用語（レコード様式 / 条件標識 / 桁 / Fキー）も配色も 5250・SDA のまま。既存の AS/400 開発者が説明なしで触れる。
  • 狙い2: 桁勘定を裏切らない。 セル幅は CSS 変数 --cell-w(px) で固定し、全角は calc(var(--cell-w) * 2)。ch 単位（"0"の幅）は全角幅と一致しないため使用していない。
  • 狙い3: DBCS の SO/SI を可視化。 実機で1桁ずつ消費される SO/SI を { } として実体化。例: 1行2桁の {社員マスタ保守} = 1 + 7文字×2 + 1 = 16桁（2-17桁）。
  • 狙い4: 様式はレイヤー、標識はトグル。 アクティブ様式だけが編集可・他は薄く固定。標識 ON/OFF で条件付き表示を即プレビュー。
  • トレードオフ: 端末風の低コントラスト配色と情報密度は新規参入者・マウス主体の利用者には不親切。プロパティ編集は右パネルの1枚に集約せざるを得ず、複雑なキーワード（SFLCTL 群など）の GUI 化は本パターンでは表現しきれない。
