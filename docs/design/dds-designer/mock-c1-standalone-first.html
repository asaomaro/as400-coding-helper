C1：スタンドアロン優先設計独立した DDS エディタとして作り、VSCode は「埋め込み先の 1 つ」として後から足す

  
    
    
  • 既定はスタンドアロン。初期状態 data-host="standalone" で、自前ヘッダ・ファイル操作・undo/redo・コマンドパレット・ヘルプ・ステータスバー・検証パネルをすべて自前で持つ。VSCode の外観（アクティビティバー・タブ・問題タブ）は模倣していない。
    • 
    
  • 減算ではなく加算。CSS の既定は「自前部品を表示」。data-fileio="host" のようにホストが肩代わりする宣言が来たときだけ、その部品を降ろす。ホスト固有機能は .hostadd{display:none} が既定で、能力があるときだけ足される。
    • 
    
  • host の意味を反転。「何が使えるか」ではなく「ホストが何を肩代わりするか」。providesFileIO / providesUndo / providesCommandPalette（＋提案として providesTitle / providesStatusBar）が降ろす側、canOpenTextEditor / hasPrompter が足す側。
    • 
    
  • 検証パネルは自前設計。問題タブの行リストではなく、1 件ごとにカード化し、80 桁のミニストリップで問題の桁範囲を図示し、修正案を添える。DDS 固有の情報量に合わせた形。
    • 
    
  • 引き継いだ核。3ペイン、双方向の選択連動（#n 行番号）、差分バッジと「未変更 N 行はバイト単位で不変」、SO/SI トグル（OFF で −2 桁のズレを可視化）、属性バイトと DDS7103、5250 配色、ズーム、桁勘定の計算関数は b2 と同一のものを使用。
    • 
    
  • 切替の検証。ヘッダ右の「モック: ホスト」で VSCode 埋め込みに切り替えると、ファイル操作・undo/redo・パレット・ファイル名・ステータスバーが降り、「テキストで開く」「F4 プロンプター」が足される。3ペインとキャンバス、ドック、検証は 1 ピクセルも変わらない。
    • 
  







  
未解決 — VSCode に埋め込んだときに collision する箇所

  
スタンドアロン優先で設計したものを VSCode モードに載せ替えたとき、レイアウトは無改造で収まった（3ペイン・キャンバス・ドック・検証・プロパティは不変）。一方で、UI を隠すだけでは解けない衝突が 5 件残る。いずれも「表示の出し分け」ではなくホストとの責務分担そのものの問題。

  


    

      
未解決キーバインドの取り合い

      
ホストへ丸ごと委譲できるキー（Ctrl+S 保存 / Ctrl+Z・Ctrl+Y undo / Ctrl+K パレット）は UI ごと降ろせば済む。問題は降ろせない 4 つ—Ctrl+= Ctrl+-（キャンバスのズーム）、Ctrl+Shift+M（検証へ移動）、Ctrl+/（ショートカット一覧）。DDS デザイナ固有の機能なのに VSCode が同じキーを先に解決する。WebView 側で握り潰すとホストのコマンドが死に、通すと自前機能が無反応になる。両立する設定は無い。

      
暫定：VSCode モードでは自前キーを無効化し、拡張側で DDS: プレフィックスのコマンドとして再登録して別キーを割り当てる。ヘルプ一覧では該当キーに取り消し線＋「VSCode が先取り」を表示（実装済み・ヘッダの「⚠ キー衝突 4」から確認可）。

    


    

      
未解決undo スタックの二重化

      
スタンドアロンでは自前の編集履歴が必須。一方 VSCode の CustomTextEditor では編集を WorkspaceEdit として発行し undo をホストへ委譲するのが正道。UI は隠せてもモデル層の分岐は残る（自前スタック / ホスト委譲の二系統）。

      
方針案：編集を必ず「ドキュメント差分（パッチ）」として表現し、適用先だけを差し替える。スタンドアロンではパッチを自前スタックへ、VSCode ではホストへ渡す。コア側に undo API を持たせないのが条件。

    


    

      
部分解決dirty 表示の粒度が落ちる

      
自前ヘッダは「未保存の変更 3 行」というDDS 固有の粒度を出せるが、VSCode のタブは ● しか出せない。providesTitle で自前表示を降ろすと、この情報が消える。

      
暫定：ソースペインのヘッダ（変更 1 行 / 追加 2 行 / 未変更 10 行）へ退避させ、ヘッダからは落とす。降ろす代わりに情報が失われる典型例。

    


    

      
部分解決ステータス項目の置き場

      
自前ステータスバーは providesStatusBar で降ろせるが、CCSID・SO/SI 状態・選択桁は VSCode のステータスバーに出せない（WebView からは StatusBarItem を登録できず、拡張本体の協力が要る）。

      
方針案：host メッセージに setStatusItems([...]) を足し、拡張側が代理登録する。host インターフェースの拡張が必要で、現行の 6 フィールドでは足りない。

    


    

      
未解決ズーム操作の二重適用

      
自前のキャンバスズーム（--cell-w）と VSCode のエディタズーム（Ctrl+=）が同時に効き、桁ルーラーが二重に拡大する。桁位置の正確さが売りの画面で実寸が信用できなくなる。

      
暫定：VSCode モードでは自前ズームを％表示だけにして Ctrl+= をホストに譲る／もしくは WebView に zoom 非追従を宣言する。どちらも一長一短で未決。

    


    

      
意図的テーマが VSCode と揃わない

      
独自パレット（--vscode-* 参照ゼロ）のため、埋め込むと配色がホストのテーマから浮く。これはスタンドアロンを正とした帰結で、バグではない。

      
選択肢：任意適用のブリッジ層（--vscode-editor-background → 自前トークン）を被せられるようにする。ただし被せると見た目の二重管理が発生するため、既定は独自パレットのままとする。
