# DDS デザイナ 画面デザイン

DDS（DSPF/PRTF）の視覚的編集の**画面デザイン**。ここにあるのは検討時のモックアップ（HTML）と、
**どれを採ったか**の記録。実装の設計判断は各 work の `design.md` / `spec.md` にある。

## 確定案: **C1（スタンドアロン優先）**

`mock-c1-standalone-first.html` を確定案とする（ユーザー判断 2026-08-27）。

**根拠**: 本 PJ の意図は「VSCode 非依存の独立したエディタとして作り、VSCode 拡張はそれを取り込む」。
スタンドアロンが本体で、VSCode は埋め込み先の 1 つ。したがって
**「VSCode で作ってスタンドアロンでは消す」（減算）ではなく「スタンドアロンで完結させ、
ホストが肩代わりする分を降ろす」（加算）**で設計する。

### 画面構成（両モードで不変）

```
┌─ ヘッダ ── ファイル名・開く/保存・元に戻す/やり直す・コマンド・ヘルプ ──────┐
├─ ツールバー ── 選択/フィールド/定数 ｜ SO-SI・属性バイト・グリッド・スナップ ｜ ズーム ─┤
│ ┌─ 左 ────────┬─ 中央 ──────────────────┬─ 右 ─────────┐ │
│ │ レコード様式ツリー │ 24×80 キャンバス          │ プロパティ       │ │
│ │ （定数/フィールド） │ （桁ルーラー・行番号・     │ キーワード       │ │
│ │ 条件標識          │  属性バイト・選択ハンドル） │ 条件標識         │ │
│ │                 │                        │ 対応ソース行      │ │
│ └───────────┴──────────────────────┴────────────┘ │
├─ 凡例 / 桁勘定（'社員マスタ保守' = SO 1 + 全角 7 字 × 2 + SI 1 = 16 桁）────┤
└─ ステータス ── 様式・画面サイズ・選択・SO/SI 表示・検証件数・CCSID ─────────┘
```

**3 ペインが移植可能性の核心。** ホストが変わっても構成は変えない。

## ホスト切替 UI について

モックアップのヘッダにある「スタンドアロン / VSCode 埋め込み」の切替は、
**1 枚の HTML で両モードを見せるためのデモ用**であり、**製品には作らない**（ユーザー判断 2026-08-27）。

実運用では**動いている場所でホストが決まる**——VSCode の WebView なら `vscode`、
ブラウザなら `standalone`。切替の余地が無いので、ホスト能力は起動時（`load` メッセージ）に確定する。
検証用ハーネス（`vscode-extension/dev/`）にだけ、両モードを比べる手段として残してよい。

## 未解決（C1 のモックが自分で挙げているもの）

| # | 論点 | 状態 |
|---|---|---|
| 1 | **キーバインドの取り合い** — 保存/undo/パレットはホストへ委譲できるが、ズーム（`Ctrl+=`/`Ctrl+-`）・検証へ移動・ショートカット一覧は**降ろせないのに VSCode が先に解決する** | 未解決。暫定案は「VSCode モードでは自前キーを無効化し、拡張側で `DDS:` コマンドとして別キーに再登録」 |
| 2 | **undo スタックの二重化** | **解決済み**（2026-08-27）。編集を「ドキュメント差分（パッチ）」として表現し、適用先だけ差し替える方針を実装した——`core/dds/ddsEdit.ts` が返すのは置き換え指示で、スタンドアロンは自前履歴へ、VSCode は `WorkspaceEdit` へ渡す。**コアに undo API を持たせていない** |
| 3 | **dirty 表示の粒度** — 自前ヘッダは「未保存 3 行」を出せるが、VSCode のタブは `●` だけ | 部分解決。ソース面のヘッダ（変更 N 行 / 追加 N 行）へ退避させる |
| 4 | **ステータス項目の置き場** — CCSID・SO/SI 状態・選択桁を VSCode のステータスバーに出せない | 部分解決。`setStatusItems` を host メッセージに足し、拡張が代理登録する案。**host インターフェースの拡張が要る** |
| 5 | **ズームの二重適用** — 自前ズームと VSCode のエディタズームが同時に効き、**桁ルーラーが二重に拡大する**（桁の正確さが売りの画面で実寸が信用できなくなる） | **回避（2026-08-27）**。二重に効く原因は**自前がキーを取ること**なので、ズームは**ボタンだけ**にして `Ctrl+=` / `Ctrl+-` を張らないことにした（`20260826-dds-display-toggles` の `decisions.md` D3）。ホスト側でエディタごと拡大されると自前の %表示とは食い違うが、**自前の倍率は実測値に対する倍率**なのでキャンバス内の整合は保たれる。**解決ではなく回避**である点に注意 |
| 6 | **テーマが VSCode と揃わない** | **意図的**。スタンドアロンを正とした帰結。任意適用のブリッジ層を被せる選択肢は残す |

## 実装の現在地（2026-08-27）

PR #109（`20260826-dds-editor-port`）で入ったのは **C1 の中央キャンバスだけ**。

| C1 の要素 | 実装 |
|---|---|
| 中央キャンバス（桁ルーラー・行番号・属性バイト・選択・ドラッグ・つまみ） | ✅ |
| 編集（移動・長さ変更・追加・削除）とパッチ表現・検証 | ✅ |
| ホスト能力の宣言と bridge の分離、単独起動での動作 | ✅（`dev/` ハーネスで実操作確認） |
| 診断の一覧 | ✅（簡易）。標識を指定したときだけ**その状態での重なり**を足す |
| **左: レコード様式ツリー** | ✅（`20260826-dds-attribute-editing`）。**描かれない項目も理由つきで出す**。様式そのものも選べる（`20260826-dds-keyword-help`） |
| **左: 条件標識パネル** | ✅（`20260826-dds-indicators`）。3 値（未設定 / オン / オフ）で倒すと描画が変わる。**未設定は「決まらない」＝描く** |
| **右: プロパティパネル**（名前・型・使用・占有・属性バイト・右端余裕） | ✅（`20260826-dds-attribute-editing`） |
| **右: キーワード編集**（チップ＋追加） | ✅（`20260826-dds-keyword-help` ＋ `20260827-dds-keyword-edit`）。チップに分け、選ぶと**原典の解説**が出る。`✕` で外し、`＋` と原典の一覧から足し、生テキストで引数を直せる。**36 桁を超えたら折る**（実機で検証済み） |
| **右: 対応ソース行** | ❌（ハーネスには有るが、エディタの一部ではない） |
| **SO/SI の `{ }` 表示**とトグル | ✅ |
| グリッド / 他様式 / ズーム | ✅ |
| スナップ / 5250 配色 | ❌（スナップは**作らない**判断。配色は後続） |
| 桁勘定の説明表示 | ✅（定数のみ。`SO/SI 2 + 全角 4 × 2 = 10 桁`） |
| ヘッダ（ファイル操作・コマンド・ヘルプ） | ❌（ホストが肩代わりする分を除く） |
